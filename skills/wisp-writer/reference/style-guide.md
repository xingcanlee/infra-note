# 写作风格指南

Wisp 的取向：**安静、准确、克制**。页面里只留下文字，其余退到背后；文章也一样。排版规则的依据是 `docs/design-system.md` §2。

## 语气

- 像对一位同行解释：直接、具体、不卖弄。第一人称用“我”或“我们”都可以，但全文统一。
- 先给结论或要回答的问题，再展开。开头不写“本文将介绍”“随着……的发展”“众所周知”。
- 能用数字、例子、代码说明的，不用形容词。“快 3 倍”优于“非常快”。
- 不确定的写“可能”“通常”并说明条件；不知道的不写。不编造数据、引用、链接。
- 避免口水话和过度强调：去掉“非常”“极其”“相当”“真正的”“强大的”“革命性的”“一定要”；不连用感叹号；不用“让我们一起来看看”。
- 一句话一个意思。从句嵌套超过两层就拆开。

## 中文技术写作规范

**标点**

- 中文语境用全角标点：，。：；！？（）、“”。代码、命令、英文句子用半角。
- 引号用“”，不用 "" 。书名号用《》。省略号用 `……`。
- 句末不用英文句点；括号内是中文用全角括号，括号内是纯英文或代码也建议全角括号包裹。
- 破折号用 `——`（两个字宽），少用。
- 括号里放英文原文：`自注意力（self-attention）`。

**中英混排**

- **不需要手动加空格**。中英文之间、中文与数字之间的间距由 CSS `text-autospace` 处理，直接写 `使用 Astro 构建`、`共 3 步`（加了也不出错，但保持全文一致，建议不加或统一加）。
- 英文专有名词保持官方大小写：`PyTorch`、`TypeScript`、`GitHub`。
- 英文单词不要被全角标点包夹后又加空格：写 `支持 Rust，也支持 Go。`，不写 `支持 Rust ，也支持 Go 。`。

**数字与单位**

- 数字用阿拉伯数字；“一个”“第一步”这类固定说法除外。
- 数值与单位之间可以不加空格（`16GB`）也可以加（`16 GB`），全文统一；单位用标准写法（`ms`、`GB`、`MHz`）。
- 百分比写 `35%`，范围写 `3–5` 或“3 到 5”，不写 `3~5`。
- 大数字用阿拉伯数字加单位：`1.2 万`、`3 亿`，或直接 `12,000`。
- 复杂度、变量、公式一律用 `$...$`，不要写成纯文本 `O(n^2)`。

**术语**

- 首次出现时标注英文：`键值缓存（KV cache）`，之后只用中文或统一缩写。
- 同一概念全文只用一个译名；业界通用英文名（如 token、softmax、embedding）可不译。
- 缩写首次出现给全称：`检索增强生成（retrieval-augmented generation，RAG）`。
- 行内代码用于标识符、命令、文件名、参数：`pnpm build`、`src/content`。不要用行内代码做强调。

**强调**

- 中文强调只用 `**粗体**`，一段至多一两处。不用斜体（主题不为中文渲染斜体）；西文强调 `*emphasis*` 可用。
- 不用全大写、下划线、颜色、emoji 强调。

## 标题层级

- 正文不用 h1（标题来自 frontmatter 的 `title`）。从 h2 开始，h3 次之，一般不超过 h4。
- **不跳级**：h2 下面才能有 h3。
- **h2 用名词短语**：“计算步骤”“复杂度”“实现”“小结”，不用“我们来看看怎么算”“为什么这么做？”。h3 同理。
- 标题里不放行内公式、链接、代码（目录里显示不好）；必须放时保持短。
- 每个 h2 下至少有两段内容；只有一句话的小节合并到上一节。
- 文章通常以“小结”或“延伸阅读”结尾，不写“谢谢阅读”。

## 段落

- 一段讲一件事，3 到 5 句，不超过约 300 字（超过时 check_post.py 给提示）。
- 段落之间不用全角空格缩进，不用 `<br>`。
- 长推导拆成“已知 → 步骤 → 结论”，公式单独成行。
- 代码块前一句说明目的，后一句说明关键点或预期输出。

## 列表与表格

- **列表**用于并列的、无需展开的条目（步骤用有序列表，选项用无序列表）。每项一句话，句式统一，不超过两层嵌套。需要解释的内容写成段落。
- 列表项以句号结尾与否要全篇统一；短语型条目不加句号。
- **表格**用于多个对象在多个维度上的对比（至少 3 行 × 3 列）。单元格里写短语，不写长句；不要用表格排版。表头明确，不留空单元格，复杂度等写成公式。
- 只有两三个条目的对比，写成句子比表格好。

## 引用块

- 用来引用他人的原话、规范原文或论文摘录，注明出处。
- 不用来做“提示”“警告”“小贴士”。这类内容放进正文，必要时用一句话开头：“注意：……”。
- 引用块不用斜体（样式已处理）。

## 脚注

- 用于补充说明和出处，不打断正文：`正文[^1]` 加 `[^1]: 说明`。
- 每条脚注一两句话。需要大段展开就放进正文。
- 脚注编号或名字在文内唯一，定义放在文末。

## 链接

- 链接文字写清目标内容：[Astro 内容集合文档](https://docs.astro.build)，不写“点击这里”。
- 站内链接用绝对路径 `/posts/<slug>/`。外部链接只放确认存在的地址。

## 自检清单

1. 第一段是否说清了结论或要解决的问题？
2. 每个术语是否首次出现时给了英文，之后保持一致？
3. 有没有可以删掉的形容词和副词？
4. 每个 h2 是名词短语，层级不跳？
5. 图、表、代码是否都有文字交代，且图有 alt？
6. check_post.py 无 error，warning 已逐条处理？
