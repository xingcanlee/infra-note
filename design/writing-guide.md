# 写作与设计约定（infra-note）

所有系列文章共用这一份约定。新增或重写文章前先读本文，写完用文末的检查表自查。

## 1. 读者与目标

**读者**：会写 Python、没有系统学过深度学习、没有 GPU 的开发者。可能听过 attention 但没推导过，可能用过 vLLM 但没读过源码。

**目标**：读者读完一篇，能用自己的话向别人解释这个机制**改了什么、为什么要改、代价是什么**，并且能在源码里找到对应位置。

两条硬性要求同时成立：

- **零基础可入**：不假设读者知道任何缩写。每个新符号、每个新术语在首次出现处用一句话解释，并给出一个具体数字的例子。
- **深度不打折**：该写的公式要写，该给的维度要给，该贴的源码行号要贴。不用「比较快」「效果更好」这类无法核对的说法代替机制。

两者的接法不是「写浅一点」，而是**先给可操作的小例子，再给一般形式**。

## 2. 每篇文章的固定骨架

章节标题可以改写，但顺序和职责固定：

| 顺序 | 章节             | 职责                                                                           | 长度     |
| ---- | ---------------- | ------------------------------------------------------------------------------ | -------- |
| 1    | 开头三句         | 这一篇解决的具体问题 / 上一篇留下的缺口 / 读完能回答什么                       | 不加标题 |
| 2    | **先看一个例子** | 一组小到能手算的具体数字（序列长 4、2 个 head、维度 4 之类），把问题暴露出来   | 短       |
| 3    | **图或动画**     | 机制的主视图。静态结构用 draw.io/Mermaid，有时间顺序或逐步累积的过程用交互动画 | 必有     |
| 4    | **机制**         | 从例子推到一般形式。公式在这里出现，每个符号都已在前文定义                     | 主体     |
| 5    | **代码实现**     | ① 可在 CPU 跑的最小实现（NumPy / PyTorch CPU）② 真实源码对照，带 commit 和行号 | 必有     |
| 6    | **代价与边界**   | 换来了什么、付出了什么、什么条件下不成立、论文数字的适用范围                   | 必有     |
| 7    | **自测**         | 3 个问题 + 1 个可动手改的小实验                                                | 短       |
| 8    | **来源**         | 论文章节锚点、源码链接、官方文档                                               | 必有     |

「来源」中的具体事实在正文 claim 后就地写 `[^key]`；文件末尾按首次引用顺序写 `[^key]: 作者或机构.《标题》或 Title. 链接. 版本/commit 或章节锚点。`。一般阅读、源码快照说明、图表署名与许可证仍放在「来源」列表；主题已提供的上一篇/下一篇导航不再重复列出。

## 3. 层层递进的接口

系列是一条链，不是文章集合。每篇承担一个「交接点」：

- 开头第一段必须出现「上一篇我们已经……，但是……」的实际内容（不是「上一篇讲了 X」这种空转）。
- 结尾不写总结，写**缺口**：这一篇解决后新暴露出的问题，正好是下一篇的开头。
- 符号表全系列统一（见 §6）。后一篇不得重新定义前一篇已有的符号。
- 同一个 toy 例子贯穿多篇：序列、维度、数值尽量复用，让读者能横向对照不同机制在**同一组输入**上的差别。

## 4. 图与动画

### 4.1 选择

| 内容                               | 形式                            |
| ---------------------------------- | ------------------------------- |
| 层次、模块关系、数据流向（静态）   | draw.io（精确对齐）             |
| 简单流程、状态机、分支判断         | Mermaid（直接写在正文）         |
| 直觉示意、手绘感、算子数据流       | Excalidraw                      |
| 逐步累积、时间顺序、循环、掩码变化 | **交互动画**（React explainer） |
| 论文原图能直接说明问题             | 引用原图并标注来源              |

原则：能用 Mermaid 讲清楚就不画图；能用一张图讲清楚就不做动画；动画只用在「一帧说不清」的地方。

### 4.2 动画必须可复用

动画不是一篇文章的插图，是**站点的一套积木**。

- 算法（纯 TS，产出 `Step[]` 时间线）放 `src/explainers/core/`，必须有 vitest 单测。
- 画面（React + SVG）放 `src/explainers/react/`，只消费 `state`，无内部业务状态。
- 文章只写一行 `import` 加一个带参数的标签。**文章目录里不放动画实现**。
- 一个场景在两篇以上文章出现时，参数化而不是复制。

详细分层与 API 见 `design/explainer-kit.md`。

### 4.3 统一视觉语义

全站图表与动画共用一套含义，跨文章不得改意：

| 颜色/语义 | 含义                                |
| --------- | ----------------------------------- |
| 蓝（q）   | Query、当前正在计算的对象、计算路径 |
| 青（k）   | Key、索引、打分依据                 |
| 绿（v）   | Value、缓存、已持久化的数据         |
| 橙        | 选择、调度、路由、判定              |
| 紫        | 融合、参数、权重矩阵                |
| 灰        | 被掩盖、被跳过、未命中              |

- 实线 = 数据流；虚线 = 索引或控制流。
- 禁止十六进制颜色，只用调色板令牌（`--wisp-*` / `--wd-*`）或 `Tone`。

## 5. 代码与证据

- **toy 实现**：必须能在没有 GPU 的机器上直接运行，依赖只允许 `numpy` 或 `torch`（CPU）。给出输入、输出和一句「这验证了什么」。
- **源码对照**：引用 `reference/` 快照中记录的 commit，写明 `文件:行号`，链接指向该 commit 的 GitHub 永久链接。
- **证据分级**，不得混用：
  - 公式/论文 → 说明设计意图；
  - 源码 → 证明字段、顺序、分支条件；
  - 日志 → 证明某条路径被选中；
  - profiler + 可重复对照 → 才能谈时间收益。
- 本机无 GPU/NPU：**不把未运行过的吞吐、显存、加速比写成实测**。论文数字保留其原始条件并标注。

## 6. 全系列符号表

| 符号            | 含义                          |
| --------------- | ----------------------------- |
| $t$             | 当前（正在生成的）token 位置  |
| $s$             | 被读取的历史 token 位置       |
| $L$             | 当前序列长度                  |
| $h$             | head 下标                     |
| $n_h$           | head 数                       |
| $d$             | 模型隐藏维度                  |
| $d_k, d_v$      | 每个 head 的 Key / Value 维度 |
| $d_c$           | 压缩后的 latent 维度          |
| $d_r$           | 位置（RoPE）分支维度          |
| $x_s$           | 位置 $s$ 的 hidden state      |
| $q_t, k_s, v_s$ | Query / Key / Value 向量      |
| $\alpha_{t,s}$  | 位置 $t$ 对 $s$ 的注意力权重  |
| $W^{\*}$        | 权重矩阵，上标标明用途        |

## 7. 排版

- 中文与英文、数字之间不加空格（主题负责视觉间距）；不使用负字距；中文不用斜体强调。
- 术语首次出现写「中文（English）」，之后统一用一种写法。
- 表格用于对照，不用于叙述。超过 6 列改成多个表。
- 代码块标语言；超过 24 行的代码块让主题折叠（已配置），因此长代码要把关键行放在前 12 行或拆块。
