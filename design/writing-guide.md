# 写作与设计约定（infra-note）

所有系列文章共用这一份约定。新增或修改文章前先读本文，完成写作后按文末验收清单与自动化脚本核验。

## 1. 读者与目标

**读者**：会写 Python、不默认学过深度学习理论、手头没有 GPU/NPU 机器也能阅读复现的开发者。可能听过 Attention 但未手推过，可能调用过 vLLM 但未跟踪过调度与图捕获代码。

**目标**：读者读完一章后，能用自己的话讲清这一机制**改了什么、为什么必须改、硬件收益与工程代价各是什么**，并能在仓库对应提交与行号里找到准确落点。

两条硬性要求同时成立：

- **零基础可入**：禁止不作解释直接抛出陌生缩写、张量下标或密集公式。每个新符号与新术语必须在首次出现前或出现处用通俗语言说明含义与张量形状，并先行给出可手算的微型具体数字例子。
- **深度不打折**：该推导的公式完整写出，该对照的上游文件、类名与行号如实核验；不使用“速度很快”“显存大幅下降”等无条件数字的模糊表述。

## 2. 行文脉络与写作规范

写文章像一位懂行的工程师向同行顺着一条问题脉络拆解设计。严禁套用教材式八股栏目（不写 `先看一个例子`、`一般原理与架构`、`代价与边界`、`自测` 或折叠参考答案），各篇围绕真实技术线索自然推进，保持五步流向：

1. **问题切入**：承接上一篇留下的真实瓶颈，用 2–3 句具体场景或数字反差直接摆出本章要解决的矛盾，不写论文摘要体或全篇提纲。
2. **微型数字直觉**：用**同一个主贯穿案例**先定符号并亮出可手算的输入，再配合 `<Explainer>` 或示意图把核心变化算明白，避免短距离内无过渡硬换多个例子。
3. **机制推导与架构**：按“先白话现象 → 再给数学定义与工程取舍”的渐进节奏推进；适用前提、硬件限制与退化条件随上下文当场讲清。
4. **代码实现或源码结构对照**：依据章节性质选用两种收束方式——涉及张量变换、坐标换算、内存布局与故障复现的章节，给出聚焦核心算法、控制在 30–85 行的自包含 Python / PyTorch 参考代码；涉及系统架构、进程拓扑、调度流程与工程插件的章节，直接以真实仓库目录树（` ```text `）+ Pele（Mermaid）或 Draw.io 模块调用关系图 + 核心源码入口对照收束，不写硬编码常数的玩具时序仿真脚本。
5. **自然收尾与过渡**：用两三句话收尾衔接本章方案仍未解决的下一层矛盾，自然引出下一篇链接。
6. **脚注来源**：全篇遵循 GFM 脚注 `[^key]`，置于它支撑的那句话或分句末尾、标点之前，在文末按首次出现顺序写清论文 arXiv 锚点、源码永久链接与许可证信息。

### 2.1 十条文风与可读性硬规范

全站改写与新增内容（同时约束正文、图片 alt/caption、`Mermaid` 节点与标题、静态图 `.drawio` / `.excalidraw` 以及交互组件 `src/explainers/**/*.tsx` 与文章私有 `src/content/posts/**/explainers/**/*.{ts,tsx}`）必须守住以下十条规矩（由 `src/style.test.ts` 与 `check_post.py` 自动检验）：

1. **禁课程预告与摘要模板化**：禁止写“读完本章你可以带走四件事 / 本章先……再……最后……”或“在上一章中，我们拆解了……”；第一段直接切入具体工程矛盾。`description` 控制在 50–120 字，用“1 句痛点/问题 + 1 句核心做法与对照范围”，禁止千篇一律用 `从……出发，拆解……` 起头。
2. **文章标题瘦身**：章节文章 `title` 不超过 `32` 字符（系列导览与 `about.md` 不超过 `34` 字符），聚焦核心主题。优先不加冒号副标题，加副标题也只用一句话点破核心问题，禁用 `从 A、B、C 到 D、E 与 F` 关键词拼盘；标题中禁止纯文本 `O(...)`、下划线内部符号与论文直译套词（如 `轴`、`账本`、`配方`、`全景`、`全解`、`解剖`、`机理`）。
3. **小标题自然可读（允许短问句与场景标题）**：`h2`–`h4` 建议 6–16 字（硬上限 `24` 字符），每节只讲一件事，减少 `A 与 B` 万能拼接；**允许简短自然的问题式或场景式标题**（如 `## 同一个“首”字，查表如何不串味`、`## 为什么静态图只用在 Decode`）与干净名词短语；严禁行内代码 `` `...` ``、纯文本公式 `O(...)`、下划线符号以及超前剧透未定义术语的“信息倒挂”。正文中由主题自动编号，禁止手写 `1.`、`①`；引用块 `>` 仅用于引述他人原文。
4. **句长与段长硬控（破除文本墙）**：常规句子控制在 30–65 字（硬上限 `98` 字），单句最多 `1` 个分号 `；`，不把三四件事硬焊成百字长句；正常散文段控制在 80–180 字（硬上限 `255` 字），按因果、步骤或对比自然分段。
5. **允许克制的短列表，严禁 PPT 腔与假散文**：严禁堆砌 `- **四到八字黑话词头**：上百字长段解释` 充当正文（`> 75` 字即触发告警），也不要把“首先做**xxx**……随后进入**yyy**……”硬焊成一段密文；允许用简洁有序/无序短列表呈现 3–5 步流程或并列条目（每条 1–2 句、硬上限 `110` 字；导览页与 `about.md` 可至 `140` 字）。
6. **单段认知负荷与源码符号节制**：单段行内代码不超过 `6` 个，括号说明不超过 `3` 对，不连续轰炸 4–5 个新缩写；仅对全文高频核心缩写首次展开 `ABBR（English Full Name，中文说明）`，次要底层概念直接白话交代。下划线开头的私有核函数（如 `_fused_engram_post_wkv_kernel`）、C++ 宏常量、行号与 Git commit 一律退居代码块或脚注 `[^key]`。对比表单元格写 10–18 字短语，不写长句。
7. **禁脱离正文自洽的看图口令与叙事倒置**：先在正文中定义符号、给出输入数值并讲清直觉，再引出图表；`<*Explainer>` 组件前用平实一句话交代演示对象与关注点，不把确定性步进写成“点击上方按钮 / 点击某元素聚焦……”操作指令；正文自身独立可读，禁止写“直接打开图 1，沿 5 个步骤观察 `op5`……”；正文引用统一写“如图 1 所示”（`图 N` 不加粗）。
8. **禁反引号纯数字、亢奋修辞与直译黑名单**：行内代码 `` `...` `` 仅用于标识符、命令、文件路径与配置项，严禁包裹纯阿拉伯数字（如 `` `1024` ``）或物理单位；变量、复杂度（`$O(N^2)$`）与算式用 `$...$`。正文与视觉文本禁用感叹号 `!` / `！`，禁用夸张与论文直译词（如 `的轴 / 条轴 / 稀疏轴 / 扩展轴 / 演化轴 / 正交轴`、`账本`、`配方`、`物化`、`全景 / 全解 / 解剖 / 机理`、`暴涨 / 暴降`、`系统铁律`、`防踩踏` 等；仅 `操作系统/Linux/OS/宏/微 内核` 允许出现 `内核`，算子统称改写 `Kernel`/`算子`），删减无信息量的强化副词（`严格`、`彻底`、`精准`、`天然`、`干净`、`清晰`）。
9. **参考代码或目录结构真实可溯**：若章节附带 `python` 代码块，单个代码块控制在 30–85 行（硬上限 `90` 行），去掉冗长样板 docstring 与重复防御，聚焦核心张量变换；架构/工程章则以真实仓库目录树（`text` 代码块）+ 模块关系图对照精确路径与类入口，不用硬编码常数仿真凑数。代码必须自包含可运行，凡正文讨论具体输出或附 ` ```text ` 块的，代码内必须有真实 `print(...)` 且输出完全一致，严禁将模拟算术称为“实测输出”。
10. **全站统一命名、弯引号与脚注规范**：六个系列标准名固定为《推理与异构硬件基础》《分布式并行与跨卡通信》《DeepSeek 架构演进》《vLLM 推理引擎：架构与核心组件》《vLLM-Ascend 昇腾插件与硬件拓展》《推理执行图：CUDA Graph 与 ACL Graph》；第一人称统一用“我们”；通用术语 `token` 全文统一；全站（正文、图注、Mermaid、Explainer、`.drawio`/`.excalidraw`）统一使用中文弯引号 `“”`，**彻底禁用直角引号 `「」『』`**；脚注使用描述性小写 ASCII key。

### 2.2 自然判断与正面表达规范（同步约束正文与全部视觉文本）

采用自然、直接、有判断力的中文写作风格，用具体事实、因果关系和工程判断推进叙述：

1. **禁防御性连接词与空转起笔**：禁用“不能证明 / 不足以说明 / 不代表 / 并不意味着 / 不能仅凭 / 不能据此 / 不等于 / 不保证 / 并不是说 / 不必然 / 不能断言 / 不能认定 / 尚不能 / 不能简单地 / 更准确地说”充当通用句子连接词；同步禁用“值得注意的是 / 需要留意的是 / 需要补充说明的是 / 需要特别注意 / 值得一提的是 / 从整体来看”等缓冲导语。仅在需要区分实验证据与外推边界时按事实直说。
2. **正面下判断，破除否定式立论模板**：优先写清事情是什么、由哪条硬件约束触发、产生什么量化影响以及得出什么工程判断；禁止反复强调“事情不是什么 / 无法证明什么”，禁用高频“不是/不在/并非/不再是 X，而是/而在于 Y”或“之所以不……是因为……”推进段落，严禁将此类句式用于文章开篇第一句。
3. **删掉免责声明式尾巴，用定量条件交代边界**：给出明确观点后，禁止自动补充“但这不意味着……”“当然，这也不能说明……”“不同集群拓扑的绝对吞吐表现仍需结合实际……”“模拟结果不代表具体芯片壁钟时间”之类的防御性后缀。存在真正影响工程选型的约束时，直接写清可观测的定量触发条件（例如序列长度、批大小阈值）。
4. **用工程师日常语言替代周报黑话**：禁用 `闭环`、`收口`、`收束`、`走查`、`合拢`、`各司其职`、`抓手`，按真实技术动作写“同步完成、汇合、对齐、合并、逐帧推演、分层隔离”。
5. **禁用生造缩写与电报体压缩词，始终使用通用自然中文**：严禁为了塞进窄表格、图表标签或字数上限而截断词素自造非通用简称（如 `关编`、`分段编`、`动态注`、`混批段`、`源栈`、`检拓扑`、`绑通道`、`均一批`、`禁同进程`、`尾发`、`懒绑`、`划槽`、`写串`、`读脏`、`选核`、`融通信`、`拆界`、`防踩踏`、`打孔热更`、`单模/双模`、`捕图/抓图/断图`、`重编`）。宁可拆成两句或精简表格列，也必须写成人人能懂的完整通用中文（如“关闭编译”“分段编译”“动态注意力”“均一批量”“校验拓扑”“绑定物理通道”“读到脏数据”“图捕获”“计算图中断”“参数原地更新”“重新编译”）。

## 3. 串联与链接规范

- **Frontmatter 单行映射**：所有系列文章统一采用单行 flow YAML：`series: { id: foundations | distributed | deepseek | vllm | vllm-ascend | execgraph, order: N }`（兼顾 Astro 内容集合校验与 `check_post.py` 解析器）；编号章节标题统一以两位数字开头（`01 ...`、`02 ...`），导览 `index.mdx` 置 `order: 1` 且不加数字前缀。
- **标签收敛**：使用全站统一的规范 `tags`（禁止同义大小写/连字符变体）。
- **相对链接可达**：同系列章间跳转用 `../02-.../`，跨系列用 `../../distributed/` 或 `../../deepseek/01-mla/`；导览 `index.mdx` 指向子章节用 `./01-.../`；独立页面 `about.md` 指向文章用 `../posts/<series>/`，确保 `base: '/infra-note'` 下零死链。
- **MDX 洁净度**：禁止 HTML 注释 `<!-- ... -->`、禁止裸 `<https://...>` 自动链接、禁止引用 `toy.py` 或 `file://` 本地文件链接、正文中数学公式一律用 `$...$` / `$$...$$`（禁用 `\(...\)` / `\[...\]`）；中文正文按主题约定使用全角标点，段落长度服从语义自然切分。

## 4. 四选一可视化路由与可复用组件体系

拒绝“只有圆角方框 + 公式”的低信息密度图；单篇文章内鼓励按场景混用下列四类工具，具体选型边界、单源工作流与论文级出图验收细节（画布上限、字号与 MathJax 缩放、避让规则、PNG 双主题导出）见 [`diagram-workflow.md`](./diagram-workflow.md)（静态图以该文档为唯一权威），图号从 `图 1：` 起按正文出现顺序连续递增：

1. **简单控制流 / 分层架构 / 双端对照 / 状态转换 / 排障决策树 → `Pele（Mermaid）`**
   - 写法：` ```mermaid caption="图 N：..." `，节点文字用双引号包裹 `A["..."]`；标签内数学符号与公式用 `$$...$$` 包裹（纯代码/API 标识符保持普通文本）。
   - 约束：不超过 `12` 个节点，禁止手写 `style`、`classDef` 或 `%%{init}%%`，节点文字尽量简短清晰。
2. **LLM 论文级结构图 / 硬件泳道 / 矩阵与掩码网格 / 等比时间线 → 单源 `Draw.io`（`.drawio`）**
   - 写法：直接维护未压缩 `.drawio` XML 或使用 Draw.io 桌面端加载 `wisp-drawio-library.xml` 元件库，再执行 `pnpm diagram lint --fix && pnpm diagram build && pnpm diagram lint --strict`；文章中用 `![alt](./diagrams/foo.drawio '图 N：说明')` 引用。
   - 核心约束（细则见 `diagram-workflow.md`）：自然宽度 `<= 704px`（严格对齐 `8px` 网格），字号 `11 / 12px`（`12 ± 1`），中性底框配 `<= 3` 种非 slate 语义色，不在画布内重复写图标题；改图后必须导出明暗 PNG 到系统临时目录目视确认无重叠。
3. **局部直觉对比 / `<= 3` 跳指针映射 / 位宽字段对照 → 单源 `Excalidraw`（`.excalidraw`）**
   - 写法：通过 `wisp_diagram.py new` 由骨架 JSON 转换并编译 `.excalidraw` + `.wisp.svg`，之后以 `.excalidraw` 为准。
   - 约束：公式用 Unicode（`×`、`√d`、`α`），节点数 `<= 12`，单图 `<= 3` 种非 slate 色调。
4. **矩阵变换、注意力/稀疏掩码、数值热力分布、离群值、`> 3` 次指针寻址或时间步演化 → 交互讲解 `<Explainer>`**
   - 就近目录结构与公共套件：文章私有交互讲解统一放置在文章目录 `src/content/posts/<series>/<slug>/explainers/` 下（单文件组件 `FooExplainer.tsx` 或模块化子目录 `<name>/{index.tsx,steps.ts,*Stage.tsx,style.css}`），在 `index.mdx` 中直接 `./explainers/...` 导入并挂载 `<FooExplainer client:visible title="图 N：..." />`；新增组件须同步注册到 `src/explainers/__tests__/explainers.test.ts` 的 `ALL_EXPLAINERS`。所有讲解统一组合 `src/explainers/kit/` 的 `<BeatExplainer>`（提供 `.wisp-kit-banner`、`.wisp-kit-banner__progress` 与 4–24 拍自动时序推进）、`SvgBeatGroup` 及 `motion/react` 原生编排（`initial={false}`、`pathLength`、`layoutId`，不自建动画 hook 封装）。每个步进阶段必须声明非空 `label`、`duration >= 3600`（末拍后留 `>= 1500ms` 停顿）与 `stageMinHeight` 防止切步跳高。
   - **引导节拍聚光 vs 反事实交互边界**：确定性因果推演（如多头查找逐头落位、流水线接力、矩阵分块过程）必须由 `BeatExplainer` 的因果节拍自动聚光逐一推进，禁止提示读者“点击某个格子或表头才能看到结论”；交互控件只用于有明确教学意义的**反事实对照**（例如切换输入样本对比是否发生槽位碰撞与门控抑制）。
   - 硬性视觉约束：颜色只能使用 `var(--wisp-*)` / `--wisp-sem-*` 语义令牌（单图非 slate 色调 `<= 3` 种），禁止硬编码 `#hex`、渐变、阴影、毛玻璃、超过 `4px` 圆角、`rx="2"` 与 emoji/Unicode 图标；CSS 包在 `@layer utilities` 内；SSR 与首帧对齐终态防闪烁，进入视口、翻页或点“重播”时从第 0 拍顺畅推演。
5. **第三方论文图与视觉检查**：
   - 仅保留验证为 CC BY 4.0 或 Apache-2.0 的一手论文图至文章 `images/` 目录并完整署名；新图或改图后须渲染明暗双主题并实测验证无文字重叠、无裁切与高对比度。

## 5. 证据分级与溯源规范

全站所有技术论断、源码描述与数据指标严格按四级证据核验与标注：

1. **论文一手数据与官方架构**：引用 `../.tmp-research/papers/`、`papers_txt/` 与 `PAPERS_INDEX.md` 中的一手公式、实验表格或 CC BY 4.0 / Apache-2.0 配图，文末脚注标明 arXiv ID、章节/图表号与许可证。
2. **双仓源码对照（先查后写，不臆测）**：NVIDIA CUDA（`vLLM` / `FlashMLA` / `DeepEP`）与华为昇腾（`vllm-ascend` / `cann-runtime` / `torch_npu`）源码引用必须先到 `../.tmp-research/repos/` 核实精确路径、符号名、1-based 行号与行为差异；若某一端暂无对应算子或走不同抽象，如实标出。
3. **可运行代码或真实目录结构**：算法/布局章附 30–85 行可运行核心代码（输出与 `print(...)` 完全一致，不把模拟算术称为“实测输出”）；架构/工程章附真实仓库目录树与核心类入口对照。
4. **本地硬件实测禁造假**：不在无真机环境下编造本地硬件实测吞吐、延迟或加速比；论文数据、模拟器数字与真实测量明确区分，交付报告中未实测或未执行的项必须明确标为 `未实测`。
