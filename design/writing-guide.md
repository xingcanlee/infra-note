# 写作与设计约定（infra-note）

所有系列文章共用这一份约定。新增或修改文章前先读本文，完成写作后按文末检查表与自动化脚本核验。

## 1. 读者与目标

**读者**：会写 Python、不默认学过深度学习理论、手头没有 GPU/NPU 机器也能阅读复现的开发者。可能听过 Attention 但未手推过，可能调用过 vLLM 但未跟踪过调度与图捕获代码。

**目标**：读者读完一章后，能用自己的话讲清这一机制**改了什么、为什么必须改、硬件收益与工程代价各是什么**，并能在仓库对应提交与行号里找到准确落点。

两条硬性要求同时成立：

- **零基础可入**：禁止不作解释直接抛出陌生缩写、张量下标或密集公式。每个新符号与新术语必须在首次出现前或出现处用通俗语言说明含义与张量形状，并先行给出可手算的微型具体数字例子。
- **深度不打折**：该推导的公式完整写出，该对照的上游文件、类名与行号如实核验；不使用「速度很快」「显存大幅下降」等无条件数字的模糊表述。

## 2. 单章固定骨架

| 顺序 | 章节职责                             | 内容要求                                                                                                                                                            |
| :--: | :----------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
|  1   | **开头导读**                         | 承接上一章遗留的具体缺口，用 3–4 条列出本章能够回答的工程问题                                                                                                       |
|  2   | **先看一个例子**                     | 用小到可手算的具体数字与维度走查，配合 `*-walkthrough.drawio` 图先直观暴露问题与机制                                                                                |
|  3   | **一般原理与架构**                   | 定义全部符号后再展开正式公式或状态机推导，配合 `*-arch.drawio` 结构图                                                                                               |
|  4   | **动手运行：`toy.py`**               | 仅依赖 Python 标准库与 NumPy（`<= 150` 行，固定 `default_rng(42)`），文内贴出实际运行输出与关键验证结论（不写成可点击 `[toy.py](./toy.py)` 死链，直接写作行内代码） |
|  5   | **`vLLM` 与 `vllm-ascend` 源码对照** | 给出锁定上游快照（如 `vllm@bb23c0a8` 与 `vllm-ascend@3649b8ff`）的模块对照表，配合 `*-runtime.drawio` 执行图；不引用已删旧文件名                                    |

|  7   | **自测与跨章衔接**                   | 提供思考题（带 `<details><summary>参考答案</summary>`）与 1 个改动 `toy.py` 参数的动手实验，并在末尾桥接到下一章链接                                                |
|  8   | **脚注来源**                         | 全篇遵循 GFM 脚注 `[^key]`，在末尾按首次出现顺序写清论文 arXiv 锚点、源码永久链接与许可证信息                                                                       |

## 3. 串联与链接规范

- **Frontmatter 单行映射**：所有系列文章统一采用单行 flow YAML：`series: { id: foundations | distributed | deepseek | vllm, order: N }`（兼顾 Astro 内容集合校验与 `check_post.py` 解析器）；编号章节标题统一以两位数字开头（`01 ...`、`02 ...`），导览 `index.mdx` 置 `order: 1` 且不加数字前缀。
- **标签收敛**：使用全站统一的规范 `tags`（禁止同义大小写/连字符变体）。
- **相对链接可达**：同系列章间跳转用 `../02-.../`，跨系列用 `../../distributed/` 或 `../../deepseek/01-mla/`；导览 `index.mdx` 指向子章节用 `./01-.../`；独立页面 `about.md` 指向文章用 `../posts/<series>/`，确保 `base: '/infra-note'` 下零死链。
- **MDX 洁净度**：禁止 HTML 注释 `<!-- ... -->`、禁止裸 `<https://...>` 自动链接、禁止相对 `[toy.py](./toy.py)` 或 `file://` 文件链接、正文中数学公式一律用 `$...$` / `$$...$$`（禁用 `\(...\)` / `\[...\]`）；中文正文按主题约定使用全角标点。

## 4. 图表绘制标准（`wisp-diagram`）

每篇正文章配备 `3` 张职责正交的 Wisp 图（命名规范：`NN-*-walkthrough.*`、`NN-*-arch.*`、`NN-*-runtime.*`），每篇导览配 `1` 张全局路线图；新建与重写章节统一用**骨架生成的 `.excalidraw` 手绘风**，其余保留章节维持 `.drawio`，单篇文章内禁止混用格式：

- **版面**：画布自然宽度控制在 `640–700px`（所有坐标宽高严格落在 `8px` 网格上），主流向从上到下，文字字号仅用 `12 / 14 / 18`；放进文章的图不在画布内写标题，`.excalidraw` 公式用 Unicode（`×`、`√d`、`α`）。
- **颜色**：仅使用 Wisp 浅色语义令牌（`palette.json`），单图最多 `3` 种 hue（`slate` 不计），禁止阴影、渐变和手写暗色值；由 `pnpm diagram build` 生成自适应双主题 `.wisp.svg` 并注册 `diagrams.manifest.json`。
- **视觉检查**：新图或改图后须渲染 light 与 dark PNG 预览并用图像读取工具核查，确认无文字重叠、无边框裁切、连线正交干净且暗色下可读。
- **第三方配图**：仅引用验证为 CC BY 4.0 等兼容许可或 Apache-2.0 的一手论文/设计图，拷贝至文章 `images/` 目录并完整署名。

## 5. 代码与证据分级

- **可跑优先**：`toy.py` 必须能在无 GPU/NPU 机器上通过 `uv run scripts/verify_toys.py` 执行并断言关键性质，输出末尾打印 `OK NN`。
- **双仓对照不臆测**：源码引用先到 `.tmp-research/repos/` 核实路径与行号；不同后端（NVIDIA CUDA vs 华为昇腾 CANN）若暂无对应算子或已重构替换，必须如实标出差异。
- **不虚构实测数据**：不在无设备环境下编造本地硬件实测吞吐或加速比；论文数据与模拟器数字明确区分。
