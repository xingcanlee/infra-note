# 写作与设计约定（infra-note）

所有系列文章共用这一份约定。新增或修改文章前先读本文，完成写作后按文末检查表与自动化脚本核验。

## 1. 读者与目标

**读者**：会写 Python、不默认学过深度学习理论、手头没有 GPU/NPU 机器也能阅读复现的开发者。可能听过 Attention 但未手推过，可能调用过 vLLM 但未跟踪过调度与图捕获代码。

**目标**：读者读完一章后，能用自己的话讲清这一机制**改了什么、为什么必须改、硬件收益与工程代价各是什么**，并能在仓库对应提交与行号里找到准确落点。

两条硬性要求同时成立：

- **零基础可入**：禁止不作解释直接抛出陌生缩写、张量下标或密集公式。每个新符号与新术语必须在首次出现前或出现处用通俗语言说明含义与张量形状，并先行给出可手算的微型具体数字例子。
- **深度不打折**：该推导的公式完整写出，该对照的上游文件、类名与行号如实核验；不使用「速度很快」「显存大幅下降」等无条件数字的模糊表述。

## 2. 行文脉络与八条文风红线

写文章像一位懂行的工程师向同行顺着一条问题脉络拆解设计。严禁套用教材式八股栏目（不写 `先看一个例子`、`一般原理与架构`、`代价与边界`、`自测` 或折叠参考答案），各篇小标题围绕真实技术线索命名，整体保持五步自然流向：

1. **问题切入**：承接上一篇留下的真实瓶颈，直接摆出本章要解决的具体矛盾。
2. **微型数字直觉**：先定符号并亮出可手算的输入，再配合 `<Explainer>` 或示意图把核心变化算明白。
3. **机制推导与架构**：完整推演公式与工程取舍；每个设计的适用前提、硬件限制与退化条件随上下文用白话当场讲清，不再单独拎到文末列固定栏目。
4. **参考实现与双仓源码对照**：给出带清晰注释的自包含 PyTorch / NumPy 代码，并对照锁定提交的 `vLLM` / `FlashMLA` / `DeepEP` 与 `vllm-ascend` 核心实现与行为差异。
5. **自然收尾与过渡**：用两三句话收尾衔接本章方案仍未解决的下一层矛盾，自然引出下一篇链接。
6. **脚注来源**：全篇遵循 GFM 脚注 `[^key]`，置于它支撑的那句话或分句末尾、标点之前，在文末按首次出现顺序写清论文 arXiv 锚点、源码永久链接与许可证信息。

### 2.1 八条文风红线（严禁 AI 教案腔与 PPT 提纲体）

全站改写与新增内容（同时约束正文、图片 alt/caption、`Mermaid` 节点与标题、静态图 `.drawio` / `.excalidraw` 以及交互组件 `src/explainers/**/*.tsx`）必须严格守住以下八条红线：

1. **禁课程预告式开头与寒暄回顾**：禁止写“读完本章你可以带走四件事 / 回答四个问题 / 本章先……再……最后……”或“在上一章中，我们拆解了……”；第一段直接切入具体工程矛盾或核心结论。
2. **禁 PPT 粗体词头列表代替自然段落**：凡需解释因果、微架构、源码逻辑的内容一律写成连贯散文段落；严禁堆砌 `- **四到八字黑话词头**：长段解释` 充当正文。列表仅用于无需展开的简短并列条目。
3. **禁源码符号报菜名与表文复读**：正文聚焦“硬件约束逼出了什么工程折中”，每处只点出 1–3 个最核心的入口类名或函数名；下划线私有辅助函数、冗长文件路径、行号、C++ 宏枚举常量、Git commit 号一律退居代码块注释或文末脚注 `[^key]`。对比表单元格严格写 10–18 字架构短语，禁止写长句或复读上文刚讲完的符号。
4. **禁脱离正文自洽的看图口令与叙事倒置**：必须先在正文中定义符号、给出输入数值并讲清直觉，再引出图表；`<*Explainer>` 组件前用平实一句话交代演示对象与步进方式，正文自身必须独立可读，严禁写“直接打开图 1，沿 5 个步骤观察 `RSV` / `**op5**`……”等绑定组件内部 UI 状态的指令；正文引用统一写“如图 1 所示”（`图 N` 不加粗）。
5. **禁数字/单位/公式套反引号与亢奋修辞**：行内代码 `` `...` `` 仅用于代码标识符、命令、文件路径与配置项；普通阿拉伯数字、百分比、物理单位严禁加反引号；变量、复杂度（`$O(N^2)$`）与算式一律用 `$...$`。正文与视觉图注/组件文本禁用感叹号 `!` / `！`，禁用夸张、医疗、商战或端架子修辞（如“狠狠撞上”“死死停在”“死攥不放手”“毫不留情”“三重病灶”“专治”“致命杀手”“像一把手术刀”“系统铁律/铁律”“并集灾难”“吞噬”“暴降”“暴涨”“饿死”“死读”“捉凶”“安全起飞”“吃干榨净”“真正厉害的工程师”“半夜秒级归因”等）。
6. **禁标题违规与双重编号**：`h2`/`h3` 一律使用干净的中文名词短语，禁止问句（“为什么……？”）、口号副标题、手写序号（`1.`、`①`，主题会自动编号）、冗长类名代码或纯文本公式。引用块 `>` 仅用于引述他人原文，禁止拿来做提示框。
7. **禁跨系列超前剧透、直觉跳步与伪称「实测」**：基础篇不超前倾倒后续系列专属复杂变体；手算微例必须给出完整输入并写出关键化简步；正文参考代码块必须自包含可运行，凡正文讨论具体输出或附 ` ```text ` 块的，代码内必须有真实 `print(...)` 且输出完全一致，严禁将理论公式或模拟器算术结果称为“实测输出”。
8. **全站统一命名、人称与脚注规范**：四个系列标准名固定为《推理与异构硬件基础》《分布式并行与跨卡通信》《DeepSeek 架构演进》《vLLM 与昇腾推理引擎》；第一人称统一用“我们”（克制少用，不混用“我”或说教式“你”）；通用术语 `token` 全文统一（不混跳“词元”与 `Token`）；脚注使用描述性小写 ASCII key（如 `[^vllm-block-pool]`）。

### 2.2 自然判断与正面表达规范（同步约束正文与全部视觉文本）

采用自然、直接、有判断力的中文写作风格，用具体事实、因果关系和工程判断推进叙述：

1. **禁防御性连接词与空转起笔**：禁用“不能证明 / 不足以说明 / 不代表 / 并不意味着 / 不能仅凭 / 不能据此 / 不等于 / 不保证 / 并不是说 / 不必然 / 不能断言 / 不能认定 / 尚不能 / 不能简单地 / 更准确地说”充当通用句子连接词；同步禁用“值得注意的是 / 需要留意的是 / 需要补充说明的是 / 需要特别注意 / 值得一提的是 / 从整体来看”等缓冲导语。仅在需要区分实验证据与外推边界时按事实直说。
2. **正面下判断，破除否定式立论模板**：优先写清事情是什么、由哪条硬件约束触发、产生什么量化影响以及得出什么工程判断；禁止反复强调“事情不是什么 / 无法证明什么”，禁用高频“不是/不在/并非/不再是 X，而是/而在于 Y”或“之所以不……是因为……”推进段落，严禁将此类句式用于文章开篇第一句。
3. **删掉免责声明式尾巴，用定量条件交代边界**：给出明确观点后，禁止自动补充“但这不意味着……”“当然，这也不能说明……”“不同集群拓扑的绝对吞吐表现仍需结合实际……”“模拟结果不代表具体芯片壁钟时间”之类的防御性后缀。存在真正影响工程选型的约束时，直接写清可观测的定量触发条件（例如序列长度、批大小阈值）。
4. **用工程师日常语言替代周报黑话**：禁用 `闭环`、`收口`、`收束`、`走查`、`合拢`、`各司其职`、`抓手`，按真实技术动作写“同步完成、汇合、对齐、合并、逐帧推演、分层隔离”。

## 3. 串联与链接规范

- **Frontmatter 单行映射**：所有系列文章统一采用单行 flow YAML：`series: { id: foundations | distributed | deepseek | vllm | aclgraph, order: N }`（兼顾 Astro 内容集合校验与 `check_post.py` 解析器）；编号章节标题统一以两位数字开头（`01 ...`、`02 ...`），导览 `index.mdx` 置 `order: 1` 且不加数字前缀。
- **标签收敛**：使用全站统一的规范 `tags`（禁止同义大小写/连字符变体）。
- **相对链接可达**：同系列章间跳转用 `../02-.../`，跨系列用 `../../distributed/` 或 `../../deepseek/01-mla/`；导览 `index.mdx` 指向子章节用 `./01-.../`；独立页面 `about.md` 指向文章用 `../posts/<series>/`，确保 `base: '/infra-note'` 下零死链。
- **MDX 洁净度**：禁止 HTML 注释 `<!-- ... -->`、禁止裸 `<https://...>` 自动链接、禁止引用 `toy.py` 或 `file://` 本地文件链接、正文中数学公式一律用 `$...$` / `$$...$$`（禁用 `\(...\)` / `\[...\]`）；中文正文按主题约定使用全角标点，段落长度服从语义自然切分。

## 4. 四选一可视化路由与可复用组件体系

拒绝“只有圆角方框 + 公式”的低信息密度图；单篇文章内鼓励按场景混用下列四类工具，图号从 `图 1：` 起按正文出现顺序连续递增：

1. **简单控制流 / 模块调用 / 排障决策树 → `Mermaid`**
   - 写法：` ```mermaid caption="图 N：..." `，节点文字用双引号包裹 `A["..."]`。
   - 约束：不超过 `12` 个节点，禁止手写 `style`、`classDef` 或 `%%{init}%%`，节点文字尽量简短清晰。
2. **复杂模型架构 / 分布式切分 / 静态硬件双泳道 → `Draw.io`（`scripts/diagram_kit.DrawioCanvas`）**
   - 写法：由 `scripts/diagrams/<slice>.py` 调用 `DrawioCanvas` 生成未压缩 `.drawio` 并编译 `.wisp.svg`，文章中用 `![alt](./diagrams/foo.drawio '图 N：说明')` 引用。
   - 约束：画布宽度 `<= 688px`，坐标严格落在 `8px` 网格上，字号仅用 `12 / 14 / 18`，单图非中性（slate）色调 `<= 3` 种，不在画布内重复写图标题；张量块长宽与字节严格按真实比例绘制，切分处画虚线。
3. **局部直觉对比 / `<= 3` 跳指针映射 / 位宽字段对照 → `Excalidraw`（`scripts/diagram_kit.ExcalidrawScene`）**
   - 写法：调用 `ExcalidrawScene` 生成骨架并用 `wisp_diagram.py new --build` 编译 `.excalidraw` + `.wisp.svg`。
   - 约束：公式用 Unicode（`×`、`√d`、`α`），节点数 `<= 12`，单图 `<= 3` 种非 slate 色调。
4. **矩阵变换、注意力/稀疏掩码、数值热力分布、离群值、`> 3` 次指针寻址或时间步演化 → 交互式 SVG `<Explainer>`（`src/explainers/kit/`）**
   - 写法：在 `src/explainers/<series>/*Explainer.tsx` 中复用 `@/explainers/kit` 的共享原语（`TensorBlock`、`ByteLedgerBar`、`HeatmapMatrix`、`ProbabilityBars`、`SlotStrip`/`PointerArcs`、`SwimlaneTimeline`、`LogRooflineChart`、`DataFlowArrow`、`ActiveFocusFrame`、`MetricRow`、`SectionBox`）构建 `4–6` 步离散状态切换组件，在 `.mdx` 中导入并挂载 `<FooExplainer client:visible title="图 N：..." />`。
   - 硬性视觉约束：颜色只能使用 `var(--wisp-*)` 语义令牌与 `kit` 色调（单图调用 `assertMaxHues` 确保非 slate 色调 `<= 3` 种），禁止硬编码 `#hex`、渐变、阴影与 emoji/Unicode 播放符；固定背景网格，逐帧高亮当前活跃张量与流向。
5. **第三方论文图与视觉检查**：
   - 仅保留验证为 CC BY 4.0 或 Apache-2.0 的一手论文图至文章 `images/` 目录并完整署名；新图或改图后须渲染明暗双主题并实测验证无文字重叠、无裁切与高对比度。

## 5. 代码与证据分级

- **可复现参考实现**：正文中提供自包含 PyTorch 或 NumPy 核心代码与形状/数值断言，无硬件设备也可理解核心张量变换。
- **双仓源码对照不臆测**：NVIDIA CUDA（`vLLM` / `FlashMLA` / `DeepEP`）与华为昇腾（`vllm-ascend` / CANN）源码引用必须先到 `.tmp-research/repos/` 核实精确路径、符号与行为差异；若某一端暂无对应算子或走不同抽象，必须如实标出。
- **不虚构实测数据**：不在无设备环境下编造本地硬件实测吞吐或加速比；论文数据与模拟器数字明确区分。
