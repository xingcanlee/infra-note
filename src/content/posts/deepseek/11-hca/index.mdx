CSA 的配方是「轻压缩 + 稀疏选择」：压 4 倍，然后在压缩条目里挑 $k$ 个。

V4 同时还有另一种注意力，配方正好相反：**重压缩 + 不做稀疏**。HCA（Heavily Compressed Attention）把每 $m'=128$ 个 token 压成一个条目，然后对**全部**压缩条目做密集注意力。

读完你能回答：两种配方各自的取舍、为什么一个模型里要同时放两种、以及 HCA 的压缩为什么反而比 CSA 的简单。

## 先看一个例子

序列 1M，两种机制面对的东西完全不同：

| | CSA | HCA |
| --- | --- | --- |
| 压缩率 | $m=4$ | $m'=128$ |
| 压完剩多少条目 | 262144 | **8192** |
| 读多少 | top-$k$（Pro 取 1024） | **全读 8192 个** |
| 选择机制 | Lightning Indexer + top-$k$ | 无 |
| 压缩方式 | 重叠（看 $2m$ 个） | 不重叠（看 $m'$ 个） |

CSA 靠「挑」来省，HCA 靠「压」来省。两者读的条目数是同一个量级（1024 vs 8192），但路径完全不同。

## 机制

### 压缩：比 CSA 简单

从 hidden state 产出一套 KV 和一套压缩权重（§2.3.2 式 (20)–(21)）：

$$
C=H W^{KV},\qquad Z=H W^{Z}
$$

每连续 $m'$ 个条目，加可学习位置偏置后 softmax，再加权求和（式 (22)–(23)）：

$$
S_{m'i:m'(i+1)-1}=\mathrm{Softmax}_{\text{row}}\big(Z_{m'i:m'(i+1)-1}+B\big)
$$

$$
C^{\mathrm{Comp}}_i=\sum_{j=m'i}^{m'(i+1)-1}S_j\odot C_j
$$

和 CSA 对比，少了一整套东西：**只有一套 $W^{KV}/W^{Z}$，没有重叠**（§2.3.2）。CSA 需要 $C^a/C^b$ 两套、每个条目看 $2m$ 个 token，HCA 就是老老实实每 $m'$ 个压成一个。

为什么 HCA 不需要重叠？一个合理的理解是：重叠是为了减轻块边界把信息切碎，而 $m'=128$ 这么大的块里，边界效应相对块内信息量本来就小；而且 HCA 读**全部**条目，不像 CSA 那样可能因为选择而漏掉边界附近的块。论文没有直接解释这一点，这里只能作为对照观察，不是论文结论。

### Query 与密集 MQA

$$
\mathbf c_t^Q=\mathbf h_t W^{DQ},\qquad \mathbf q_t=\mathbf c_t^Q W^{UQ}
$$

$$
\mathbf o_{t,i}=\mathrm{CoreAttn}(\text{query}=\mathbf q_{t,i},\ \text{key}=C^{\mathrm{Comp}},\ \text{value}=C^{\mathrm{Comp}})
$$

注意式 (26) 里的 key/value 是 $C^{\mathrm{Comp}}$ **整体**，没有下标筛选——这就是「密集」的含义。同样是共享 KV 的 MQA，同样接第 10 篇那套分组输出投影。

### 同样需要窗口分支

和 CSA 一样，HCA 也要合并最近 $n_{\text{win}}=128$ 个未压缩 token（§2.3.3）。原因相同：压缩是按块对齐的，当前块内的细节拿不到。

压缩率越高，这个洞越大——HCA 的块是 128 个 token，意味着当前块内最多 127 个邻居都只能靠窗口拿。而窗口恰好也是 128。

## 两种配方的取舍

| | CSA | HCA |
| --- | --- | --- |
| 省的方式 | 压一点 + 挑一部分 | 压很多 + 全读 |
| 细节保留 | 块小（4），块内细节保留得多 | 块大（128），块内细节被平均掉很多 |
| 远处覆盖 | 只覆盖被选中的 $k$ 个块 | **覆盖全部历史**（粗粒度） |
| 额外成本 | Lightning Indexer（$O((L/m)^2)$） | 无选择器 |
| 风险 | 挑错块就丢信息 | 块内细节丢失，且无法挽回 |

**两者的失败模式正好互补**：CSA 可能「看漏」（没选中的块完全不可见），HCA 可能「看糊」（全都能看到，但每 128 个 token 糊成一个）。

这解释了为什么 V4 要把两者**交错使用**而不是二选一：某一层看漏的，另一层可能看糊了但至少看到了；某一层看糊的，另一层可能精确选中了。

## 层级排布

论文 §4.2.1 给出的（也只给出了这些）：

| 模型     | 前 2 层 | 之后             |
| -------- | ------- | ---------------- |
| V4-Flash | 纯 SWA  | CSA 与 HCA 交错  |
| V4-Pro   | HCA     | CSA 与 HCA 交错  |

超参数（两个模型相同的部分）：$m'=128$、$n_{\text{win}}=128$、$c=512$。其余按模型：

| 参数                | V4-Flash | V4-Pro |
| ------------------- | -------- | ------ |
| query head 数 $n_h$ | 64       | 128    |
| query 压缩维 $d_c$  | 1024     | 1536   |
| 输出投影组数 $g$    | 8        | 16     |
| 组内中间维 $d_g$    | 1024     | 1024   |

**论文没有给出交错的精确周期、层号列表或 CSA:HCA 的数量比例**——只说了「interleaved」。想知道确切排布只能等开源实现，不能从论文推断。

为什么前两层特殊？论文没有解释。可以观察到的是：前两层离输入最近，此时 hidden state 还很「局部」，用纯 SWA（Flash）或纯 HCA（Pro）而不是带选择的 CSA，或许与此有关——但这是推测，不是论文结论。

## 代码实现

> 完整可运行脚本见文章目录下的 `toy.py`。

```python
def hca_compress(H, W_KV, W_Z, B, m_prime):
    """式 (20)–(23)：一套权重、不重叠、每 m′ 个压成一个。"""
    C, Z = H @ W_KV, H @ W_Z
    out = []
    for i in range(len(H) // m_prime):
        z = Z[m_prime * i:m_prime * (i + 1)] + B
        s = np.exp(z - z.max(axis=0)) / np.exp(z - z.max(axis=0)).sum(axis=0)
        out.append((s * C[m_prime * i:m_prime * (i + 1)]).sum(axis=0))
    return np.array(out)
```

`toy.py` 的输出：

```
1M 上下文下两种机制面对的序列：
  CSA ：1048576 → 262144 个压缩条目，再挑 1024 个 → 实际读 1024
  HCA ：1048576 →   8192 个压缩条目，全部读      → 实际读 8192

每个被读条目代表多少原始 token：
  CSA ：每个条目来自 8 个 token（2m，重叠）→ 覆盖面 8192 个原始 token
  HCA ：每个条目来自 128 个 token         → 覆盖面 1048576 个原始 token（全部）

失败模式对照（序列 64、当前位置 63）：
  CSA 只选 2 个块：能看到 16 个原始位置，看不到的有 47 个
  HCA 读全部 7 个块：能（粗粒度地）看到 56 个原始位置，看不到的有 7 个
  但 HCA 的每个条目把 8 个 token 平均成了 1 个 —— 看得到，但看不清

分辨率（每个被读条目混入的 token 数，越小越清晰）：CSA 8，HCA 128
```

这组数字把「看漏 vs 看糊」量化了：CSA 覆盖面小但分辨率高，HCA 覆盖面满但分辨率低。

## 代价与边界

- HCA 没有选择器，所以省掉了 indexer 的开销，但也失去了「按内容聚焦」的能力——它对所有历史一视同仁。
- $m'=128$ 的压缩是有损的，而且不可逆。块内 128 个 token 的差异被一组学出来的权重压成一个向量。
- HCA 的「密集」是相对压缩后的序列而言。$L=1$M 时它仍要读 8192 个条目，不是常数。
- 窗口分支 $n_{\text{win}}=128$ 恰好等于 $m'$，但论文没有说这是刻意对齐的设计。
- **论文中未找到**：CSA:HCA 的层数比例与交错周期、前两层为何特殊、HCA 为何不用重叠压缩、CSA/HCA 的单独消融表。本篇中标为「观察」或「推测」的段落都不是论文结论。
