## 机制

### 统一形式

论文先把三条分支写成同一个模板[^nsa-paper]：每条分支把完整的 K/V 映射成一组更紧凑的 K/V，再各自算一遍注意力，最后按 gate 求和（§3.2 式 (5)）：

$$
\mathbf{o}^{*}_{t}=\sum_{c\in\mathcal{C}} g_{t}^{c}\cdot \mathrm{Attn}\big(\mathbf{q}_{t},\tilde{K}_{t}^{c},\tilde{V}_{t}^{c}\big),
\qquad \mathcal{C}=\{\text{cmp},\text{slc},\text{win}\}
$$

$g_t^c\in[0,1]$ 是门控分数，由当前 token 的特征过一个 MLP 加 sigmoid 得到。**gate 是逐 token 的**：遇到需要远程引用的 token，模型可以把权重压到选块分支上；遇到普通续写，就倚重窗口分支。

三条分支**各有自己的 K/V 投影**，不是共用一份。论文的理由是：共用会让局部分支「抄近路」，并造成梯度互相干扰[^nsa-paper]（§3.3.3）。

### ① 压缩分支：把一块压成一个

把连续的 $l$ 个 key 聚合成一个压缩 key，相邻块之间按 stride $d$ 滑动[^nsa-paper]（§3.3.1 式 (7)）：

$$
\tilde{K}^{\text{cmp}}_{t}=\Big\{\varphi\big(\mathbf{k}_{id+1:\,id+l}\big)\ \Big|\ 0\leqslant i\leqslant \Big\lfloor \tfrac{t-l}{d}\Big\rfloor\Big\}
$$

$\varphi$ 是一个**可学习的 MLP**（带块内位置编码），不是简单的平均池化。论文取 $l=32$、$d=16$[^nsa-paper]——注意 $d<l$，相邻块有一半重叠，这是为了减轻「信息被块边界切碎」。

这条分支的读取量按 $t/d$ 增长，比全读慢 16 倍，但**仍随序列增长**。它提供的是粗粒度的全局概览。

### ② 选块分支：打分是白捡的

这是 NSA 最值得学的一步。要挑出「最相关的几个块」，就得给每个块打分——而打分本身如果很贵，就白忙了（这正是下一篇 DSA 要专门解决的问题）。

NSA 的办法是**直接复用压缩分支已经算出来的注意力概率**[^nsa-paper]（§3.3.2 式 (8)）：

$$
\mathbf{p}_{t}^{\text{cmp}}=\mathrm{Softmax}\big(\mathbf{q}_{t}^{\top}\tilde{K}_{t}^{\text{cmp}}\big)
$$

压缩分支为了算自己的输出，本来就要算这个 softmax。既然每个压缩 key 对应原序列的一个块，那么 $\mathbf{p}_t^{\text{cmp}}[i]$ 天然就是「第 $i$ 块有多相关」的分数。**打分的边际成本是零。**

当压缩与选择用同一种分块时（$l'=l=d$），直接令 $\mathbf{p}_t^{\text{slc}}=\mathbf{p}_t^{\text{cmp}}$；分块不同时按空间对应关系求和（式 (9)）：

$$
\mathbf{p}_{t}^{\text{slc}}[j]=\sum_{m=0}^{\frac{l'}{d}-1}\sum_{n=0}^{\frac{l}{d}-1}\mathbf{p}_{t}^{\text{cmp}}\Big[\tfrac{l'}{d}j-m-n\Big]
$$

然后取分数最高的 $n$ 个块，**读这些块里的原始 token**[^nsa-paper]（式 (11)–(12)）：

$$
\mathcal{I}_{t}=\{\,i\mid \mathrm{rank}(\mathbf{p}_{t}^{\text{slc}\prime}[i])\leqslant n\,\},\qquad
\tilde{K}^{\text{slc}}_{t}=\mathrm{Cat}\big[\{\mathbf{k}_{il'+1:(i+1)l'}\mid i\in\mathcal{I}_{t}\}\big]
$$

论文取 $l'=64$、$n=16$[^nsa-paper]，其中有 **1 个起始块和 2 个局部块是固定激活的**（算在这 16 个里）。固定起始块就是第 07 篇的 attention sink，固定局部块保证当前位置附近一定被覆盖。

所以压缩分支有双重身份：既是一条输出分支，又是选块分支的**打分器**。

### ③ 窗口分支：最近 $w$ 个

$$
\tilde{K}_{t}^{\text{win}}=\mathbf{k}_{t-w:t},\qquad \tilde{V}_{t}^{\text{win}}=\mathbf{v}_{t-w:t}
$$

论文取 $w=512$[^nsa-paper]。就是第 07 篇的滑动窗口，原封不动。

### 为什么必须按「块」而不是按 token 选

按单个 token 挑出最相关的 $k$ 个，理论上更精确。NSA 坚持按块，有两个硬理由[^nsa-paper]（§3.3.2、§2.1）：

1. **访存**：连续块的读取吞吐远高于散落的单 token，而且 blockwise 计算才能用上 Tensor Core。注意力分数本身也有空间聚集性（相关的位置往往扎堆），所以块粒度的损失没想象中大。
2. **GQA 分组**：多个 query head 共享同一份 KV。如果每个 head 各挑各的块，实际要搬运的是这一组所有 head 选择的**并集**——计算稀疏了，访存并没有。所以 NSA 把组内所有 head 的块分数**加起来**，让整组共用一套块索引（式 (10)）：

$$
\mathbf{p}_{t}^{\text{slc}\prime}=\sum_{h=1}^{H}\mathbf{p}_{t}^{\text{slc},(h)}
$$

这是第 03 篇埋下的伏笔：GQA 的分组结构会一路影响到稀疏注意力该怎么设计。**稀疏注意力的收益是访存收益，所以它必须按访存的规律来设计，而不是按 FLOPs。**

### 「原生可训练」是什么意思

常见做法是：先按全注意力训练[^nsa-paper]，推理时再加稀疏（事后稀疏化）。论文指出这有问题（§2.2）：

- 模型是按「能看到全部历史」优化出来的，推理时突然只给一部分，等于偏离了它的优化轨迹。
- 论文给的具体证据：**top-20% 的注意力只覆盖约 70% 的总注意力分数**[^nsa-paper]。剩下 30% 分散在长尾里，剪掉它们可能误伤 retrieval head 这类关键结构。

NSA 把稀疏结构放进架构里，从预训练第一步就带着它训练：压缩 MLP $\varphi$、门控 MLP 都是可学习的，并配了专用的前向/反向 kernel。模型因此是**在自己的稀疏结构下**学会如何分配注意力的[^nsa-paper]。

一处要诚实的地方：top-$n$ 的排序本身不可导。论文没有声称对离散 rank 做了梯度处理，可引用的准确表述是「稀疏结构参与端到端训练，参数与稀疏路径共同优化」[^nsa-paper]——离散选择的梯度细节论文中未展开。

## 代码实现

> 完整可运行脚本见文章目录下的 `toy.py`。

```python
import numpy as np

def nsa_branches(q, k, v, l=4, d=2, l_blk=4, n_sel=2, w=4, phi=None):
    """返回三条分支各自的输出与读取量。phi 是压缩函数（论文里是可学习 MLP）。"""
    L = len(k)
    t = L - 1
    phi = phi or (lambda blk: blk.mean(axis=0))      # toy 用均值代替可学习 MLP

    # ① 压缩：每 l 个 token 压成一个，stride = d
    starts = [i * d for i in range(max(0, (t - l) // d + 1))]
    k_cmp = np.array([phi(k[s:s + l]) for s in starts])
    v_cmp = np.array([phi(v[s:s + l]) for s in starts])
    p_cmp = softmax(k_cmp @ q / np.sqrt(q.shape[-1]))   # ← 这个 softmax 要算两次用
    o_cmp = p_cmp @ v_cmp

    # ② 选块：直接复用 p_cmp 当块分数，不另算
    n_blocks = (t + l_blk) // l_blk
    blk_score = np.zeros(n_blocks)
    for bi, s in enumerate(starts):                      # 压缩块 → 选择块的空间对应
        blk_score[min(s // l_blk, n_blocks - 1)] += p_cmp[bi]
    blk_score[0] += 1e9                                  # 固定激活：起始块
    blk_score[t // l_blk] += 1e9                         # 固定激活：当前局部块
    chosen = np.sort(np.argsort(blk_score)[::-1][:n_sel])
    idx = np.concatenate([np.arange(b * l_blk, min((b + 1) * l_blk, t + 1)) for b in chosen])
    o_slc = softmax(k[idx] @ q / np.sqrt(q.shape[-1])) @ v[idx]

    # ③ 窗口
    widx = np.arange(max(0, t - w + 1), t + 1)
    o_win = softmax(k[widx] @ q / np.sqrt(q.shape[-1])) @ v[widx]

    return (o_cmp, o_slc, o_win), (len(starts), len(idx), len(widx))
```

`toy.py` 的输出：

```
压缩分支：读 14 个压缩条目（由 32 个 token 压成）
选块分支：读 8 个原始 token（2 个块 × 4）
窗口分支：读 4 个原始 token
门控合并：g = [0.3 0.5 0.2]，三条分支输出加权求和

选块分支挑中的块 = [0 7]，其中块 0 是固定激活的起始块
块分数完全来自压缩分支的 softmax —— 没有额外的打分计算 ✓

合并覆盖 8 / 32 个原始位置；窗口单独只覆盖 4 个
```

最后一行是三条分支分工的意义所在：窗口只摸到最近 4 个位置，而合并之后序列开头也被覆盖了。`toy.py` 还断言了块分数之和为 1——因为它就是压缩分支那个 softmax 的重新分配，没有任何新计算。

### 论文给的效率数字

论文 §5.2 Table 4[^nsa-paper] 按「decode 时要加载多少 KV」对照（单位是等效 token 数）：

| 上下文长度 | 全注意力 | NSA   | 论文给的预期加速 |
| ---------- | -------- | ----- | ---------------- |
| 8,192      | 8,192    | 2,048 | 4.0×             |
| 16,384     | 16,384   | 2,560 | 6.4×             |
| 32,768     | 32,768   | 3,584 | 9.1×             |
| 65,536     | 65,536   | 5,632 | 11.6×            |

每一步最多加载 $\lfloor (s-l)/d\rfloor$ 个压缩条目、$nl'$ 个选中 token、$w$ 个邻近 token。注意 NSA 那一列也在涨——因为压缩分支按 $s/d$ 增长，没有封顶。但增速慢得多：上下文翻 8 倍，它只涨 2.75 倍。

**这张表的「预期加速」是在「decode 受显存带宽限制」这个假设下由访存量推出的估算，不是端到端实测**。论文另外用 Triton kernel 实测了前向/反向：64k 时前向最多 9.0×、反向 6.0×（§5.1 图 6）[^nsa-paper]。

## 代价与边界

- 三条分支各有独立的 K/V 投影，所以**参数更多**，而且三份 K/V 都要缓存。NSA 省的是计算和访存，不是参数。
- 压缩分支的读取量仍随序列线性增长（按 $1/d$），所以 NSA 的单步代价并没有完全封顶，只是增速降了一个量级。
- 块粒度选择必然比 token 粒度粗。论文用「注意力分数有空间聚集性」来论证这个损失可接受，这是经验性论据。
- 选块复用压缩分支的分数，意味着**选块的质量受限于压缩表示的质量**。压缩得不好，就会挑错块。
- 表 4 的加速是访存量推算，§5.1 的 9.0×/6.0× 是特定 kernel、特定硬件（8×A100）、特定配置下的实测。本机无 GPU，本篇不做任何性能验证。
- gate MLP 的层数、权重形式与 sigmoid 的具体写法，论文中未给出。
