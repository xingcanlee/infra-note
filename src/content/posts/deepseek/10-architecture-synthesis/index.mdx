## V4.1 单步解码全链路与多流张量流转

DeepSeek-V4.1 主干在层间始终维护四条并行流形残差 `[T, 4, d]`，替代了传统 Transformer 的单流残差传递。图 1 展示了单步解码的六个阶段、张量形状、字节流向与算子边界。

![DeepSeek-V4.1 单 token 解码六阶段流程：Mega-mHC Pre-Mix、CSA2/CED、Async Engram（L1,14）、DeepSeekMoE、mHC Post-Mix 与 DSpark Draft](./diagrams/10-v41-layer-panoramic.drawio '图 1：DeepSeek-V4.1 单 token 解码六阶段流程与算子边界')

顺着 `[T, 4, d]` 的生命周期走完单层解码全链路。进入子层时，首先由 `Mega-mHC` 边界把上一子层的残差写回（`post_mix` 与 `res_mix`）、本子层错位时移的输入聚合权重 $A_{l-1}$ 以及 `RMSNorm` 合并成单遍读写（访存 $10d$）。

这一边界把四条流聚合成单流 BF16 激活 `[T, d]` 送入注意力分支：SM100 走 `mhc_shifted_post_pre_deep_gemm`，昇腾走 `npu_hc_pre_v3`。同时 20 轮 FP32 Sinkhorn 保证深层连乘下的信号增益受控[^vllm-synth][^ascend-synth]。

注意力侧执行 CSA2 / Sparse MLA，40 层按静态 Full / Reindex / Reuse 拓扑复用全局缓存[^v41-flash][^vllm-synth][^ascend-synth]。GPU 侧对应 `DeepseekV4MegaAttnAttention` 与 `DeepseekV4SparseMLABackend`，昇腾对应 `AscendDSAV41Impl`。具体角色由 `is_kv_source`、`is_index_source` 与 `DeepseekV41LayerRole` 控制。

Full 与 Decoder Reindex 层需要重新筛选历史 KV 位置。512 维潜向量经压缩器与 **HSI（Hierarchical Sparse Indexer，两级分层稀疏索引器）**在 16,384 个槽位中选出 Top-512。每槽按 288 B 的 NVFP4 读取。Reuse 层则跳过投影与打分，直接消费上游缓存与索引。

由于压缩条目同时充当 Key 与 Value 并携带绝对位置旋转，注意力输出末尾 64 维在输出投影 `wo_a / wo_b` 之前还要施加逆旋转 $R_{-t}$，以恢复相对位置依赖。

在第 1、14 层（`layers.1` 与 `layers.14`），计算流在 `mhc_post` 之后与 `mhc_pre` 前并入异步 Prefetch 的 Engram 静态记忆[^v41-flash][^vllm-synth][^ascend-synth]。因为哈希行索引在第 0 层前已确定，后台流可通过 UVA 或 RDMA 提前把主机表行搬至设备缓存。

计算流等待跨流事件（`cuda.Event` 或 `ExternalEvent`）就绪。随后把 6144 维向量（V4.1-Flash 3 阶 × 每阶 2048 维）投影为 4:1 的分支 Key 与共享 Value。随后经带符号开方 `RMSNorm` 门控原位写回 `[T, 4, d]`。GPU 侧需在 1、14 层显式拆开跨子层融合；NPU 侧由于 `npu_hc_post` 已在每个子层末尾写出四流，可直接原位注入。

随后单流激活进入 DeepSeekMoE，在偏置 `e_score_correction_bias` 引导下选出 Top-K 细粒度路由专家，并与 1 个常驻共享专家并发执行。共享专家趁 `DeepEP` 或 `TokenDispatcherWithMC2` 执行 `Dispatch` 时算完。路由结果经 `Combine` 归位后，再由 mHC Post-Mix 写回 `[T, 4, d]`。

整网末层归并回 `[T, d]` 后，抽取辅助层隐状态送入 DSpark（3 层 $n_{\text{win}}=128$ 并行 Draft 配秩 256 `DSparkMarkovHead` 与置信度头），由无损拒绝采样步进多 token[^v41-flash]。

下表对照 NVIDIA SM100 与华为昇腾两套生态在各模块的对应实现映射：

| 执行环节              | NVIDIA SM100（`vllm`）             | 华为昇腾 NPU（`vllm-ascend`）                |
| --------------------- | ---------------------------------- | -------------------------------------------- |
| 残差混合边界          | `Mega-mHC` / CuTe 延迟融合         | `npu_hc_pre_v3` + `npu_hc_post` 成对边界     |
| 稀疏注意力与逆向 RoPE | `FlashMLAMegaAttn` 融合逆 RoPE     | `AscendDSAV41Impl` + `packed_cache_ops`      |
| 条件记忆卸载          | `DPSharedEngramStorage` / `DeepEP` | `HostUvaBuffer` $2^{22}$ 分块与 IPC          |
| MoE 通信分组          | `EPBuffer` + `DeepGEMM`            | `AscendMoERunner` + `TokenDispatcherWithMC2` |
| 动态推测采样          | `all_to_all_vocab_shards` 请求转置 | `LmheadTPDraftSamplingMixin` 容量对齐        |
| 静态图同步            | `FULL` CUDA Graph + `cuda.Event`   | `ACLGraphWrapper` + `ExternalEvent`          |

把整网全局缓存从 V3 的 70,272 B 压到 V4.1-Flash 的 890 B（降幅约 79 倍，较 V3.2 的 48,068 B 也降低约 54 倍），依靠三条维度的乘法联合压缩[^v41-flash]。首先，单槽位体积从 1,152 B 降至 656 B 再到 NVFP4 的 288 B。其次，Encoder 18 层实施 $m = 2$ 序列折叠，使单主层均摊降至 144 B。配合跨层复用，40 层最终仅保留 2.5 份全局主 KV（720 B）与 2.5 份 MXFP4 HSI 索引（170 B）。

为了同步削减前缀重算（重复 Prefill）并压低持久化缓存，V4.1-Flash 将非对称 CED（Causal Encoder-Decoder，因果编码-解码）与 SWA 有界重放绑定在一起[^v41-flash]。前 20 层编码器算完长序列后，后 20 层直接由第 20 层输出投影出全局 KV。热内存池中的 SWA 缓存过期后只需重放末尾 128 个 token，将 SSD 前缀池体积压至 V4 的 1/8。

## 集群级 DBO 双微批与异步 Engram 协同

即使单卡 Kernel 已经高度融合，多卡 EP 推理仍面临跨节点 `All-to-All` 通信裸露的问题。如果整批算完注意力再集体停下来等 `Dispatch` 与 `Combine`，计算单元会在网络等待期间空转。

`vLLM` 的 `UBatchContext` 将一个全局批拆成交替推进的双微批 μB0 与 μB1，用计算流与通信流的事件屏障把网络传输藏进计算窗口[^vllm-synth]。图 4 按毫秒等比刻度展示了这一切换过程。

![集群级 Dual-Microbatch (DBO) 与 Host DDR Engram 异步 Prefetch 协同时间线：从串行 15.2 ms 降至稳态 9.4 ms（1.62 倍加速）](./diagrams/10-cluster-dbo-engram.drawio '图 4：集群级 Dual-Microbatch (DBO) 与异步 Engram Prefetch 毫秒等比时间线')

结合图 4 的时序刻度，串行执行两份微批加上同步等待 Engram 查表共耗时 15.2 ms。切入稳态 DBO 后，计算流先算 μB0 注意力；就在 μB0 进入 1.8 ms 的 Dispatch 通信瞬间，计算流立刻切去算 μB1 注意力（1.4 ms）。

紧接着，μB0 的 MoE GEMM 掩盖 μB1 Dispatch，μB1 的 MoE GEMM 掩盖 μB0 Combine。最后一段 μB1 Combine（7.6–9.4 ms）则由下一层 μB0 注意力接管掩盖，使单层稳态步长收敛到 9.4 ms，较串行基线提速 1.62 倍。

与此同时，第 1、14 层的 Engram 索引在第 0 层启动前已算完，后台流在首层启动时就同步发起主机内存 Prefetch，图 4 中 6.0 ms 的传输被前序层计算完全掩盖。为防止并发微批写入查表缓冲与元信息时发生覆盖冲突（数据竞争），`DeepseekV4Model` 与昇腾 `EngramModelState` 均隔离了 `ubatch_idx`（0 或 1）[^vllm-synth][^ascend-synth]。具体下标通过 `dbo_current_ubatch_id()` 读取。

开启 DBO 时存在一条互斥回退约束：在 `vLLM` GPU 实现中，一旦开启 `use_ubatching`，`supports_mhc_overlap` 会返回 `False`[^vllm-synth]。这会关闭跨层边界的 `mhc_shifted_post_pre` 延迟融合重排。

正常单批模式下，上一层的 MoE `Combine` 和张量并行 `AllReduce` 可以延后到下一层入口一并合并。开启 DBO 后，μB0 与 μB1 在 MoE 边界频繁交错切换事件，跨层延迟收尾会在 `compute_stream` 与 `comm_stream` 上引发冲突。因此每个微批必须在当层同步收尾后再让出执行权。

## PyTorch 端到端全链路验证

下面的自包含 `MiniV41DecodeStep` 把整套单步全链路微缩进可运行模型中。它串联了 `[B, 4, d]` 双随机多流混合、跨层 2 倍折叠 KV 共享、输出端逆旋转 $R_{-t}$、边界门控 Engram 与分组 MoE。最后将 $B = 4$ 批拆成两个微批对比执行，验证计算等价性与 890 B/token 整网 KV 开销。

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

rms = lambda t: t * torch.rsqrt(t.square().mean(-1, keepdim=True) + 1e-6)

def sinkhorn(logits: torch.Tensor, iters: int = 20) -> torch.Tensor:
    m = torch.exp(logits - logits.amax(dim=(-2, -1), keepdim=True))
    for _ in range(iters):
        m = m / (m.sum(dim=-2, keepdim=True) + 1e-12)
        m = m / (m.sum(dim=-1, keepdim=True) + 1e-12)
    return m

def partial_rope(x: torch.Tensor, pos: torch.Tensor, d_rope: int = 4, inv: bool = False) -> torch.Tensor:
    inv_freq = 10000.0 ** (torch.arange(0, d_rope // 2, device=x.device) / (d_rope // 2))
    ang = pos.float().unsqueeze(-1) / inv_freq
    c, s = ang.cos(), (-ang.sin() if inv else ang.sin())
    t1, t2 = x[..., -d_rope::2], x[..., -d_rope + 1 :: 2]
    rot = torch.stack([t1 * c - t2 * s, t2 * c + t1 * s], dim=-1).flatten(-2)
    return torch.cat([x[..., :-d_rope], rot], dim=-1)

class MiniV41Layer(nn.Module):
    def __init__(self, is_kv_src: bool = True, has_eg: bool = False):
        super().__init__()
        self.d, self.d_kv, self.d_rope, self.is_kv_src = 16, 12, 4, is_kv_src
        self.phi, self.wq, self.wo = nn.Linear(64, 24, bias=False), nn.Linear(16, 12, bias=False), nn.Linear(12, 16, bias=False)
        self.wkv = nn.Linear(16, 12, bias=False) if is_kv_src else None
        self.eg_emb = nn.Embedding(17, 16) if has_eg else None
        self.eg_wkv = nn.Linear(16, 80, bias=False) if has_eg else None
        self.router, self.shared, self.experts = nn.Linear(16, 4, bias=False), nn.Linear(16, 16, bias=False), nn.Linear(16, 64, bias=False)

    def _mhc(self, X):  # 双随机流形混合：产出 pre、post 与 Sinkhorn res 系数
        p, q, r = self.phi(rms(X.flatten(-2))).split([4, 4, 16], dim=-1)
        return torch.sigmoid(p).unsqueeze(-2), 2.0 * torch.sigmoid(q).unsqueeze(-2), sinkhorn(r.unflatten(-1, (4, 4)))

    def forward(self, H, prefix, tok_ids, pos, shared_kv=None, topk_idx=None):
        pre_a, post_a, res_a = self._mhc(H)
        q = partial_rope(self.wq((pre_a @ H).squeeze(-2)), pos, self.d_rope)
        if self.is_kv_src:  # Full 层做 2x 序列折叠并产出共享压缩 KV 与 Top-K 索引
            kv_c = self.wkv(prefix.unflatten(1, (-1, 2)).mean(dim=2))
            pos_kv = torch.arange(kv_c.shape[1], device=H.device).unsqueeze(0)
            shared_kv = partial_rope(kv_c, pos_kv, self.d_rope)
            topk_idx = torch.topk((q.unsqueeze(1) * shared_kv).sum(-1), 4, dim=-1).indices
        kv_sel = torch.gather(shared_kv, 1, topk_idx.unsqueeze(-1).expand(-1, -1, self.d_kv))
        attn_w = F.softmax((q.unsqueeze(1) @ kv_sel.transpose(-1, -2)).squeeze(1) / math.sqrt(self.d_kv), dim=-1)
        ctx = partial_rope((attn_w.unsqueeze(1) @ kv_sel).squeeze(1), pos, self.d_rope, inv=True)
        H = res_a @ H + post_a.transpose(-1, -2) * self.wo(ctx).unsqueeze(-2)
        if self.eg_emb is not None:  # 边界门控注入 Engram（4:1 K/V 与带符号开方）
            ek, ev = self.eg_wkv(self.eg_emb(tok_ids % 17)).split([64, 16], dim=-1)
            z = (rms(H) * rms(ek.unflatten(-1, (4, 16)))).sum(-1) / 4.0
            gate = torch.sigmoid(z.sign() * z.abs().clamp_min(1e-6).sqrt())
            H = H + gate.unsqueeze(-1) * ev.unsqueeze(-2)
        pre_m, post_m, res_m = self._mhc(H)
        xm = (pre_m @ H).squeeze(-2)
        w, ids = torch.topk(torch.sigmoid(self.router(xm)), 2, dim=-1)
        e_out = self.experts(xm).view(-1, 4, 16).gather(1, ids.unsqueeze(-1).expand(-1, -1, 16))
        moe = self.shared(xm) + ((w / w.sum(dim=-1, keepdim=True)).unsqueeze(-1) * e_out).sum(dim=1)
        return res_m @ H + post_m.transpose(-1, -2) * moe.unsqueeze(-2), shared_kv, topk_idx

class MiniV41DecodeStep(nn.Module):
    def __init__(self):
        super().__init__()
        self.l1, self.l2 = MiniV41Layer(is_kv_src=True, has_eg=True), MiniV41Layer(is_kv_src=False)

    def forward(self, H, prefix, tok_ids, pos):
        H, skv, idx = self.l1(H, prefix, tok_ids, pos)
        return self.l2(H, prefix, tok_ids, pos, skv, idx)[0].mean(dim=-2)

if __name__ == "__main__":
    torch.manual_seed(10)
    m = MiniV41DecodeStep().eval()
    H, pre, tids, pos = torch.randn(4, 4, 16), torch.randn(4, 16, 16), torch.tensor([101, 205, 308, 412]), torch.full((4,), 8)
    with torch.no_grad():
        out_full = m(H, pre, tids, pos)
        out_dbo = torch.cat([m(H[:2], pre[:2], tids[:2], pos[:2]), m(H[2:], pre[2:], tids[2:], pos[2:])], dim=0)
        dbo_diff = (out_full - out_dbo).abs().max().item()
        assert dbo_diff < 1e-5
        assert int((3 * 0.5 + 1.0) * (512 * 0.5 + 32 + 68)) == 890
    print(f"[10-synthesis] out_shape={tuple(out_full.shape)}, dbo_max_diff={dbo_diff:.2e}, net_kv=(V3:{61 * 1152}B, V3.2:{61 * 788}B, V4.1:890B)")
```

```text
[10-synthesis] out_shape=(4, 16), dbo_max_diff=5.96e-07, net_kv=(V3:70272B, V3.2:48068B, V4.1:890B)
```

校验结果显示，整批前向与拆成 μB0、μB1 两个微批独立执行的输出最大误差仅为 5.96e-07（源于浮点矩阵分块归约次序），验证了共享权重与只读压缩 KV 在微批拆分下的数学一致性。同时 V4.1-Flash 整网每 token 全局缓存 890 B，相比 V3 的 70,272 B 缩减约 79 倍，与前文统计对齐。

把这么多部件放进同一张执行图之后，全链路的稳定就取决于几条必须同时成立的系统耦合前提。第一，在 `vLLM` 里启用 `num_ubatches > 1` 后，执行期必须保持 `FULL` 静态图捕获而不能回退分段图 `PIECEWISE`。同时批内需凑够可均衡拆分的计算量，否则切换与同步开销会抵消通信收益[^vllm-synth]。

第二，多卡部署时 `PipelineRelay`、上下文并行与分段编译受限于跨界状态传递；启用微批后，引擎还需关闭跨级缓存接力和有界解码重放等依赖全局一致批长的优化路径[^vllm-synth]。

第三，单步内同时并存环形尾缓存、跨层 `topk_indices_buffer`、双微批隔离的 `EngramModelState` 与 DSpark 回滚槽位。昇腾图模式还依赖 `ExternalEvent` 与 `valid_token_count` 边界检查同步空跑卡，任何指针越界都会沿着 4 条 mHC 残差通道向深层传播。

到这里，我们完成了从 DeepSeek-V2 到 V4.1-Flash 模型层架构与单步全链路的拆解。接下来要把这套复杂模型真正拉起为高并发在线服务，工程主战场转向请求调度、`torch.compile` 分段图与静态图捕获编排——请继续阅读 [系列四：vLLM 推理引擎](../../vllm/)。
