## V4.1 单步解码全链路与多流张量流转

DeepSeek-V4.1 主干在层间始终维护四条并行流形残差 `[T, 4, d]`，替代了传统 Transformer 的单流残差传递。图 1 用六阶段交互视图展示了单步解码期间张量形状、字节流向与算子边界，点击步进即可逐段追踪层内执行状态。

顺着 `[T, 4, d]` 的生命周期走完单层解码全链路。进入子层时，首先由 `Mega-mHC` 边界把上一子层的残差写回（`post_mix` 与 `res_mix`）和本子层错位时移的输入聚合权重 $A_{l-1}$ 及 `RMSNorm` 合并成单遍读写（访存 $10d$），将四条流聚合成单流 BF16 激活 `[T, d]` 送入注意力分支（SM100 走 `mhc_shifted_post_pre_deep_gemm`、昇腾走 `npu_hc_pre_v3`），同时靠 20 轮 FP32 Sinkhorn 保证深层连乘下的信号增益受控[^vllm-synth][^ascend-synth]。

注意力侧执行 CSA2 / Sparse MLA（`DeepseekV4MegaAttnAttention` / `DeepseekV4SparseMLABackend` 与昇腾 `AscendDSAV41Impl`），40 层按静态 Full / Reindex / Reuse 拓扑（`is_kv_source`、`is_index_source` 与 `DeepseekV41LayerRole`）复用全局缓存[^v41-flash][^vllm-synth][^ascend-synth]。在需要重新选词的 Full 与 Decoder Reindex 层，512 维潜向量（448 NoPE + 64 RoPE）经压缩器与分层稀疏索引器（HSI）在 16,384 个候选槽位内选出 Top-512 条目，每槽仅按 288 B 的 NVFP4 格式读取；Reuse 层则跳过投影与打分直接消费上游缓存与索引。由于压缩条目同时充当 Key 与 Value 并携带绝对位置旋转，注意力输出末尾 64 维在输出投影 `wo_a / wo_b` 之前还要施加逆旋转 $R_{-t}$ 以恢复相对位置依赖。

在第 1、14 层（0-indexed `layers.1` 与 `layers.14`），计算流会在层入口处——位于上一层收尾的 `mhc_post` 之后、本层开头的 `mhc_pre` 与注意力计算之前——先并入异步预取的 Engram 静态记忆[^v41-flash][^vllm-synth][^ascend-synth]。由于哈希行索引早在第 0 层前已由输入 token 序列确定，后台流通过 UVA 或 RDMA 提前把主机表行搬至设备缓存；计算流只需等待跨流事件（`cuda.Event` 或 `ExternalEvent`）就绪，将 1280 维（V4.1-Flash 扩至 $\{2, 3, 4\}$ 阶共 2048 维）向量投影成 4:1 的分支 Key 与共享 Value，经有符号开方 `RMSNorm` 门控原位写回 `[T, 4, d]`。在 GPU 上，这要求第 1、14 层显式拆开跨子层融合（`mhc_post_tilelang -> engram -> mhc_pre`）；而 NPU 因为每子层尾已由 `npu_hc_post` 物化四流，可以直接原位注入。

随后单流激活进入 DeepSeekMoE，在无辅助损失偏置 `e_score_correction_bias` 引导下选出 Top-K 细粒度路由专家，并与 1 个常驻共享专家并发执行——共享专家的投影计算趁 `DeepEP` 或 `TokenDispatcherWithMC2` 执行跨卡 `Dispatch` 时完成，计算后经对称 `Combine` 归位并由 mHC Post-Mix 写回 `[T, 4, d]`。整网最后一层归并回 `[T, d]` 后，抽取若干辅助层隐状态送入 DSpark（3 层 $n_{\text{win}} = 128$ SWA 并行 Draft 模型 + 秩 256 `DSparkMarkovHead` + 置信度头），由无损拒绝采样在下一步验证并步进多 token[^v41-flash]。

下表对照 NVIDIA SM100 与华为昇腾两套生态在各模块的对应实现映射：

| 执行环节       | NVIDIA SM100（`vllm`）             | 华为昇腾 NPU（`vllm-ascend`）                |
| -------------- | ---------------------------------- | -------------------------------------------- |
| 残差混合边界   | `Mega-mHC` / CuTe 延迟融合         | `npu_hc_pre_v3` + `npu_hc_post` 成对边界     |
| 稀疏注意与逆旋 | `FlashMLAMegaAttn` 融合逆 RoPE     | `AscendDSAV41Impl` + `packed_cache_ops`      |
| 条件记忆卸载   | `DPSharedEngramStorage` / `DeepEP` | `HostUvaBuffer` $2^{22}$ 分块与 IPC          |
| MoE 通信分组   | `EPBuffer` + `DeepGEMM`            | `AscendMoERunner` + `TokenDispatcherWithMC2` |
| 动态推测采样   | `all_to_all_vocab_shards` 请求转置 | `LmheadTPDraftSamplingMixin` 容量对齐        |
| 静态图同步     | `FULL` CUDA Graph + `cuda.Event`   | `ACLGraphWrapper` + `ExternalEvent`          |

## 五代演进与整网 KV 字节账本收敛

DeepSeek 五代架构演化始终围绕同一个系统目标推进：在保持长上下文检索与推理精度的同时，压缩单并发 KV 缓存容量与 Decode 阶段 HBM 带宽占用。图 2 用比例尺对比了从 V2/V3 到 V4.1-Flash 的字节账本缩减轨迹、参数存储分工以及两大硬件执行栈。

把整网全局缓存从 V3 的 70,272 B 压到 V4.1-Flash 的 890 B（降幅约 79 倍，较 V3.2 的 48,068 B 也降低约 54 倍），靠的是三条维度上的乘法联合压缩：单槽位精度从 1,152 B 降至 656 B 再到 NVFP4 的 288 B；Encoder 18 层实施 $m = 2$ 序列折叠使单主层均摊降至 144 B；跨层复用让 40 层收敛至仅保留 2.5 份全局主 KV（720 B）与 2.5 份 MXFP4 HSI 索引（170 B）[^v41-flash]。

为了同步削减重填充计算并把持久化缓存压到最低，V4.1-Flash 将非对称因果编码-解码（CED）与 SWA 有界重放绑定在一起：前 20 层编码器跑完长序列后，后 20 层直接由第 20 层顶输出投影得到全局 KV；而仅在分钟级热内存池中短驻留的 SWA 缓存一旦过期，只需按末尾 128 个 token 做有界重放恢复即可，从而将 SSD 持久化前缀池体积压缩至 V4 的 1/8[^v41-flash]。

## 集群级 DBO 双微批与异步 Engram 协同

即使单卡 Kernel 已经高度融合，多卡 EP 推理仍面临跨节点 `All-to-All` 通信裸露的问题：如果整批算完注意力再集体停下来等 `Dispatch` 与 `Combine` 返回，计算单元会在网络等待期间大量空转。`vLLM` 的 `UBatchContext` 将一个全局批拆成交替推进的乒乓微批 μB0 与 μB1，用计算流与通信流的硬件事件屏障把网络传输藏进矩阵计算窗口[^vllm-synth]。图 3 按毫秒等比刻度展示了这一调度切换过程。

结合图 3 的时序刻度来看，串行执行两份微批加上同步等待 Engram 查表共耗时 15.2 ms。切入稳态 DBO 后，计算流先执行 μB0 注意力，就在 μB0 进入 1.8 ms 的 Dispatch 通信瞬间，计算流立刻切换去执行 μB1 注意力（1.4 ms）；紧接着 μB0 的 MoE GEMM 掩盖 μB1 Dispatch，μB1 的 MoE GEMM 掩盖 μB0 Combine，而最后一段 μB1 Combine（7.6–9.4 ms）则由下一层的 μB0 注意力接管掩盖，使单层稳态步长收敛到 9.4 ms（较串行基线提速 1.62 倍）。

与此同时，由于第 1、14 层的 Engram 索引早在第 0 层启动前已经计算完毕，后台流在首层计算启动时就同步发出主机内存预取（图 3 中 6.0 ms 的传输窗口被前序层的注意力与 MoE 计算完全掩盖）；为了防止两个并发微批互相踩踏静态查表缓冲与注意力元信息，`DeepseekV4Model` 与昇腾 `EngramModelState` 均按 `dbo_current_ubatch_id()` 严格隔离 `ubatch_idx`（取值为 0 或 1）[^vllm-synth][^ascend-synth]。

开启 DBO 时存在一条硬性退避规则：在 `vLLM` 的 GPU 实现中，一旦 `use_ubatching` 开启，`supports_mhc_overlap` 会主动返回 `False`，关闭跨子层异步系数重叠与延迟融合 `AllReduce`（即关闭跨越层边界延迟收尾的 `mhc_shifted_post_pre` 跨层融合重排）[^vllm-synth]。正常单批模式下，上一层的 MoE `Combine` 和张量并行 `AllReduce` 可以延后到下一层的 `mhc_shifted_post_pre` 入口一并合并；而开启 DBO 后，μB0 与 μB1 在 MoE 边界频繁交错切换计算流与通信流事件，跨越层边界延迟收尾会与交替进场的另一微批在 `compute_stream` 与 `comm_stream` 上发生同步冲突。因此，启用 DBO 时每个微批必须在当前层内同步完成 MoE 写回与集合通信后再让出执行权。

## PyTorch 端到端参考实现：MiniV41DecodeStep

下面的自包含 PyTorch `MiniV41DecodeStep` 参考实现把整套单步全链路微缩进可运行模型中：串联 `[B, 4, d]` 双随机 Sinkhorn 多流残差混合、Full / Reuse 跨层 2 倍折叠 KV 共享与输出端逆旋转 $R_{-t}$、边界门控 Engram 注入与分组 MoE，最后将 $B = 4$ 批拆成 μB0 与 μB1 两个微批对比执行，验证双微批计算等价性与 890 B/token 整网 KV 账本。

```python
import math, torch, torch.nn as nn, torch.nn.functional as F
rms = lambda t: t * torch.rsqrt(t.square().mean(-1, keepdim=True) + 1e-6)

def sinkhorn(logits: torch.Tensor, iters: int = 20) -> torch.Tensor:
    m = torch.exp(logits - logits.amax(dim=(-2, -1), keepdim=True))
    for _ in range(iters):
        m = m / (m.sum(dim=-2, keepdim=True) + 1e-12)
        m = m / (m.sum(dim=-1, keepdim=True) + 1e-12)
    return m

def partial_rope(x: torch.Tensor, pos: torch.Tensor, d_rope: int = 4, inv: bool = False) -> torch.Tensor:
    ang = pos.float().unsqueeze(-1) / (10000.0 ** (torch.arange(0, d_rope // 2, device=x.device) / (d_rope // 2)))
    c, s, t1, t2 = ang.cos(), (-ang.sin() if inv else ang.sin()), x[..., -d_rope::2], x[..., -d_rope + 1::2]
    return torch.cat([x[..., :-d_rope], torch.stack([t1 * c - t2 * s, t2 * c + t1 * s], dim=-1).flatten(-2)], dim=-1)

class MiniV41Layer(nn.Module):
    def __init__(self, is_kv_src: bool = True, has_eg: bool = False):
        super().__init__()
        self.d, self.d_kv, self.d_rope, self.is_kv_src = 16, 12, 4, is_kv_src
        self.phi, self.wq, self.wo = nn.Linear(64, 24, bias=False), nn.Linear(16, 12, bias=False), nn.Linear(12, 16, bias=False)
        self.wkv = nn.Linear(16, 12, bias=False) if is_kv_src else None
        self.eg_emb, self.eg_wkv = (nn.Embedding(17, 16), nn.Linear(16, 80, bias=False)) if has_eg else (None, None)
        self.router, self.shared, self.experts = nn.Linear(16, 4, bias=False), nn.Linear(16, 16, bias=False), nn.Linear(16, 64, bias=False)

    def forward(self, H, prefix, tok_ids, pos, shared_kv=None, topk_idx=None):
        def mhc(X):  # 双随机流形混合：产出 pre、post 与 Sinkhorn res 系数
            p, q, r = self.phi(rms(X.flatten(-2))).split([4, 4, 16], dim=-1)
            return torch.sigmoid(p).unsqueeze(-2), 2.0 * torch.sigmoid(q).unsqueeze(-2), sinkhorn(r.unflatten(-1, (4, 4)))
        pre_a, post_a, res_a = mhc(H)
        q = partial_rope(self.wq((pre_a @ H).squeeze(-2)), pos, self.d_rope)
        if self.is_kv_src:  # Full 层做 2x 序列折叠并产出共享压缩 KV 与 Top-K 索引
            kv_c = self.wkv(prefix.unflatten(1, (-1, 2)).mean(dim=2))
            shared_kv = partial_rope(kv_c, torch.arange(kv_c.shape[1], device=H.device).unsqueeze(0), self.d_rope)
            topk_idx = torch.topk((q.unsqueeze(1) * shared_kv).sum(-1), 4, dim=-1).indices
        kv_sel = torch.gather(shared_kv, 1, topk_idx.unsqueeze(-1).expand(-1, -1, self.d_kv))
        attn_w = F.softmax((q.unsqueeze(1) @ kv_sel.transpose(-1, -2)).squeeze(1) / math.sqrt(self.d_kv), dim=-1)
        ctx = partial_rope((attn_w.unsqueeze(1) @ kv_sel).squeeze(1), pos, self.d_rope, inv=True)  # 逆旋恢复相对位置编码
        H = res_a @ H + post_a.transpose(-1, -2) * self.wo(ctx).unsqueeze(-2)
        if self.eg_emb is not None:  # 边界门控注入 Engram（4:1 K/V 与有符号开方）
            ek, ev = self.eg_wkv(self.eg_emb(tok_ids % 17)).split([64, 16], dim=-1)
            z = (rms(H) * rms(ek.unflatten(-1, (4, 16)))).sum(-1) / 4.0
            H = H + torch.sigmoid(z.sign() * z.abs().clamp_min(1e-6).sqrt()).unsqueeze(-1) * ev.unsqueeze(-2)
        pre_m, post_m, res_m = mhc(H)
        xm = (pre_m @ H).squeeze(-2)
        w, ids = torch.topk(torch.sigmoid(self.router(xm)), 2, dim=-1)
        e_out = self.experts(xm).view(-1, 4, 16).gather(1, ids.unsqueeze(-1).expand(-1, -1, 16))
        moe = self.shared(xm) + ((w / w.sum(dim=-1, keepdim=True)).unsqueeze(-1) * e_out).sum(dim=1)
        return res_m @ H + post_m.transpose(-1, -2) * moe.unsqueeze(-2), shared_kv, topk_idx

class MiniV41DecodeStep(nn.Module):
    def __init__(self):
        super().__init__()
        self.l1, self.l2 = MiniV41Layer(is_kv_src=True, has_eg=True), MiniV41Layer(is_kv_src=False)
    def forward(self, H, prefix, tok_ids, pos):
        H, skv, idx = self.l1(H, prefix, tok_ids, pos)
        return self.l2(H, prefix, tok_ids, pos, skv, idx)[0].mean(dim=-2)

if __name__ == "__main__":
    torch.manual_seed(10)
    m, H, pre, tids, pos = MiniV41DecodeStep().eval(), torch.randn(4, 4, 16), torch.randn(4, 16, 16), torch.tensor([101, 205, 308, 412]), torch.full((4,), 8)
    with torch.no_grad():
        out_full, out_dbo = m(H, pre, tids, pos), torch.cat([m(H[:2], pre[:2], tids[:2], pos[:2]), m(H[2:], pre[2:], tids[2:], pos[2:])], dim=0)
        dbo_diff = (out_full - out_dbo).abs().max().item()
        assert dbo_diff < 1e-5 and int((3 * 0.5 + 1.0) * (512 * 0.5 + 32 + 68)) == 890
    print(f"[10-synthesis] out_shape={tuple(out_full.shape)}, dbo_max_diff={dbo_diff:.2e}, net_kv=(V3:{61*1152}B, V3.2:{61*788}B, V4.1:890B)")
```

运行输出：


校验结果显示，整批前向与拆成 μB0、μB1 两个微批独立执行的输出最大误差仅为 5.96e-07（源于浮点矩阵分块归约次序），验证了共享权重与只读压缩 KV 在微批拆分下的数学一致性；同时 V4.1-Flash 整网每 token 全局缓存 890 B 相比 V3 整网 70,272 B 收敛约 79 倍，与前文账本严格对齐。

把这么多部件放进同一张执行图之后，全链路的稳定就取决于几条必须同时成立的系统耦合前提。第一，在 `vLLM` 里只要启用了 `num_ubatches > 1` 的 DBO 微批重叠，执行期就必须保持 `FULL` 静态图捕获而禁止回退到分段图（`PIECEWISE`），同时请求批内必须凑够可均衡拆分的计算量，否则切换微批和事件同步的额外开销会超过通信掩盖收益[^vllm-synth]。第二，多卡部署时 `PipelineRelay`、上下文并行与分段编译都受限于状态跨界传递约束，微批启用后引擎还需同步关闭跨级缓存接力和有界解码重放等依赖全局一致批长的优化路径[^vllm-synth]。

第三，单步之内同时并存着环形尾缓存、跨层 `topk_indices_buffer`、双微批隔离的 `EngramModelState` 以及 DSpark 回滚槽位，昇腾图模式还依赖 `ExternalEvent` 与 `valid_token_count` 边界检查同步空跑卡，任何一处指针越界或脏状态残留都会沿着 4 条 mHC 残差通道向深层传播。

到这里，我们完成了从 DeepSeek-V2 到 V4.1-Flash 模型层架构与单步全链路的拆解。接下来要把这套复杂模型真正拉起为高并发在线服务，工程主战场转向请求调度、`torch.compile` 分段图与静态图捕获编排——请继续阅读 [系列四：vLLM 与昇腾推理引擎](../../vllm/)。
