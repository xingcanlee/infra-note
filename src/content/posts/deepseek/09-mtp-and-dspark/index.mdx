自回归解码每输出 1 个 token，都要把整张大权重从 HBM 搬进计算单元一次。当批量较小或 KV 缓存访问占主导时，算术强度远低于 GPU 与 NPU 的 Roofline 算力拐点，绝大多数矩阵计算核心都在等待数据搬运。

**Speculative Decoding（推测解码）**通过“廉价草稿先连猜 $K$ 步、目标模型一次并行验证 $1 + K$ 个位置”来摊薄单步权重读取开销[^spec-dec]。由于验证 1 个 token 和同时验证数个 token 搬运的权重总量相同，一旦前缀接受长度够长，每 token 分摊的权重访存就会成倍下降。

全篇符号与维度约定如下：

| 符号                       | 含义                                     | 取值 / 形状约定                                                                   |
| :------------------------- | :--------------------------------------- | :-------------------------------------------------------------------------------- |
| $K,\; k$                   | 单步草稿提议数量、草稿位置索引           | $k \in \{1, \dots, K\}$，单步最多推进 $K+1$ 个 token                              |
| $p(x),\; q(x)$             | 目标模型条件概率分布、草稿模型分布       | 均定义在词表 $x \in \{1, \dots, V\}$ 上                                           |
| $P_{\text{res}}(x),\; u$   | 拒绝后的归一化残差分布、均匀采样阈值     | $P_{\text{res}}(x) = \operatorname{norm}(\max(0, p(x) - q(x)))$，$u \sim U(0, 1)$ |
| $z_k^{\text{base}},\; z_k$ | 第 $k$ 步基础 logits、条件修正后 logits  | 均属于 $\mathbb{R}^{B \times V}$，$B$ 为批大小                                    |
| $W_1,\; W_2,\; r$          | 低秩马尔可夫修正头嵌入矩阵与输出投影     | $W_1 \in \mathbb{R}^{V \times r},\; W_2 \in \mathbb{R}^{r \times V},\; r = 256$   |
| $c_k,\; a_j$               | 第 $k$ 步条件接收率、第 $j$ 位前缀存活率 | $a_j = \prod_{i=1}^j c_i \in (0, 1)$                                              |
| $n_{\text{win}}$           | DSpark 草稿侧 SWA 滑动窗口宽度           | V4.1-Flash 采用 3 层 SWA，$n_{\text{win}} = 128$                                  |

## 无损拒绝采样与分布等价证明

假设草稿模型顺次提出候选序列 $(x_1, \dots, x_K)$，各位置对应的草稿概率为 $q(x)$，主干大模型一次性前向并行算出每个位置上的真实条件概率 $p(x)$。若不作分布校正而直接按经验阈值接收草稿，整句输出就会偏离目标模型。

标准无损拒绝采样的校验规则可拆成三步。在交互操作图 1 的阈值滑块观察概率条与重采样分布前，我们先明确这三条裁决逻辑。

结合图 1 的 4 个候选位置（$K = 4$），验证阶段从左到右在每个位置独立抽取均匀随机数 $u \sim U(0, 1)$。若满足 $u \le \min\!\big(1, p(x)/q(x)\big)$，则保留该草稿 token 并继续检查下一位。

一旦某位置出现拒绝，立即丢弃之后所有草稿后缀，在该位置构造归一化残差分布 $P_{\text{res}}(x) = \operatorname{norm}\!\big(\max(0,\, p(x) - q(x))\big)$ 并从 $P_{\text{res}}(x)$ 重采样 1 个合法 token 替代。若全部 $K$ 个候选位置均通过检验，主模型在末端位置 $K + 1$ 已算出的 logits 还可以额外采样 1 个奖励（Bonus）token，单步最多推进 $K + 1$ 个 token[^spec-dec]。

### 边缘分布等价性推导

对词表中任意 token $x$，最终在这一位置输出 $x$ 的事件由“草稿选出 $x$ 且被接收”与“某个提案被拒后落入残差重采样并抽中 $x$”两个互斥事件组成。先求单步触发拒绝的总概率 $P(\text{reject})$：

$$
\begin{aligned}
P(\text{reject}) &= \sum_{y} q(y)\left(1 - \min\!\left(1, \frac{p(y)}{q(y)}\right)\right) \\
&= \sum_{y} \max\!\big(0,\, q(y) - p(y)\big)
\end{aligned}
$$

由于 $\sum_y p(y) = \sum_y q(y) = 1$，草稿超出目标的概率质量之和与欠缺的概率质量之和必定相等，即 $\sum_y \max(0, q(y) - p(y)) = \sum_y \max(0, p(y) - q(y)) = Z$，恰好等于残差分布的分母 $Z$。因此最终采到任意 $x$ 的边缘概率为：

$$
\begin{aligned}
P_{\text{final}}(x) &= q(x)\min\!\left(1, \frac{p(x)}{q(x)}\right) + P(\text{reject}) \cdot \frac{\max(0, p(x) - q(x))}{Z} \\
&= \min(p(x), q(x)) + \max(0, p(x) - q(x)) = p(x)
\end{aligned}
$$

无论草稿模型多么粗糙，只要经过上述拒绝采样与残差重采样校正，单步乃至整条序列的联合分布都等于主干大模型独立自回归采样的结果，草稿质量只会影响期望接受长度而不会损伤输出分布。

## MTP、DFlash 与 DSpark 演进

解决无损验证后，系统瓶颈转到草稿侧。记草稿耗时为 $T_{\text{draft}}$、目标验证耗时为 $T_{\text{verify}}$、单步平均接受长度为 $\tau$，则推测解码的每 token 平均延迟为[^dspark-paper]：

$$
L = \frac{T_{\text{draft}} + T_{\text{verify}}}{\tau}
$$

提升加速比归结为三条路径：压低 $T_{\text{draft}}$、拉高 $\tau$，以及裁剪无效验证以降低 $T_{\text{verify}}$。草稿模型也顺着这条权衡演化出因果自回归、单次并行与半自回归三条路线。

### 自回归草稿：V3 因果 MTP

在 DeepSeek 之前，**MTP（Multi-Token Prediction，多 token 预测）**主要用于训练阶段：在主干模型末端追加若干轻量预测头，一次预测未来多个位置，提高样本梯度利用率[^v3-mtp]。DeepSeek-V3 将训练好的 MTP 模块直接复用到推理阶段充当草稿模型，省去单独训练小模型的成本，并在每个预测深度保留了完整的因果链（图 2）。

对照 `vLLM` 的 `DeepSeekMultiTokenPredictorLayer` 实现[^vllm-spec]，第 $k$ 步预测先把上一步隐状态与第 $k$ 步嵌入各自归一化。两者沿特征维拼接后，再经 `eh_proj` 从 $2H$ 压回 $H$。

合并特征再穿过 1 个轻量级 `mtp_block` 写入草稿层自身的 KV 缓存，最后送入共享输出头 `SharedHead` 采样第 $k$ 步草稿。由于第 $k$ 步依赖前一步采到的 token $x_{k-1}$，草稿生成耗时随步数线性增长（$T_{\text{draft}} \propto K$），$K=4$ 时须串行发起 4 次前向，把 MTP-1 以外的多步草稿生成限制在很浅的模块规模内[^dspark-paper]。

### 并行草稿：DFlash 特征注入

为了打破 $T_{\text{draft}} \propto K$ 的串行瓶颈，并行草稿模型改在一次前向内同时产出全部 $K$ 个位置的分布，使 $T_{\text{draft}}$ 几乎不随候选长度增加。其中 **DFlash** 是代表性的特征注入式并行草稿方案（图 3），从两个环节保证单次生成的质量[^dspark-paper]：

1. **跨层 KV 注入**：抽取目标模型若干代表层隐状态，经 `RMSNorm` 与投影得上下文特征 $H_{\text{ctx}}$，拼入草稿模型各层的键值序列中[^dspark-paper]。
2. **锚点加 Mask 前向**：把上一轮验证出的锚点 token 与 $K$ 个 `[MASK]` 拼成连续块并复用冻结词头，一次前向双向交互并同时预测全部候选分布[^dspark-paper]。

![DFlash 跨层 KV 特征注入与锚点加 Mask 单次并行草稿生成架构图](./diagrams/09-dflash-arch.drawio '图 3：DFlash 跨层 KV 注入与锚点加 Mask 单次并行草稿生成架构')

对照 `vLLM` 的 `DFlashSpeculator` 实现[^vllm-spec]，引擎正是靠准备锚点与 Mask 输入配合 `KV` 注入完成整块单次并行生成。不过各位置独立采样时彼此不可见，位置 $k$ 看不到前一位刚采出的 token。遇到多种合法续写并存时（如 `"of course"` 与 `"no problem"`），容易混搭出 `"of problem"`，导致越靠后接受率越低[^dspark-paper]。

### 半自回归 DSpark：并行骨架与低秩修正

为了兼具 DFlash 的单次并行速度与 MTP 的词间连贯性，DSpark[^dspark-paper] 与 DeepSeek-V4.1-Flash[^v41-flash] 将架构升级为“并行草稿骨干 + 微秒级低秩马尔可夫链”（图 4）。对照 `DeepseekV41DSparkModel` 的实现[^ascend-spec]，草稿侧把目标模型代表层特征投影进 3 层 SWA（$n_{\text{win}} = 128$）。同时它让锚点本身充当第 1 个预测位，只需额外拼入 $K - 1$ 个 Mask，一次前向就能产出全部位置的基础 logits $z_k^{\text{base}}$。

针对纯并行生成缺少块内依赖的问题，DSpark 在基础 logits 后串接了低秩 $r = 256$ 的马尔可夫修正头 `DSparkMarkovHead`[^vllm-spec]，从左到右逐位加上前驱 token $x_{k-1}$ 的转移偏置：

$$
\begin{aligned}
z_k &= z_k^{\text{base}} + W_1[x_{k-1}]\, W_2 \\
W_1 &\in \mathbb{R}^{V \times r},\quad W_2 \in \mathbb{R}^{r \times V},\quad r = 256
\end{aligned}
$$

其中 $W_1$ 相当于词表嵌入查找表，$W_2$ 是窄瓶颈投影矩阵。每步只需从 $W_1$ 查出第 $x_{k-1}$ 行并做一次 $[B, 256] \times [256, V]$ 窄矩阵乘，就能在微秒级耗时内补全草稿的局部上下文关联。图 5 定量对比了 $K = 4$ 时 V3 串行 MTP（11.8 ms）与 V4.1 DSpark 并行草稿链（6.0 ms，时延减半）的泳道差异。

![DeepSeek-V3 串行 MTP（11.8 ms）与 V4.1 DSpark 并行 SWA + r=256 低秩马尔可夫链（6.0 ms，时延减半）对比](./diagrams/09-dspark-vs-mtp.drawio '图 5：DeepSeek-V3 串行 MTP 与 V4.1 DSpark 轻量并行草稿链时序对比')

高并发场景下，盲目验证过长草稿反而会占用批容量。为此 DSpark 配备了置信度头 `DSparkConfidenceHead`[^dspark-paper][^v41-flash]。它在各草稿位预测单步条件接收概率 $c_k \in (0, 1)$（离线经 Sequential Temperature Scaling 校准），运行时按链式法则累乘出前缀存活概率 $a_j = \prod_{i=1}^j c_i$。

在 GPU 侧，`AdaptiveVerificationManager` 将浮点存活概率按位转为整型后执行二分检索[^vllm-adaptive]。线上实测表明（图 6），随着并发请求数攀升，系统会自动把验证预算从接近 5.5 个草稿动态下压到 3.5 左右，在 Flash 与 Pro 两条模型线上全面超越固定预算的 MTP 基线[^dspark-paper]。

下表总结了三种草稿架构在结构依赖与延迟伸缩上的核心取舍[^v3-mtp][^dspark-paper]：

| 草稿架构          | 生成方式     | 块内词间依赖     | 生成耗时趋势         | 核心权衡                 |
| :---------------- | :----------- | :--------------- | :------------------- | :----------------------- |
| `DeepSeek-V3 MTP` | 因果逐位串行 | 完整自回归依赖   | 随步数 $K$ 线性增长  | 单步慢，通常限短步       |
| `DFlash`          | 单次双向并行 | 无块内依赖       | 几乎与 $K$ 无关      | 快但后缀易因不一致而衰减 |
| `DSpark`          | 并行骨架+头  | $r=256$ 马尔可夫 | 一次前向加微秒级串行 | 兼具低延迟与高接受率     |

## PyTorch 无损采样与低秩草稿链

下面这段自包含 PyTorch 代码覆盖两项验证。首先，`lossless_rejection_sample` 对失真放大两倍的草稿分布做 50,000 次拒绝与重采样，检验总变差收敛性。其次，`DSparkMarkovHead` 演示并行基础 logits 如何借助秩 256 双线性表完成条件修正。

```python
import torch
import torch.nn as nn


def lossless_rejection_sample(
    p: torch.Tensor, q: torch.Tensor, n_samples: int
) -> tuple[torch.Tensor, float]:
    """向量化无损拒绝采样：对草稿分布 q 采样并用残差分布 norm(max(0, p - q)) 补偿被拒位。"""
    # 1. 从草稿分布 q 采样候选 token，按 min(1, p(x)/q(x)) 概率接收
    drafts = torch.multinomial(q, n_samples, replacement=True)
    probs_ratio = (p[drafts] / q[drafts]).clamp_max(1.0)
    accept_mask = torch.rand(n_samples, dtype=p.dtype) <= probs_ratio

    # 2. 构造残差补偿分布 P_res(x) = norm(max(0, p(x) - q(x)))，补齐欠采样 token 的概率质量
    res = torch.clamp(p - q, min=0.0)
    res_p = res / res.sum()

    # 3. 仅对被拒绝槽位从残差分布 P_res 重采样替换，保证最终边缘分布等于目标 p
    n_reject = int((~accept_mask).sum().item())
    final_tokens = drafts.clone()
    final_tokens[~accept_mask] = torch.multinomial(res_p, n_reject, replacement=True)
    return final_tokens, accept_mask.float().mean().item()


class DSparkMarkovHead(nn.Module):
    """V4.1 DSpark 低秩马尔可夫条件修正头（对应 qwen3_dspark.py）。"""

    def __init__(self, vocab_size: int = 1024, markov_rank: int = 256):
        super().__init__()
        # 低秩分解转移矩阵 W_1 [V, r] 与 W_2 [r, V]，将条件转移压进 r=256 窄瓶颈
        self.markov_w1 = nn.Embedding(vocab_size, markov_rank)
        self.markov_w2 = nn.Linear(markov_rank, vocab_size, bias=False)

    def forward(self, prev_tokens: torch.Tensor) -> torch.Tensor:
        return self.markov_w2(self.markov_w1(prev_tokens))

    def draft_chain(self, base_logits: torch.Tensor, prev: torch.Tensor) -> torch.Tensor:
        drafted = []
        for k in range(base_logits.shape[1]):
            logits_k = base_logits[:, k] + self(prev)
            prev = logits_k.argmax(dim=-1)
            drafted.append(prev)
        return torch.stack(drafted, dim=1)


if __name__ == "__main__":
    torch.manual_seed(9)
    # 故意放大第 2 个 token 的草稿概率（0.50 vs 0.25），检验残差重采样仍无损收敛回目标分布 p
    p = torch.tensor([0.35, 0.25, 0.30, 0.10], dtype=torch.float64)
    q = torch.tensor([0.20, 0.50, 0.20, 0.10], dtype=torch.float64)
    trials = 50_000
    sampled, accept_rate = lossless_rejection_sample(p, q, trials)
    emp = torch.bincount(sampled, minlength=4).double() / trials
    tv = 0.5 * (emp - p).abs().sum().item()
    assert tv < 0.01

    B, K, V, r = 2, 5, 1024, 256
    head = DSparkMarkovHead(vocab_size=V, markov_rank=r)
    with torch.no_grad():
        base_logits = torch.randn(B, K, V)
        prev = torch.tensor([10, 42], dtype=torch.long)
        drafted = head.draft_chain(base_logits, prev)
    assert drafted.shape == (B, K)
    print(
        f"[09-mtp-dspark] lossless_TV={tv:.5f}, accept_rate={accept_rate:.4f}, "
        f"dspark_draft_shape={tuple(drafted.shape)}"
    )
```

校验输出：

```text
[09-mtp-dspark] lossless_TV=0.00270, accept_rate=0.7503, dspark_draft_shape=(2, 5)
```

尽管人为把第 2 个 token 的草稿概率放大到目标的两倍（0.50 对 0.25），50,000 次采样后的总变差仅为 0.00270，低于 0.01 阈值。单步接收率 0.7503 也吻合理论期望 $\sum_x \min(p, q) = 0.20 + 0.25 + 0.20 + 0.10 = 0.75$。

| 机制维度     | `vllm` GPU 栈              | `vllm-ascend` NPU 栈                  |
| ------------ | -------------------------- | ------------------------------------- |
| 草稿调度类   | 复用 `DFlash` 与独立重排器 | 混入词表对齐与 NPU 专属图管理         |
| 稀疏索引复用 | 步间压缩复用首步候选索引   | 跳过 `DSA`/`SFA` 步间解码重写         |
| 多卡词表采样 | 按请求转置词表分片本地采样 | 填充至统一容量后再做集合裁剪          |
| 静态图适配   | 按自适应开关切换图捕获模式 | 关闭 FIA 尾部填充并动态重分配槽位     |
| 拒绝采样算子 | 支持 FP64 校验与批量分片   | 禁用 FP64 与水印，改用概率拒绝 Triton |

围绕多卡采样与静态图对齐，两套运行时在两处存在架构分歧。第一处在词表并行边界：`vLLM` GPU 侧通过 `DSparkSpeculator` 里的 `all_to_all_vocab_shards` 重排词表分片[^vllm-spec]。转置后，每张卡持有部分请求的完整词表。

随后 $K$ 步 `DSparkMarkovHead` 采样循环就能留在单卡本地完成，无需每步做卡间 `AllReduce`。

昇腾 `AscendDSparkSpeculator` 则关闭了 `supports_batch_sharded_draft_logits`[^ascend-spec]。它改由 `LmheadTPDraftSamplingMixin` 在 `compute_draft_logits` 前把输入行填充到 TP 约定上限，算完再裁回真实行数。同时 NPU 拒绝采样算子禁用 FP64 校验、`fly_window_size` 在途窗口与水印路径。

第二处在动态验证步数与静态图捕获的兼容：只要开启 `AdaptiveVerificationManager`，各请求的验证步数就会随置信度实时波动，破坏固定输入长度 `FULL` 图假设。

GPU 侧在调度初始化阶段由 `resolve_adaptive_cudagraph_mode` 切至兼容可变长批的图路由[^vllm-adaptive]。NPU 侧则在 `NPUModelRunner` 中跳过固定图形状的 FIA 序列尾部填充，改用 `compact_batch` 与 `reallocate_drafts` 紧缩有效草稿位后再验证[^ascend-spec]。

部署开启推测解码时需守住两道边界。一方面，高温度采样或生僻代码场景会让平均接受率跌破盈亏线，此时草稿与多位置并行验证反而拖慢延迟，必须依赖动态预算截断主动缩回验证长度。另一方面，前缀拒绝丢弃尾部草稿时，引擎既要回退分页 KV 指针，也必须重置 DSpark 的 `context_wkv_proj` 状态。同时 SWA 边界与已 Prefetch 的 Engram 槽位也要一并回滚，避免脏状态污染后续前缀。

至此，DeepSeek 系列从注意力压缩、MoE、Engram、mHC 到 MTP 与 DSpark 的单模块设计已经各自明确。最后一篇 [10 全链路整合：V4.1 单步执行与双硬件协同](../10-architecture-synthesis/) 将把这些模块合入同一条 decode 时间线与双微批集群流水线中。
