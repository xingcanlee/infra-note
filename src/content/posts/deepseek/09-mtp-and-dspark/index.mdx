自回归解码每输出 1 个 token，都要把整张大权重从 HBM 搬进计算单元一次。当批量较小或 KV 缓存访问占主导时，算术强度远低于 GPU 与 NPU 的 Roofline 算力拐点，绝大多数矩阵计算核心都在等待数据搬运。

**Speculative Decoding（推测解码）**通过「廉价草稿先连猜 $\gamma$ 步、目标模型一次并行验证 $1 + \gamma$ 个位置」来摊薄单步权重读取开销[^spec-dec]。由于验证 1 个 token 和同时验证数个 token 搬运的权重总量相同，多算几个查询位置几乎不增加额外访存延迟；一旦验证通过前缀够长，平均每 token 分摊的权重访存就会成倍下降。

## 无损拒绝采样与分布等价证明

假设草稿模型顺次提出候选序列 $(x_1, \dots, x_\gamma)$，各位置对应的草稿概率为 $q(x)$，主干大模型一次性前向并行算出每个位置上的真实条件概率 $p(x)$。若不作分布校正而直接按经验阈值接收草稿，整句输出就会偏离目标模型。

标准无损拒绝采样的校验规则可拆成三步。在步进图 1 的概率条与重采样柱状对比前，我们先明确这三条裁决逻辑。

结合图 1 的 4 个候选槽位，验证阶段从左到右在每个位置独立抽取均匀随机数 $u \sim U(0, 1)$：若满足 $u \le \min\!\big(1, p(x)/q(x)\big)$，则保留该草稿 token 并继续检查下一位；一旦在第一个位置出现拒绝，立即丢弃之后所有草稿后缀，在该位置构造截断归一化残差分布 $p'(x) = \operatorname{norm}\!\big(\max(0,\, p(x) - q(x))\big)$ 并从 $p'(x)$ 补抽 1 个合法 token 替代；如果全部 $\gamma$ 个候选位置均通过检验，主模型在末端位置 $\gamma + 1$ 已经算出的 logits 还可以额外采样 1 个奖励 token，使单步最多推进 $\gamma + 1$ 个 token[^spec-dec]。

### 边缘分布等价性推导

对词表中任意 token $x$，最终在这一位置输出 $x$ 的事件由「草稿选出 $x$ 且被接收」与「某个提案被拒后落入残差重采样并抽中 $x$」两个互斥事件组成。先求单步触发拒绝的总概率 $P(\text{reject})$：

$$
\begin{aligned}
P(\text{reject}) &= \sum_{y} q(y)\left(1 - \min\!\left(1, \frac{p(y)}{q(y)}\right)\right) \\
&= \sum_{y} \max\!\big(0,\, q(y) - p(y)\big)
\end{aligned}
$$

由于 $\sum_y p(y) = \sum_y q(y) = 1$，草稿超出目标的概率质量之和与欠缺的概率质量之和必定相等，即 $\sum_y \max(0, q(y) - p(y)) = \sum_y \max(0, p(y) - q(y)) = Z$，恰好等于残差分布的分母 $Z$。因此最终采到任意 $x$ 的边缘概率为：

$$
\begin{aligned}
P_{\text{final}}(x) &= q(x)\min\!\left(1, \frac{p(x)}{q(x)}\right) + P(\text{reject}) \cdot \frac{\max(0, p(x) - q(x))}{Z} \\
&= \min(p(x), q(x)) + \max(0, p(x) - q(x)) = p(x)
\end{aligned}
$$

无论草稿模型多么粗糙，只要经过上述拒绝采样与残差重采样校正，单步乃至整条序列的联合分布都严格等于主干大模型独立自回归采样的结果，草稿质量只会影响期望接受长度而不会损伤输出分布。

## 从 DeepSeek-V3 因果 MTP 到 V4.1 DSpark

解决无损验证后，系统瓶颈转移到草稿侧本身的延迟：如果草稿模型每猜一步都要串行重跑一层 Decoder 与全词表投影，推测收益会被草稿耗时抵消。图 2 对比了两代架构在草稿生成与检验阶段的时序演进。

### DeepSeek-V3 因果 MTP 与串行层开销

DeepSeek-V3 在预训练期间联合训练了 **MTP（Multi-Token Prediction，多 token 预测）**模块[^v3-mtp]。在 `vLLM` 实现的 `DeepSeekMultiTokenPredictorLayer` 中[^vllm-spec]，第 $k$ 步预测先把上一步主干隐藏状态与第 $k$ 步输入嵌入各自经 `hnorm`、`enorm` 归一化，沿特征维拼接后通过 `eh_proj` 从 $2H$ 压回 $H$；合并特征再穿过 1 个轻量级 `mtp_block` 写入草稿层自己的 KV 缓存，最后送入复用的共享输出头 `SharedHead` 采样第 $k$ 步草稿。这套设计复用了目标模型的嵌入层与输出投影，但受制于严格的自回归因果依赖：当预测深度 $K = 3$ 时，引擎仍须串行发起 3 次 `mtp_block` 前向与 3 次全词表采样，小批量下的 Kernel 启动与卡间 `AllReduce` 延迟会随步数线性累积（图 2 上泳道）。

### V4.1 DSpark 并行 SWA、低秩马尔可夫头与置信度调度

为了突破串行草稿延迟，DSpark[^dspark-paper] 与 DeepSeek-V4.1-Flash[^v41-flash] 将多步串行起草改为「一次并行 Draft 模型特征提取 + 微秒级低秩马尔可夫链」的半自回归架构。对照 `DeepseekV41DSparkModel` 的实现[^ascend-spec]，Draft 模型从主模型挑选若干代表层的隐状态拼接起来，经 `main_proj`、`main_norm` 与 `context_wkv_proj` 一次性投影进 3 层 SWA（Sliding Window Attention，滑动窗口注意力，窗宽 128）KV 槽位。随后 Draft 模型把上一轮的锚点 token 与 $\gamma - 1$ 个占位掩码拼成连续块，单次并行前向即可同时产出未来 $\gamma$ 个位置的基础 logits $\mathbf{z}_k^{\text{base}}$，消除了 Draft 前向耗时随 $\gamma$ 线性增长的限制。

然而纯并行前向会丢失块内 token 之间的强条件依赖——当语境允许多个合法续写时（如 `"of course"` 与 `"no problem"`），各位置独立边缘分布采样容易混搭出 `"of problem"` 之类的碰撞错误[^dspark-paper]。为此，DSpark 在并行输出的基础 logits 上串接了一个低秩 $r = 256$ 的马尔可夫条件修正头 `DSparkMarkovHead`[^vllm-spec]，左到右依次补回相邻前驱 token $x_{k-1}$ 的转移偏置：

$$
\begin{aligned}
\mathbf{z}_k &= \mathbf{z}_k^{\text{base}} + \mathbf{W}_1[x_{k-1}]\, \mathbf{W}_2 \\
\mathbf{W}_1 &\in \mathbb{R}^{V \times r},\quad \mathbf{W}_2 \in \mathbb{R}^{r \times V},\quad r = 256
\end{aligned}
$$

其中 $\mathbf{W}_1$ 相当于词表嵌入查找表，$\mathbf{W}_2$ 是窄瓶颈投影矩阵。每一步只需从 $\mathbf{W}_1$ 查出第 $x_{k-1}$ 行再做一次 $[B, 256] \times [256, V]$ 的极窄矩阵乘，就能在微秒级时间内串联起连续草稿的上下文连贯性（图 2 下泳道）。

针对高并发场景下盲目验证过长草稿反而占用批容量的系统问题，DSpark 还配备了置信度头 `DSparkConfidenceHead`[^dspark-paper][^v41-flash]。它在每个草稿位点预测单步条件接收概率 $c_k \in (0, 1)$（离线通过 Sequential Temperature Scaling 校准），运行时按链式法则累乘出前缀存活概率 $a_j = \prod_{i=1}^j c_i$。在高并发下，GPU 侧 `AdaptiveVerificationManager` 通过将浮点存活概率按位转为整型后执行二分检索（`_assign_draft_token_budget_kernel`）[^vllm-adaptive]，结合引擎吞吐曲线动态裁掉低期望回报的长尾草稿，避免无效验证把批量推过计算拐点。

## PyTorch 参考实现：无损拒绝采样与低秩马尔可夫头

下面这段自包含 PyTorch 代码覆盖两条核心验证：一方面通过 `lossless_rejection_sample` 对人为放大两倍失真的草稿分布做 50,000 次拒绝与残差重采样，检验边缘分布的总变差收敛性；另一方面通过 `DSparkMarkovHead` 演示并行 SWA 基础 logits 如何借助秩 256 双线性查找表完成左到右条件修正。

```python
import torch
import torch.nn as nn


def lossless_rejection_sample(
    p: torch.Tensor, q: torch.Tensor, n_samples: int
) -> tuple[torch.Tensor, float]:
    """向量化无损拒绝采样：对草稿分布 q 采样并用残差分布 norm(max(0, p - q)) 补偿被拒位。"""
    # 1. 从草稿分布 q 采样候选 token，按 min(1, p(x)/q(x)) 概率接收
    drafts = torch.multinomial(q, n_samples, replacement=True)
    probs_ratio = (p[drafts] / q[drafts]).clamp_max(1.0)
    accept_mask = torch.rand(n_samples, dtype=p.dtype) <= probs_ratio

    # 2. 构造残差补偿分布 p'(x) = norm(max(0, p(x) - q(x)))，补齐欠采样 token 的概率质量
    res = torch.clamp(p - q, min=0.0)
    res_p = res / res.sum()

    # 3. 仅对被拒绝槽位从残差分布 p' 重采样替换，保证最终边缘分布严格等于目标 p
    n_reject = int((~accept_mask).sum().item())
    final_tokens = drafts.clone()
    final_tokens[~accept_mask] = torch.multinomial(res_p, n_reject, replacement=True)
    return final_tokens, accept_mask.float().mean().item()


class DSparkMarkovHead(nn.Module):
    """V4.1 DSpark 低秩马尔可夫条件修正头（对应 qwen3_dspark.py）。

    输入：
        base_logits: [B, n_spec, V]（由 3 层 SWA Draft 模型一次并行产出）
        prev:        [B]（第 0 步起始 token ID）
    输出：
        drafted:     [B, n_spec]（依次修正采样出的草稿 token 序列）
    """

    def __init__(self, vocab_size: int = 1024, markov_rank: int = 256):
        super().__init__()
        # 低秩分解转移矩阵 W_1 [V, r] 与 W_2 [r, V]，将条件转移压进 r=256 窄瓶颈
        self.markov_w1 = nn.Embedding(vocab_size, markov_rank)
        self.markov_w2 = nn.Linear(markov_rank, vocab_size, bias=False)

    def forward(self, prev_tokens: torch.Tensor) -> torch.Tensor:
        # O(1) 取出 prev_tokens 对应行后乘 W_2，等价 [B, r] @ [r, V] -> [B, V] 条件偏置
        return self.markov_w2(self.markov_w1(prev_tokens))

    def draft_chain(self, base_logits: torch.Tensor, prev: torch.Tensor) -> torch.Tensor:
        drafted = []
        for i in range(base_logits.shape[1]):
            # 第 k 步并行基础 logits 加上刚采出的第 k-1 步马尔可夫偏置，形成微秒级条件链
            logits_i = base_logits[:, i] + self(prev)
            prev = logits_i.argmax(dim=-1)
            drafted.append(prev)
        return torch.stack(drafted, dim=1)


if __name__ == "__main__":
    torch.manual_seed(9)
    # 故意放大第 2 个 token 的草稿概率（0.50 vs 0.25），检验残差重采样仍无损收敛回目标分布 p
    p = torch.tensor([0.35, 0.25, 0.30, 0.10], dtype=torch.float64)
    q = torch.tensor([0.20, 0.50, 0.20, 0.10], dtype=torch.float64)
    trials = 50_000
    sampled, accept_rate = lossless_rejection_sample(p, q, trials)
    emp = torch.bincount(sampled, minlength=4).double() / trials
    tv = 0.5 * (emp - p).abs().sum().item()
    assert tv < 0.01

    B, n_spec, V, r = 2, 5, 1024, 256
    head = DSparkMarkovHead(vocab_size=V, markov_rank=r)
    with torch.no_grad():
        base_logits = torch.randn(B, n_spec, V)
        prev = torch.tensor([10, 42], dtype=torch.long)
        drafted = head.draft_chain(base_logits, prev)
    assert drafted.shape == (B, n_spec)
    print(
        f"[09-mtp-dspark] lossless_TV={tv:.5f}, accept_rate={accept_rate:.4f}, "
        f"dspark_draft_shape={tuple(drafted.shape)}"
    )
```

校验输出：

```text
[09-mtp-dspark] lossless_TV=0.00270, accept_rate=0.7503, dspark_draft_shape=(2, 5)
```

尽管人为把第 2 个 token 的草稿概率放大到目标的两倍（0.50 对 0.25），50,000 次采样后的总变差仅为 0.00270（低于 0.01 阈值），单步接收率 0.7503 也严格吻合理论期望 $\sum_x \min(p, q) = 0.20 + 0.25 + 0.20 + 0.10 = 0.75$。

## 双硬件生产运行时：vLLM GPU 与 vllm-ascend

把草稿起草与置信度裁剪真正接进多卡 TP（Tensor Parallelism，张量并行）与 CUDA Graph / ACLGraph 静态图捕获时，`vLLM` GPU 与 `vllm-ascend` NPU 在词表并行、图模式路由与拒绝采样 Kernel 上走出了清晰差异，整体执行栈如图 3 所示。

![vLLM GPU 与 Ascend NPU Speculator 运行时栈对照](./diagrams/09-mtp-vllm-runtime.drawio '图 3：vLLM V1 GPU Speculator 与 vllm-ascend V2 混合扩展运行时栈对照')

下表从五个结构维度对照两套运行时实现[^vllm-spec][^vllm-adaptive][^ascend-spec]：

| 机制维度     | `vllm` GPU 栈              | `vllm-ascend` NPU 栈              |
| ------------ | -------------------------- | --------------------------------- |
| 草稿调度类   | 复用 `DFlash` 与独立重排器 | 混入词表对齐与 NPU 专属图管理     |
| 稀疏索引复用 | 步间压缩复用首步候选索引   | 跳过 `DSA`/`SFA` 步间解码重写     |
| 多卡词表采样 | 按请求转置词表分片本地采样 | 填充至统一容量后再做集合裁剪      |
| 静态图适配   | 按自适应开关切换图捕获模式 | 关闭 FIA 尾填充并动态重分配槽位   |
| 拒绝采样核   | 支持 FP64 校验与批量分片   | 禁 FP64/水印，改用概率拒绝 Triton |

围绕多卡采样与静态图对齐，两套运行时的工程分岔主要落在两处。第一处在词表并行与拒绝采样 Kernel 边界：在 `DSparkSpeculator` 中，GPU 侧通过 `all_to_all_vocab_shards` 将按词表切分的基础 logits 转置为「每张卡持有部分请求的完整词表」，从而让后续 $\gamma$ 步 `DSparkMarkovHead` 采样循环留在单卡本地完成，无需每步做卡间 `AllReduce`[^vllm-spec]；而 `AscendDSparkSpeculator` 将 `supports_batch_sharded_draft_logits` 设为 `False`，改由 `LmheadTPDraftSamplingMixin` 在调用 `compute_draft_logits` 前将输入行对齐填充至 TP 组约定的 `max_num_reqs * num_speculative_steps` 上限、计算后再裁回真实行数，同时在 NPU 拒绝采样 Kernel 内禁用 `use_fp64`、`fly_window_size > 0` 与水印路径[^ascend-spec]。

第二处在动态验证步数与静态图捕获的兼容：只要开启 `AdaptiveVerificationManager`，各请求的验证步数就会随置信度实时波动，破坏固定输入长度 `FULL` 图假设。GPU 侧在调度初始化阶段由 `resolve_adaptive_cudagraph_mode` 切换至兼容可变长批的图路由[^vllm-adaptive]；NPU 侧则在 `NPUModelRunner` 中判断启用自适应验证时跳过面向固定图形状的 FIA 序列尾填充，并通过 `compact_batch` 与 `reallocate_drafts` 重新紧缩有效草稿位后再送入目标模型验证[^ascend-spec]。

工程部署开启推测解码时，需要同步守住两道边界。一方面，当高温度采样或极生僻代码上下文导致平均接受率跌破盈亏线时，草稿前向与多槽位验证的额外计算会直接拖慢单步延迟，此时必须依赖动态预算截断主动缩回验证长度；另一方面，只要发生前缀拒绝并丢弃尾部草稿，引擎不仅要回退分页 KV 的写入指针，还必须同步重置或回滚 DSpark 的 `context_wkv_proj` 状态、SWA 滑窗边界以及前置预取的 Engram 槽位，避免脏状态污染下一轮前缀。
