第 06 篇给了三个结构性指标（密度、单步代价上限、可达范围），它们只看掩码形状，不看数值。第 07–11 篇逐个讲了机制。

这一篇把它们**放在同一个 query 上真的跑一遍**，加两个数值指标：挑中的位置覆盖了多少注意力质量、最终输出和全注意力差多少。读完你能回答：为什么「读得多」不如「挑得准」、为什么覆盖率 100% 的机制反而可能输出最差。

## 实验设定

序列长 512，看最后一个位置。$d=64$，Q/K/V 随机生成，但**人为在位置 37、150、400 附近各植入一个与当前 query 相关的区域**——否则所有机制都等价于随机抽样，比较没有意义。

三个指标：

| 指标           | 定义                           | 回答什么       |
| -------------- | ------------------------------ | -------------- |
| **读取量**     | 这一步实际参与注意力的条目数   | 成本           |
| **注意力质量** | 选中位置在全注意力权重里的总和 | 挑得准不准     |
| **输出余弦**   | 与全注意力输出向量的余弦相似度 | 最终结果对不对 |

后两个必须分开看——这一篇的核心结论就藏在它们的差异里。

## 结果

```
机制                                      读取       注意力质量      输出余弦  说明
────────────────────────────────────────────────────────────────────────────
全注意力（基线）                            512      100.0%    1.0000  读完全部历史
SWA w=64                                  64        0.2%    0.0543  只读最近的
SWA w=64 + 4 sink                         68        0.2%    0.0792  加前缀锚点
NSA 式（选 9 块 + 窗口 64）                288       99.5%    1.0000  块分数复用压缩分支
DSA 式 top-64（随机初始化 indexer）         64       14.5%    0.2578  indexer 没训练
DSA 式 top-64（完美 indexer 上限）          64       99.1%    1.0000  上限参考
CSA 式（压 4 倍后选 16 + 窗口 16）          32       99.0%    0.7745  两级：压缩+稀疏
HCA 式（压 64 倍后全读 + 窗口 16）          24      100.0%    0.0951  覆盖全历史但很糊
```

### 结论一：挑得准 ≫ 读得多

SWA 和「完美 indexer 的 top-64」**读取量完全相同（64 个）**，结果天差地别：

|             | 注意力质量 | 输出余弦 |
| ----------- | ---------- | -------- |
| SWA w=64    | 0.2%       | 0.0543   |
| 完美 top-64 | 99.1%      | 1.0000   |

同样的预算，一个几乎全错、一个几乎完美。差别只在**选哪 64 个**。

这解释了为什么稀疏注意力从固定模式走向按内容选择：位置本身不携带相关性信息。当然这里的相关区域是人为植入在远处的——真实文本的相关性通常更偏向局部，SWA 不会这么惨。但方向是明确的。

### 结论二：DSA 的全部风险都在打分上

同一个 top-64，换一个 indexer：

|                      | 注意力质量 | 输出余弦 |
| -------------------- | ---------- | -------- |
| 随机初始化的 indexer | 14.5%      | 0.2578   |
| 完美 indexer         | 99.1%      | 1.0000   |

第 09 篇说「indexer 打分的质量决定一切」，这就是它的量化版本。DSA 那套两阶段 KL 训练不是锦上添花——**没有它，机制本身是坏的**。

### 结论三：覆盖率 100% 也可能输出最差

这是本篇最反直觉的一行：

|                          | 注意力质量 | 输出余弦   |
| ------------------------ | ---------- | ---------- |
| HCA 式（压 64 倍后全读） | **100.0%** | **0.0951** |

HCA 读了全部历史——没有漏掉任何一个相关位置，注意力质量满分。但输出和全注意力几乎正交。

原因是**两个指标衡量的是不同的失败**：

- 注意力质量回答「相关的位置在不在我读的集合里」——这是**选择**的问题。
- 输出余弦回答「读完之后算出来的东西对不对」——这还包括**表示**的问题。

把 64 个 token 平均成一个向量，相关的那十几个 token 的信号被另外五十个无关 token 稀释掉了。**位置在集合里，信息却已经不在了。**

这正是第 11 篇「看漏 vs 看糊」的量化版：CSA（压 4 倍）输出余弦 0.77，HCA（压 64 倍）只有 0.095。压缩率直接决定了分辨率。

### 结论四：NSA 的代价是读得多

NSA 式三分支拿到了最好的结果（99.5% / 1.0000），但读了 **288** 个条目——是其他机制的 4–10 倍。它赢在「块分数来自压缩分支」这一步白捡的全局视野，但三条分支的并集本身就不小。

把四行放在一起，取舍就清楚了：

| 机制 | 怎么省       | 主要风险                |
| ---- | ------------ | ----------------------- |
| SWA  | 只看近处     | 远处完全看不到          |
| NSA  | 三分支分工   | 读取量仍然不小          |
| DSA  | 按打分精选   | 打分器本身的质量        |
| CSA  | 压缩 + 精选  | 压缩损失 + 选择损失叠加 |
| HCA  | 重压缩后全读 | 分辨率塌陷              |

## 代码实现

> 完整 harness 见文章目录下的 `toy.py`。它把每个机制统一成「这一步实际参与注意力的 K/V」，所以加一个新机制只需加十行。

```python
def evaluate(name, idx, k_src=None, v_src=None):
    """idx：参与注意力的原始位置；k_src/v_src 给压缩机制用（条目不是原始 token）。"""
    if k_src is None:
        k_src, v_src = k_all[idx], v_all[idx]
    w = softmax(k_src @ q / scale)
    out = w @ v_src
    cos = out @ full_out / (np.linalg.norm(out) * np.linalg.norm(full_out))
    mass = full_w[idx].sum()        # 选中位置在全注意力里的权重总和
    return dict(name=name, read=len(k_src), mass=mass, cos=cos)
```

## 代价与边界

这一节比结果本身更重要。**上面的数字不能用来给论文里的机制排名**，原因如下：

1. **压缩用的是均值池化，不是论文里可学习的压缩。** NSA 的 $\varphi$ 是带位置编码的 MLP，CSA/HCA 的压缩权重是 softmax 加权且**训练出来的**。均值池化是其中最差的一种特例。所以 **CSA 和 HCA 那两行是下界，系统性地低估了它们**——真实的压缩会保留块内的主导信号，而不是把它平均掉。
2. **这些机制是和模型一起训练的。** 表里把稀疏机制套在一个没有为它训练过的随机权重上，等于第 08 篇说的「事后稀疏化」。NSA 论文整节在论证这样做不公平。
3. **相关区域是人为植入在远处的。** 这个设定对 SWA 特别不利。换成局部性强的文本，SWA 的表现会好得多。
4. 单个 query、单层、随机权重、无 RoPE、无多 head。它展示的是**机制的失败模式**，不是它们的能力排序。
5. 所有数字都来自本地 CPU 上的一次 toy 运行，不是任何论文的复现，也不涉及性能。

**这个 harness 的正确用法**：理解「覆盖率」和「输出保真度」为什么会分离、看清每种机制的失败长什么样。要比较机制的真实能力，必须各自训练后在相同任务上评测——那是论文做的事。

## 自测

1. SWA 和完美 top-64 读取量相同，为什么结果差这么多？这说明稀疏注意力真正的难点在哪？
2. 「注意力质量」和「输出余弦」衡量的是两种不同的失败。各举一个只会影响其中一个指标的情形。
3. HCA 覆盖率 100% 却输出最差，用「选择」和「表示」两个词解释。
4. 为什么说表里 CSA/HCA 两行是下界？要让这个 harness 对它们更公平，至少要改哪一处？
5. 动手：在 `toy.py` 里把植入的相关区域从 (37, 150, 400) 改到 (480, 495, 505)（都在窗口内），重跑一遍。哪些机制的排名变了？这说明什么？
