自回归模型每吐出第 1001 个词元，注意力层都需要和前面 0 到 999 个历史词元的键（Key）和值（Value）做交互；而这批历史键值对与生成第 1000 个词元时算出的结果完全相同。如果不缓存它们，每次吐出新词元都要把整段前缀重新投影一遍，单序列投影计算量会从线性 $O(T)$ 膨胀到平方 $O(T^2)$；一旦缓存它们，64 层多头注意力在长上下文和大并发下又会迅速把 HBM 容量与访存带宽塞满。

读完本章，你可以带走四件确定的事：

1. **为什么 KV Cache 与重算在数学上逐位等价**：只投影当前新词元并按物理槽位追加写入，可以把线性投影开销压回 $O(T)$，双精度实测输出误差不超过 `1.22e-15`。
2. **64 层 MHA 撞墙的精确账本**：64 个注意力头在 BF16 下每词元要吃掉 `2.0 MiB` 缓存；16 路并发跑 32K 上下文总缓存高达 `1024.0 GiB`，且单步解码算术强度仅有 `0.999 FLOP/B`。
3. **MQA 与 GQA 如何靠头共享拉升算术强度**：把 $n_q$ 个 Query 头拆成 $n_{kv}$ 组共享同一份 Key/Value，每搬运 1 字节历史 KV 就能服务组内 $g = n_q / n_{kv}$ 个 Query 头，显存与带宽同步下降 $g$ 倍、算术强度抬升接近 $g$ 倍，但也引入了明确的表达力妥协。
4. **生产推理框架如何落地槽位写入与分组调度**：在 vLLM 中由 `reshape_and_cache_flash` 写入 5D 分页池[^vllm-fa]，在 vllm-ascend 中由 `DeviceOperator.reshape_and_cache` 按硬件族路由至散射写入与融合推理注意力算子[^vllm-ascend-attn]。

## 先看一个例子：4 步自回归解码，缓存比全前缀重算省多少

图 1 交互式演示了 `Decode t=1..4` 的增量推进过程：每生成 1 个新词元时，只计算单行 $Q_t [1, d]$ 与新槽位 $(k_t, v_t)$ 并追加进 `K/V Cache`，历史槽位直接命中复用、注意力只算当前最后一行。相比之下，第 5 步对照视图展示了无缓存重算必须在第 `t=4` 步一次性重算全部 4 个词元并丢弃前 3 行，仅 4 步累计投影次数就相差 `2.50x`（`4` 次 vs `10` 次）。

在更普遍的「提示词长度 $T_{\text{prompt}}$ + 生成步数 $T_{\text{gen}}$」场景中，无缓存路径每步重算的前缀长度为等差数列。当取 $T_{\text{prompt}} = 4,\,T_{\text{gen}} = 4$ 时，重算路径总共执行了 $5 + 6 + 7 + 8 = 26$ 次全词元 KV 投影，而开启 KV Cache 仅需 $4$ 次新词元投影，算力差距立刻拉大到 `6.50x`，且随序列长度线性增长为 $O(T)$ 倍。

## 显存与带宽账本：64 层 MHA 为什么会撞墙

先把容量账算清楚。设模型共有 $L$ 层，每层有 $n_{kv}$ 个 Key/Value 头，单头维度为 $d_{\text{head}}$，每个元素占 $b_{\text{dtype}}$ 字节（BF16 取 2 字节）。由于每一层都要同时存下 Key 与 Value 两个张量，单个词元在全模型占用的 KV 缓存字节数为：

$$
M_{\text{tok}} = 2 \cdot L \cdot n_{kv} \cdot d_{\text{head}} \cdot b_{\text{dtype}}
$$

其中 $L$ 为 Transformer 层数，$n_{kv}$ 为每层缓存的 KV 头数，$d_{\text{head}}$ 为单头向量长度，$b_{\text{dtype}}$ 为单元素字节数；逻辑形状等价于每层维护 `[2, T, n_kv, d_head]`。代入主流 64 层标准 MHA 模型（$L=64$、$n_q = n_{kv} = 64$、$d_{\text{head}} = 128$、$b_{\text{dtype}} = 2$）：

- **单词元缓存开销**：$2 \times 64 \times 64 \times 128 \times 2 = 2{,}097{,}152\text{ B} = 2048.0\text{ KiB/tok} = 2.0\text{ MiB/tok}$。
- **并发与长文本容量爆炸**：当批大小 $B = 16$、序列长度 $T = 32768$ 时，总 KV 缓存达到 $16 \times 32768 \times 2.0\text{ MiB} = 1024.0\text{ GiB} = 1.0\text{ TiB}$，远远超出单张 `80 GB` HBM 加速卡的物理显存上限。

比显存容量更隐蔽的是单步 Decode 的**带宽墙**。当批大小 $B = 1$、上下文长度为 $T$ 时，单层注意力只生成 1 个词元：向量 $q_t$ 的形状是 `[n_q, d_head]`，而历史缓存 $K, V$ 各是 `[T, n_kv, d_head]`。算术强度为：

$$
I_{\text{attn}} = \frac{4 \, T \, n_q \, d_{\text{head}}}{\bigl(2(T + 1)\, n_{kv}\, d_{\text{head}} + 2\, n_q\, d_{\text{head}}\bigr)\cdot b_{\text{dtype}}}
$$

分子来自 $Q K^\top$ 与 $P V$ 两次乘法；分母统计读取 $Q$、写入新词元 $k_t, v_t$、读取长度为 $T$ 的历史 $K, V$ 以及写回输出 $O$ 的总字节流量。在标准 BF16 MHA（$n_{kv} = n_q$）下取 $T = 2048$ 代入上式，解码算术强度仅有 **`0.999 FLOP/B`**——硬件每搬运 2 字节数据只做 2 次乘加就丢掉，计算单元绝大部分时间都在空转等数据。

## MQA 与 GQA：用头共享换取 g 倍带宽与算术强度

既然标准 MHA 的症结在于每个 Query 头都要搬运专属 KV 头，最直接的思路就是让多个 Query 头共用同一组 Key 和 Value。把 $n_q$ 个 Query 头均匀切分为 $n_{kv}$ 组，每组包含 $g = n_q / n_{kv}$ 个 Query 头。图 2 用严格等比例宽度的张量条直观呈现了三者 KV 体积的悬殊差距（`100%` -> `25%` -> `12.5%`）。

![MHA（8:8=100%）、GQA（8:2=25%）与 MQA（8:1=12.5%）严格等比 KV 宽度对比](./diagrams/03-mqa-gqa-arch.drawio '图 2：MHA（8:8=100%）、GQA（8:2=25%）与 MQA（8:1=12.5%）头映射与缓存字节宽度等比对照')

- **MHA（$g = 1$，$n_{kv} = n_q$）**：每个 Query 头独占 1 组 KV，容量最大、访存最多、算术强度被钉死在 `0.999 FLOP/B` 附近。
- **MQA（Multi-Query Attention，$g = n_q$，$n_{kv} = 1$）**：Shazeer 在 2019 年提出让层内所有 Query 头共享唯一的一对 $K_0, V_0$[^mqa-paper]。在论文表 2 的 TPUv2 实测中，贪心解码单步耗时从 `46 us/token` 骤降至 `3.8 us/token`（Beam-4 下从 `203 us` 降至 `32 us`）；对应到 64 层账本，每词元缓存缩减 64 倍至 `32.0 KiB/tok`，`B=16, 32K` 总量仅需 `16.0 GiB`。
- **GQA（Grouped-Query Attention，$1 \lt g \lt n_q$）**：Ainslie 等人在 2023 年让每 $g$ 个 Query 头共享 1 组 KV，通过均值池化合并 MHA 检查点并做 `5%` uptraining[^gqa-paper]。在 T5-XXL 上 MHA 均分 `47.2`（`1.51 s`），MQA 降至 `46.6`（`0.24 s`），而 GQA-8 拉回至 **`47.1`**（耗时仍仅 `0.28 s`）。

为什么压缩 $n_{kv}$ 能让矩阵引擎「吃饱」？在 GQA 中，同一组里的 $g$ 个 Query 向量天然组成小矩阵 `[g, d_head]`，片上从 HBM 加载 1 份共享历史 $K, V$ 后就能同时喂给 $g$ 个 Query 头做小矩阵乘 `[g, d_head] @ [d_head, T_block]`。在 $T = 2048$ 的 64 层账本里，GQA-8 把算术强度从 `0.999 FLOP/B` 提升到 **`7.965 FLOP/B`**，MQA 则升至 **`62.031 FLOP/B`**。

但头共享是一场绕不开的**表达力妥协**：

| 模型配置与来源                                                | KV 压缩比例       | 代表任务表现对比                                                                             |
| :------------------------------------------------------------ | :---------------- | :------------------------------------------------------------------------------------------- |
| 1B-word 语言模型（Shazeer 2019 表 3[^mqa-paper]）             | MHA vs MQA        | 困惑度（PPL）：MHA `29.9` vs MQA `30.2`（若硬砍 $h$ 或 $d_k$ 会退化到 `30.9`–`31.2`）        |
| T5-XXL 微调（Ainslie 等 2023 表 1[^gqa-paper]）               | GQA-8（$g=8$）    | 综合均分：MHA `47.2` vs GQA-8 `47.1` vs MQA `46.6`                                           |
| 7B Dense 从零训 1.33T tokens（DeepSeek-V2 表 8[^dsv2-paper]） | MHA / GQA-8 / MQA | MMLU `45.2` / `41.2` / `37.9`；BBH `37.0` / `35.6` / `33.2`；C-Eval `42.9` / `37.7` / `30.0` |

DeepSeek-V2 团队在 7B 稠密架构下从零训练 `1.33T` tokens 的对照实验尤其直接[^dsv2-paper]：MHA 在 MMLU 拿到 `45.2`、C-Eval 拿到 `42.9`；换成 GQA-8 掉到 `41.2` 与 `37.7`；降到 MQA 更是跌到 `37.9` 与 `30.0`。这正是下一系列 DeepSeek MLA 要回答的命题：如何**不靠砍掉独立头数**就把 KV 缓存压下来？

## 生产 KV Cache 排布与写入调度

在工业推理框架中，PagedAttention 将长序列切成固定大小的物理块（`block_size`），当前步新投影出来的 `[num_tokens, n_kv, d_head]` 并不是在 Python 里动态 `torch.cat`，而是由融合内核按一维映射张量 `slot_mapping` 原地散射写入物理显存槽位。图 3 并排对比了 **vLLM GPU** 与 **vllm-ascend NPU** 两套底层池布局与硬件对齐逻辑。

![vLLM GPU 5D 池布局与 vllm-ascend PA_NZ 16x16 分形 KV 布局对比](./diagrams/03-gpu-vs-npu-kv-layout.drawio '图 3：vLLM GPU 5D Paged KV 池与 vllm-ascend NPU 的 PA_NZ 16x16 分形布局及调度路径')

| 对比维度             | vLLM GPU（`flash_attn.py`[^vllm-fa]）                                                                  | vllm-ascend NPU（`attention_v1.py` / `mla_v1.py`[^vllm-ascend-attn]）                                                                 |
| :------------------- | :----------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------ |
| **KV Pool 物理形状** | `[num_blocks, n_kv, block_size, 2 * head_size]` 合并视图                                               | 标准池 `[2, num_blocks, block_size, n_kv, head_size]`；MLA `PA_NZ` 按 `16` 维切分成 `[num_blocks, n_kv * rank // 16, block_size, 16]` |
| **槽位散射算子**     | `do_kv_cache_update` 调用 `.transpose(1, 2).split(head_size, dim=-1)` 后触发 `reshape_and_cache_flash` | `DeviceOperator.reshape_and_cache` 在 A2/A3 调用 `npu_scatter_pa_kv_cache`，310P 调用 `_npu_reshape_and_cache`[^vllm-ascend-dev]      |
| **分组注意力读取**   | `FlashAttention` CUDA 内核内部按 `num_q_heads / num_kv_heads` 偏移读取同一组 KV 并做 TMA 步长对齐      | `npu_fused_infer_attention_score_v2` 接收紧致 `TND`、`BSND_NBSD` 或 `BNSD_NBSD` 布局并原生复用 KV 头                                  |

两条后端在源码中的对齐细节同样非常鲜明[^vllm-fa][^vllm-ascend-attn][^vllm-ascend-dev]：

```python
# vllm/v1/attention/backends/flash_attn.py:1422-1440 (vllm@bb23c0a8)
key_cache, value_cache = kv_cache.transpose(1, 2).split(self.head_size, dim=-1)
reshape_and_cache_flash(
    key, value, key_cache, value_cache, slot_mapping,
    self.kv_cache_dtype, layer._k_scale, layer._v_scale,
)

# vllm_ascend/device/device_op.py:298-305 (vllm-ascend@3649b8ff)
torch_npu.npu_scatter_pa_kv_cache(
    key=key.contiguous(), value=value.contiguous(),
    key_cache=key_cache, value_cache=value_cache,
    slot_mapping=slot_mapping.contiguous(), cache_mode="Norm",
)
```

需要留意：无论是在 GPU 上用块索引偏移，还是在昇腾 NPU 上用 `PA_NZ` 分形视图（C8 量化则为 `NZ_FMT_LAST_DIM = 32`，MLA 则按 Cube 的 `nz_fmt_last_dim = 16` 分块），GQA 都不会在显存里真的复制 $g$ 份物理数据，而是直接把 `[n_kv]` 个物理头地址交给底层算子在片上广播复用。

## NumPy 核心实现：缓存等价性与 64 层带宽账本

下面的独立 NumPy 脚本在 MHA（`n_kv=8`）、GQA（`n_kv=2`）与 MQA（`n_kv=1`）三种拓扑下验证「全前缀重算」与「增量 KV Cache」数值逐位等价，并打印 64 层生产模型的容量与 $T=2048$ 解码算术强度：

```python
import math
import numpy as np

def softmax(x, axis=-1):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / np.sum(e, axis=axis, keepdims=True)

rng = np.random.default_rng(3)
d_model, n_q, T_p, T_g = 64, 8, 4, 4
X = rng.normal(0.0, 1.0, (T_p + T_g, d_model))
Wq = rng.normal(0.0, 0.1, (d_model, d_model))

for n_kv in (8, 2, 1):
    g, dh = n_q // n_kv, d_model // n_q
    Wk = rng.normal(0.0, 0.1, (d_model, n_kv * dh))
    Wv = rng.normal(0.0, 0.1, (d_model, n_kv * dh))
    kc, vc, cached_outs = [], [], []
    for t in range(T_p + T_g):
        qt = (X[t] @ Wq).reshape(n_q, dh)
        kc.append((X[t] @ Wk).reshape(n_kv, dh))
        vc.append((X[t] @ Wv).reshape(n_kv, dh))
        ka = np.repeat(np.stack(kc, axis=0), g, axis=1)
        va = np.repeat(np.stack(vc, axis=0), g, axis=1)
        probs = softmax(np.einsum("hd,khd->hk", qt, ka) / math.sqrt(dh))
        cached_outs.append(np.einsum("hk,khd->hd", probs, va).reshape(d_model))
    Q_all = (X @ Wq).reshape(T_p + T_g, n_q, dh)
    K_all = np.repeat((X @ Wk).reshape(T_p + T_g, n_kv, dh), g, axis=1)
    V_all = np.repeat((X @ Wv).reshape(T_p + T_g, n_kv, dh), g, axis=1)
    S_all = np.where(np.tril(np.ones((8, 8), dtype=bool))[None], np.einsum("thd,khd->htk", Q_all, K_all) / math.sqrt(dh), -np.inf)
    full_outs = np.einsum("htk,khd->thd", softmax(S_all), V_all).reshape(8, d_model)
    max_diff = float(np.max(np.abs(np.stack(cached_outs) - full_outs)))
    assert max_diff < 1e-13
    print(f"n_q={n_q}, n_kv={n_kv} (g={g}): max_abs_diff={max_diff:.2e}")

for name, n_kv in (("MHA", 64), ("GQA-8", 8), ("MQA", 1)):
    m_kib = (2 * 64 * n_kv * 128 * 2) / 1024
    ai = (4 * 2048 * 64 * 128) / ((2 * 2049 * n_kv * 128 + 2 * 64 * 128) * 2)
    print(f"{name:5s}: {m_kib:6.1f} KiB/tok | B=16,32K: {m_kib * 16 * 32768 / 1048576:6.1f} GiB | AI={ai:6.3f} FLOP/B")
```

运行输出：

```text
n_q=8, n_kv=8 (g=1): max_abs_diff=1.11e-15
n_q=8, n_kv=2 (g=4): max_abs_diff=8.88e-16
n_q=8, n_kv=1 (g=8): max_abs_diff=1.22e-15
MHA  : 2048.0 KiB/tok | B=16,32K: 1024.0 GiB | AI= 0.999 FLOP/B
GQA-8:  256.0 KiB/tok | B=16,32K:  128.0 GiB | AI= 7.965 FLOP/B
MQA  :   32.0 KiB/tok | B=16,32K:   16.0 GiB | AI=62.031 FLOP/B
```

三组头映射的数值差全部落在双精度舍入误差（`1.22e-15` 以内），同时印证了图 2 与图 3 揭示的 `8x` 与 `64x` 显存/算术强度同步迁移规律。

## 代价与边界

- **GQA 的硬件天花板依然存在**：即便压缩到 GQA-8，64 层模型在 `B=16, 32K` 下仍需 `128.0 GiB` KV 缓存，且 `7.965 FLOP/B` 仍远低于主流芯片两百以上的算术强度拐点，需要靠增大并发批大小或压缩单层 KV 维度弥补。
- **张量并行（TP）下的头数约束**：当使用 8 卡 TP 切分权重时，如果模型 $n_{kv}$ 小于 TP 度（如 MQA 的 $n_{kv}=1$ 或 GQA-4 跑在 TP8 上），每张卡不得不各自复制一份相同的 KV 缓存，省下来的显存红利会被并行复制抵消。
- **结构性瓶颈未破**：GQA 本质是在**显存省量**与**独立特征头数**之间二选一。要打破零和博弈，须把多头 KV 联合压缩进低秩潜在空间，这正是[系列三 DeepSeek 01：MLA](../../deepseek/01-mla/) 的核心；在此之前，下一章先看 **FlashAttention** 如何用片上分块消除 $O(N^2)$ 中间矩阵显存读写。

## 自测

1. 为什么给推理加上 KV Cache 后，投影矩阵的输入长度从 $O(T)$ 变成了 $O(1)$，但解码阶段却依然容易撞上性能瓶颈？
2. 在 GQA-8 中，KV 缓存体积比 MHA 缩小了 8 倍，为什么单步解码的算术强度也会跟着放大接近 8 倍，而不是保持不变？
3. 如果要把一个 `n_kv = 4` 的 GQA 模型强行部署在 8 卡张量并行（TP=8）集群上，单卡实际持有的 KV Cache 总量会比单卡部署时减半还是翻倍？
4. **动手推演**：把上文账本公式里的解码长度 `2048` 分别替换成短上下文 `64` 与超长上下文 `32768`，重新计算三组结构的算术强度。观察为什么当序列短到几十词元时，读取 $Q$ 与写回 $O$ 的固定开销会把 MQA 拉离 `64` 渐近线，而序列上万后三者几乎严格对齐 `1`、`8`、`64` 三条水平线。
