自回归语言模型生成第 1001 个 token 时，注意力层需要与前面 1000 个历史 token 的键（Key）和值（Value）做交互；而这批历史键值对在前几步已经算出并保持不变。若未将其缓存，每生成 1 个新 token 都必须把整段前缀重新投影一遍，累计投影计算复杂度随序列长度 $N$ 按 $O(N^2)$ 平方增长；把历史键值对全量留存在片外显存后，64 层多头注意力在长上下文和大并发下又会迅速占满 HBM 容量与访存带宽。

## 增量解码与全前缀重算的工作量对比

把生成过程中的历史键和值留在显存里逐槽追加，称作**键值缓存（KV Cache）**。由于第 $t$ 步的查询向量 $Q_t$ 只需要计算当前最后一行注意力分数，而前面 $1 \dots t-1$ 行的因果掩码只依赖各自左侧的历史键、互不影响，增量写入缓存与每步重算完整前缀在数学上完全等价。图 1 按解码步 $t = 1 \dots 4$ 对比了增量追加与无缓存全量重算的投影次数差异：有缓存路径每步只计算 1 组 $Q_t$ 与 $(k_t, v_t)$ 并填入空槽，前 4 步累计执行 4 次 token 级 KV 投影；而在对照视图中，如果不做缓存，仅在第 4 步就要重算全部 4 个 token 的键值并丢弃前 3 行，4 步累计投影达 10 次，相差 2.50 倍。

放在包含提示词前缀的一般推理场景里，这种差距会拉得更大。设提示词长度为 $T_{\text{prompt}}$、自回归生成 $T_{\text{gen}}$ 步，无缓存路径每步重算的前缀长度呈等差数列递增。当取 $T_{\text{prompt}} = 4$、$T_{\text{gen}} = 4$ 时，重算路径累计执行 $5 + 6 + 7 + 8 = 26$ 次全 token KV 投影，开启 KV Cache 则只需计算 4 个新生成 token 的键值，投影运算量差距立刻拉大到 6.50 倍，并随着上下文总长线性扩大到 $O(T)$ 倍。

## 64 层 MHA 的显存与带宽账本

省下了重复计算，代价是必须在显存里常驻不断增长的 KV 张量。设模型共有 $L$ 个 Transformer 层，每层缓存 $n_{kv}$ 个键值头，单头向量长度为 $d_{\text{head}}$，每个元素占 $b_{\text{dtype}}$ 字节（BF16 精度取 2 字节）。由于每层都需要同时保存 Key 与 Value 两个形状等价于 `[T, n_kv, d_head]` 的张量，单个 token 在全模型中占用的 KV 缓存字节数为：

$$
M_{\text{tok}} = 2 \cdot L \cdot n_{kv} \cdot d_{\text{head}} \cdot b_{\text{dtype}}
$$

代入主流 64 层标准多头注意力模型（$L = 64$、$n_q = n_{kv} = 64$、$d_{\text{head}} = 128$、$b_{\text{dtype}} = 2$），每个 token 占用 $2 \times 64 \times 64 \times 128 \times 2 = 2{,}097{,}152\text{ B} = 2048.0\text{ KiB/token} = 2.0\text{ MiB/token}$。一旦服务 16 路并发请求且序列长度达到 32768（32K），全模型 KV Cache 总量立即膨胀到 $16 \times 32768 \times 2.0\text{ MiB} = 1024.0\text{ GiB}$（即 1.0 TiB），远远超出单张 80 GB 显存卡的物理容量。

比显存容量更隐蔽的是单步解码的带宽墙。以批大小 $B = 1$、上下文长度 $T$ 为例，每层注意力只为当前 1 个新 token 计算输出：查询 $q_t$ 的形状是 `[n_q, d_head]`，历史键和值各为 `[T, n_kv, d_head]`。统计 $Q K^\top$ 与 $P V$ 两次核心乘加运算，除以读取历史 $K/V$、读写当前 $Q/O$ 及追加新 $(k_t, v_t)$ 的总字节数，得到解码注意力的算术强度：

$$
I_{\text{attn}} = \frac{4 \, T \, n_q \, d_{\text{head}}}{\bigl(2(T + 1)\, n_{kv}\, d_{\text{head}} + 2\, n_q\, d_{\text{head}}\bigr)\cdot b_{\text{dtype}}}
$$

在 BF16 精度（$b_{\text{dtype}} = 2$）且上下文较长（$T \gg n_q / n_{kv}$）时，括号内的常数项可以略去，算术强度直接渐近化简为查询头数与键值头数的比值 $g$：

$$
I_{\text{attn}} \approx \frac{4\,T\,n_q\,d_{\text{head}}}{4\,T\,n_{kv}\,d_{\text{head}}} = \frac{n_q}{n_{kv}} = g
$$

这行渐近关系直接决定了解码注意力的 Roofline 位置：在标准 MHA 下每组键值头只服务 1 个查询头（$g = 1$），代回 $T = 2048$ 的精确公式算得算术强度只有 0.999 FLOP/B。无论算力核多强，只要每次搬进 2 字节历史 KV 只做 2 次乘加就丢弃，硬件就几乎全部时间在等 HBM 搬运。

## MQA 与 GQA 的头共享妥协

既然标准 MHA 的瓶颈在于每个查询头都要从显存里拉取一份专属的 Key 和 Value，最直接的压缩办法就是减少键值头数 $n_{kv}$，让多个查询头共用同一组 KV。把 $n_q$ 个查询头均匀划分为 $n_{kv}$ 组，每组包含 $g = n_q / n_{kv}$ 个查询头。图 2 用严格等比例宽度的张量条对比了标准多头（MHA）、分组查询（GQA）与多查询（MQA）之间的头映射关系和缓存字节体积。

![MHA（8:8=100%）、GQA（8:2=25%）与 MQA（8:1=12.5%）严格等比 KV 容量对比](./diagrams/03-mqa-gqa-arch.drawio '图 2：MHA（8:8=100%）、GQA（8:2=25%）与 MQA（8:1=12.5%）头映射与缓存字节占比等比对照')

沿着图 2 从上往下压缩键值头数，硬件收益和模型质量之间呈现出一条清晰的折中曲线。在 **MHA（$g = 1$，$n_{kv} = n_q$）** 模式下每个查询头独占一套 KV，容量与访存需求最大；2019 年 Shazeer 提出的 **MQA（Multi-Query Attention，$g = n_q$，$n_{kv} = 1$）**[^mqa-paper] 让层内所有查询头共享唯一一对 $(K_0, V_0)$，在 TPUv2 上将贪心解码单步耗时从 46 us/token 压低到 3.8 us/token（Beam-4 搜索从 203 us 降至 32 us），对应到前面的 64 层模型账本，每 token 缓存缩小 64 倍至 32.0 KiB/token，16 路并发 32K 上下文总显存从 1024.0 GiB 降为 16.0 GiB，且 $T=2048$ 时的解码算术强度跃升至 62.031 FLOP/B。

为了避免只留 1 个 KV 头带来的训练收敛风险，Ainslie 等人在 2023 年提出折中的 **GQA（Grouped-Query Attention，$1 < g < n_q$）**[^gqa-paper]，通过对已训练 MHA 检查点按组均值池化并补充 5% 计算量的持续微调，在保留接近 MQA 解码速度的同时把综合评测质量拉回 MHA 水平。压缩 $n_{kv}$ 能提高矩阵计算单元利用率，关键在于同组内的 $g$ 个查询向量在计算时组成一个 `[g, d_head]` 小矩阵：片上从 HBM 读出 1 份共享的 $K$ 或 $V$ 块后，可以同时乘以组内全部 $g$ 个查询头，将算术强度同步放大接近 $g$ 倍——例如在 64 层模型中采用 GQA-8（$g=8$）时，单 token 缓存降至 256.0 KiB/token，16 路并发 32K 上下文总量降至 128.0 GiB，而 $T=2048$ 解码算术强度抬升到 7.965 FLOP/B。

不过，头共享本质上是在用独立键值的表达自由度换取显存与带宽空间。在几项经典对照实验中，这种表达力折中都有明确体现：

| 模型配置与来源                                           | 头共享配置        | 代表任务表现对比                                                           |
| :------------------------------------------------------- | :---------------- | :------------------------------------------------------------------------- |
| 1B-word 语言模型（Shazeer 2019[^mqa-paper]）             | MHA vs MQA        | 困惑度 29.9 vs 30.2（若砍 $h$ 或 $d_k$ 退化至 30.9–31.2）                  |
| T5-XXL 微调（Ainslie 等 2023[^gqa-paper]）               | MHA / GQA-8 / MQA | 综合均分 47.2 / 47.1 / 46.6；解码耗时 1.51 s / 0.28 s / 0.24 s             |
| 7B Dense 从零训 1.33T tokens（DeepSeek-V2[^dsv2-paper]） | MHA / GQA-8 / MQA | MMLU 45.2 / 41.2 / 37.9；BBH 37.0 / 35.6 / 33.2；C-Eval 42.9 / 37.7 / 30.0 |

尤其当直接从零开始用 GQA 或 MQA 训练万亿级 token 时，模型在知识与复杂推理基准上的得分会比同源 MHA 基线低几个百分点。此外，即使压到 GQA-8，128.0 GiB 的并发缓存依然偏大，7.965 FLOP/B 也仍远低于主流芯片拐点；一旦开启 8 卡张量并行切分模型，像 MQA（$n_{kv}=1$）或 GQA-4 这种头数少于卡数的配置，每张卡都得各自复制一份完整 KV，省下来的容量又会被跨卡冗余占掉一半。如何在不砍掉独立注意力头数的前提下把 KV 体积再压低一个数量级，将是[《DeepSeek 架构演进》第 01 篇](../../deepseek/01-mla/)拆解多头潜在注意力（MLA）时的核心命题。

## NumPy 验证：缓存等价性与 64 层带宽账本

下面用一段独立可运行的 NumPy 脚本，在 MHA（$n_{kv}=8$）、GQA（$n_{kv}=2$）与 MQA（$n_{kv}=1$）三种拓扑下验证逐 token 增量缓存与全前缀重算的数值等价性，并核对 64 层模型在 $T = 2048$ 下的容量与算术强度账本：

```python
import math
import numpy as np

def softmax(x, axis=-1):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / np.sum(e, axis=axis, keepdims=True)

rng = np.random.default_rng(3)
d_model, n_q, T_p, T_g = 64, 8, 4, 4
X = rng.normal(0.0, 1.0, (T_p + T_g, d_model))
Wq = rng.normal(0.0, 0.1, (d_model, d_model))

for n_kv in (8, 2, 1):
    g, dh = n_q // n_kv, d_model // n_q
    Wk = rng.normal(0.0, 0.1, (d_model, n_kv * dh))
    Wv = rng.normal(0.0, 0.1, (d_model, n_kv * dh))
    kc, vc, cached_outs = [], [], []
    for t in range(T_p + T_g):
        qt = (X[t] @ Wq).reshape(n_q, dh)
        kc.append((X[t] @ Wk).reshape(n_kv, dh))
        vc.append((X[t] @ Wv).reshape(n_kv, dh))
        ka = np.repeat(np.stack(kc, axis=0), g, axis=1)
        va = np.repeat(np.stack(vc, axis=0), g, axis=1)
        probs = softmax(np.einsum("hd,khd->hk", qt, ka) / math.sqrt(dh))
        cached_outs.append(np.einsum("hk,khd->hd", probs, va).reshape(d_model))
    Q_all = (X @ Wq).reshape(T_p + T_g, n_q, dh)
    K_all = np.repeat((X @ Wk).reshape(T_p + T_g, n_kv, dh), g, axis=1)
    V_all = np.repeat((X @ Wv).reshape(T_p + T_g, n_kv, dh), g, axis=1)
    S_all = np.where(np.tril(np.ones((8, 8), dtype=bool))[None], np.einsum("thd,khd->htk", Q_all, K_all) / math.sqrt(dh), -np.inf)
    full_outs = np.einsum("htk,khd->thd", softmax(S_all), V_all).reshape(8, d_model)
    max_diff = float(np.max(np.abs(np.stack(cached_outs) - full_outs)))
    assert max_diff < 1e-13
    print(f"n_q={n_q}, n_kv={n_kv} (g={g}): max_abs_diff={max_diff:.2e}")

for name, n_kv in (("MHA", 64), ("GQA-8", 8), ("MQA", 1)):
    m_kib = (2 * 64 * n_kv * 128 * 2) / 1024
    ai = (4 * 2048 * 64 * 128) / ((2 * 2049 * n_kv * 128 + 2 * 64 * 128) * 2)
    print(f"{name:5s}: {m_kib:6.1f} KiB/tok | B=16,32K: {m_kib * 16 * 32768 / 1048576:6.1f} GiB | AI={ai:6.3f} FLOP/B")
```

脚本运行输出如下，三组头映射的数值最大绝对误差均不超过 $1.22 \times 10^{-15}$（落在双精度浮点舍入误差范围内），容量与算术强度也与前文推导一致：

```text
n_q=8, n_kv=8 (g=1): max_abs_diff=1.11e-15
n_q=8, n_kv=2 (g=4): max_abs_diff=8.88e-16
n_q=8, n_kv=1 (g=8): max_abs_diff=1.22e-15
MHA  : 2048.0 KiB/tok | B=16,32K: 1024.0 GiB | AI= 0.999 FLOP/B
GQA-8:  256.0 KiB/tok | B=16,32K:  128.0 GiB | AI= 7.965 FLOP/B
MQA  :   32.0 KiB/tok | B=16,32K:   16.0 GiB | AI=62.031 FLOP/B
```

## 生产分页 KV 排布与双端调度

生产级推理引擎写入 KV Cache 时，需要绕开连续数组逐步拼接带来的重分配开销。若为每条请求按最大上下文长度提前申请一整块连续显存，大量未写满的尾部空间会造成严重的内部碎片；若每生成 1 个 token 就重新分配并拷贝整段缓存，又会浪费大量显存带宽。因此，以 PagedAttention 为代表的生产框架借鉴操作系统的虚拟内存分页机制[^paged-attn]，将逻辑连续的请求序列切分成固定大小的物理块（`block_size`）按需从全局缓存池申领；每步前向时，调度器为当前批中每个新 token 算出对应的全局一维槽位编号 `slot_mapping`（物理块编号乘以块大小加块内偏移），由底层融合算子按槽位执行原地 Scatter 写入。

图 3 并排对照了 `vLLM` GPU 与 `vllm-ascend` NPU 在这套分页缓存模型下的物理内存排布与读写通路。

![vLLM GPU 行主序分页池与 vllm-ascend 16x16 分形 KV 布局对比](./diagrams/03-gpu-vs-npu-kv-layout.drawio '图 3：vLLM GPU 行主序分页 KV 池与 vllm-ascend 16×16 分形布局对照')

在写入和读取这两个环节上，两条硬件栈围绕各自的内存访问偏好做出了清晰区分。`vLLM` GPU 路径的 `FlashAttentionImpl` 维护合并的物理池张量，更新缓存时直接按最后一维切出 Key 和 Value 视图，交给 `reshape_and_cache_flash` 按 `slot_mapping` 原地执行 Scatter 写入，且块内沿着 `head_size` 保持行主序连续排布，以匹配 Tensor Core 与 TMA 的 16 字节对齐读取；读取时 CUDA 注意力 Kernel 直接按 `num_q_heads / num_kv_heads` 的组比例偏移复用同一份物理 KV 头，避免在 HBM 里复制 $g$ 份副本[^vllm-fa]。而在 `vllm-ascend` 路径中，标准注意力默认采用 `block_size = 128` 并将池形状组织为 `(2, num_blocks, block_size, num_kv_heads, head_size)`（部分融合场景会进一步折叠为对齐 Cube 16×16 突发读取的分形布局），通过 `DeviceOperator.reshape_and_cache` 按设备代际分发至 `npu_scatter_pa_kv_cache` 等 Scatter 写入算子，随后由融合推理注意力算子 `npu_fused_infer_attention_score_v2` 直接按头分组比例广播消费物理缓存[^vllm-ascend-attn][^vllm-ascend-dev]。

```python
# vllm/v1/attention/backends/flash_attn.py:1422-1440 (vllm@bb23c0a8)

```

| 对比维度          | `vLLM` GPU（`bb23c0a8`）   | `vllm-ascend` NPU（`3649b8ff`） |
| :---------------- | :------------------------- | :------------------------------ |
| 物理缓存形状      | 合并 5D 池按行主序对齐     | 2 通道池（可折叠 16×16 分形）   |
| 槽位 Scatter 算子 | `reshape_and_cache_flash`  | `npu_scatter_pa_kv_cache`       |
| 分组读取机制      | Kernel 按组偏移片上复用 KV | 融合注意力算子原生分组读取      |

分页排布仅解决了历史 KV 的物理存储和读取效率；在长序列 Prefill 或 Decode 过程中，注意力分数矩阵 $Q K^\top$ 的尺寸依然按序列长度平方 $O(N^2)$ 增长。下一章 [04 FlashAttention 与硬件对齐 Kernel：从在线 Softmax 到 FA-4、FlashMLA 与昇腾融合注意力](../04-flash-attention/) 将介绍如何利用片上在线归并把中间分数矩阵留在核心内部，从而绕开 $O(N^2)$ 的显存读写墙。
