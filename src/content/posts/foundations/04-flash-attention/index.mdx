在长序列场景下，标准注意力把中间矩阵反复写回 HBM 再重新读出，这一片外访存开销直接主导了算子耗时。以序列长度 $N = 32{,}768$、128 个查询头、BF16 精度（每元素 2 字节）为例，将注意力打分矩阵 $S = QK^\top / \sqrt{d}$ 完整写回显存 HBM 就需要 $128 \times 32{,}768^2 \times 2\text{ B} = 256\text{ GiB}$，随后算完概率矩阵 $P = \operatorname{softmax}(S)$ 再写读一遍，吞吐就被显存带宽墙直接限制住[^fa1-paper]。

到了自回归解码阶段，瓶颈又反转到并行度一侧。由于每次只为 1 个新 token 计算查询向量（$s_q = 1$），如果 Kernel 沿查询序列切分任务块，绝大多数计算单元（SM 或 AI Core）会因为查询行数太少而长时间闲置；此时必须改为沿长历史上下文切分键值块（Split-KV），再将各块的局部统计量无损归并。

## 在线 Softmax 与片上分块累加

按教科书定义计算注意力，必须先算出完整分数矩阵 $S$ 扫第一遍找最大值与分母，再扫第二遍乘以 $V$。由于 $S$ 太大装不进算力核心旁只有几百 KB 的片上 SRAM 或 UB，朴素实现只能先把 $S$ 与 $P$ 写回慢速 HBM 再读入。

要消除这轮片外往返，关键在于**片上只保留唯一一份在线累加状态 $(m, \ell, \tilde{O})$，每当新分块刷出更大的行最大值 $m_{\text{new}}$ 时，利用标量指数拆分恒等式就地缩放旧账**：

$$
e^{x - m_{\text{new}}} = e^{x - m_{\text{old}}} \cdot e^{m_{\text{old}} - m_{\text{new}}}
$$

利用这条恒等式，计算过程中直接复用片上当前累加状态，无需回溯历史分数 $x$：无论前面累加了多少个元素，只需把已累加的指数和与输出向量整体乘以同一个标量因子 $\alpha = \exp(m_{\text{old}} - m_{\text{new}})$，就能等价换算到新基准 $m_{\text{new}}$ 下，全部块扫完后再除一次最终分母。

为了手算核对全过程，考虑分块尺寸 $B_r = 2, B_c = 2$、序列长度 $N = 4$ 的最小示例，取前两行得分 $S = \begin{bmatrix} 1 & 3 & 5 & 2 \\ 4 & 2 & 1 & 2 \end{bmatrix}$ 与值矩阵 $V = \begin{bmatrix} 1 & 0 \\ 0 & 2 \\ 2 & 1 \\ 0 & 4 \end{bmatrix}$。图 1 步进演示了这组 2×2 分块如何在片上复用同一块输出缓冲完成就地重缩放。

顺着图 1 核对第 0 行的数值演化（第 1 行同步推进）。在第一个分块上，局部得分 $S^{(1)} = [[1,3],[4,2]]$、值分块 $V_{0:2} = [[1,0],[0,2]]$ 载入片上缓冲后，第 0 行求得当前最大值 $m_0^{(1)} = 3.0$，局部未归一化权重 $\tilde{P}_0^{(1)} = [\exp(-2), \exp(0)] \approx [0.135335, 1.0]$，分母累加为 $\ell_0^{(1)} = 1.135335$，乘以 $V_{0:2}$ 写入唯一的累加器得 $\tilde{o}_0^{(1)} = [0.135335, 2.000000]$（第 1 行对应得到 $[1.000000, 0.270671]$）。

接着载入第二个分块 $S^{(2)} = [[5,2],[1,2]]$ 与 $V_{2:4} = [[2,1],[0,4]]$，直接原地覆盖片上分块槽位。第 0 行最大值从 3.0 跳到 5.0，依据指数拆分恒等式算出缩放因子 $\alpha_0 = \exp(3 - 5) \approx 0.135335$；而第 1 行旧最大值 4.0 依然不小于新块最大值 2.0，因此 $\alpha_1 = \exp(4 - 4) = 1.0$ 无需缩放。把旧累加器乘以 $\alpha$ 并加上新块贡献 $\tilde{P}^{(2)} V_{2:4}$ 后，片上更新为 $\tilde{O}^{(2)} = [[2.018316, 1.469819], [1.099574, 0.861799]]$，分母更新为 $\ell^{(2)} = [1.203438, 1.320458]$。直到全部分块扫完，才在片上做唯一一次除法 $O = \tilde{O}^{(2)} / \ell^{(2)} = [[1.677125, 1.221350], [0.832722, 0.652652]]$ 并写回 HBM，与全量 Softmax 结果对比的双精度最大绝对误差仅为 $2.22 \times 10^{-16}$。

将这套无除法内循环写回一般分块形式：

$$
\begin{aligned}
m^{(j)} &= \max\bigl(m^{(j-1)},\; \operatorname{rowmax}(S^{(j)})\bigr), \qquad \alpha^{(j)} = \exp\bigl(m^{(j-1)} - m^{(j)}\bigr) \\
\ell^{(j)} &= \alpha^{(j)} \odot \ell^{(j-1)} + \operatorname{rowsum}\bigl(\exp(S^{(j)} - m^{(j)})\bigr) \\
\tilde{O}^{(j)} &= \operatorname{diag}(\alpha^{(j)})\,\tilde{O}^{(j-1)} + \exp(S^{(j)} - m^{(j)})\,V^{(j)}
\end{aligned}
$$

图 2 从硬件存储层级还原了这条数据通路：外循环固定一块 $Q_i$ 留在片上，内循环流式读入 $K_j, V_j$ 并在片上销毁中间分数，因此规模为 $O(N^2)$ 的 $S$ 与 $P$ 从诞生到销毁从未写回片外显存，HBM 总读写复杂度也从 $\Theta(Nd + N^2)$ 压降到 $\Theta(N^2 d^2 M^{-1})$（$M$ 为片上缓冲容量）[^fa1-paper]。

## 从 FA-2 到 FA-4 的硬件对齐演进

在线 Softmax 绕开显存带宽墙之后，前向 Kernel 能否跑满芯片标称算力，取决于硬件内部不同计算单元之间日益扩大的算力落差。从 FlashAttention-2 到 FlashAttention-4 的每一步演进，本质上都是围绕当下最拥挤的那条片内通道重新排布流水线。

### FA-2：循环重排与延迟归一化

在 Ampere A100 上，Tensor Core 矩阵乘峰值达到 312 TFLOPS，但执行 `exp`、乘法缩放与归约的非矩阵 FP32 算力只有 19.5 TFLOPS，两者相差 16 倍[^fa2-paper]。FlashAttention-2 针对性改写了循环结构与线程分工：先是在内循环里跳过逐块除以 $\ell^{(j)}$ 的操作、只对未归一化累加器 $\tilde{O}$ 乘以标量 $\alpha$，把唯一一次除法推迟到全部键值块结束；接着把外循环改为切分 $Q$、内循环流式扫过 $K, V$，使单个 `CTA（CUDA Thread Block）` 始终将 $\tilde{O}_i$ 留在寄存器中直至最后写回 HBM 一次；同时改为按 $Q$ 行切片把工作分配给 `CTA` 内的不同 Warp（Split-Q），消除了早期版本每步在共享内存 `SMEM` 中做跨 Warp 归约的同步开销，在 A100 上把前向推升至 230 TFLOPS（约 73% 利用率）[^fa2-paper]。

### FA-3：异步引擎与乒乓交错

到了 Hopper H100，异步拷贝引擎 TMA 与异步矩阵指令 WGMMA 允许搬运和矩阵乘脱离线程同步等待；但如果让同一个线程组串行做完矩阵乘再去算 `exp`，Tensor Core 利用率会回落到约 35%[^fa3-paper]。FlashAttention-3 将线程块内的 Warpgroup 拆分为专职数据搬运的 Producer 与两组交替执行 GEMM 和 Softmax 的 Consumer（乒乓交错调度），并引入 FP8 分块量化与 Hadamard 旋转抑制离群误差，在 H100 FP16 前向达到 740 TFLOPS（75% 利用率）[^fa3-paper]。不过在 Hopper 上，输出累加器仍然占着每 SM 仅 65,536 个 32-bit 寄存器中的大头，限制了更大分块的双缓冲余量。

### FA-4：专用张量内存与多项式分流

到 Blackwell B200 时，硬件偏科进一步拉大：BF16 矩阵算力翻倍到每 SM 每周期 8192 次运算，但特殊函数单元 `MUFU` 的指数吞吐依然停在每周期 16 次运算，`SMEM` 读带宽也维持在每周期 128 字节[^fa4-paper]。面对较大的矩阵分块，`MUFU` 计算指数的周期数甚至超过矩阵乘本身，直接拖慢 Tensor Core。为此，FlashAttention-4 利用 B200 新增的 256 KB 专用张量内存（Tensor Memory，TMEM）接管 $128 \times 128$ UMMA 累加器，释放大量寄存器并将 Warpgroup 细分为双 Softmax、独立 Correction 与 MMA/TMA 四路协同；针对 `MUFU` 瓶颈，按 $2^x = 2^{\lfloor x\rfloor}\cdot 2^{x-\lfloor x\rfloor}$ 将小数部分用 3 次 Horner 多项式交由空闲 FMA 管线分担 10%–25% 的 `exp2` 计算（近似误差远低于 BF16 7-bit 尾数舍入底噪）；同时引入条件跳过重缩放，仅当块间最大值增幅超过阈值 $\tau = \log_2(256) = 8.0$（对应 256 倍缩放）时才触发 `TMEM` 中的 $\tilde{O}$ 重缩放，最终借助 CuTe-DSL 在 B200 前向达到 1613 TFLOPS（约 71% 理论峰值）[^fa4-paper]。

## Decode 分片归并、宽向量流水与昇腾 1C2V 协同

回到自回归解码阶段，单条请求在当前步只有 $s_q = 1$ 个新查询 token。如果依然只按查询长度切分线程块，在中小并发下大量 SM 会闲置；Split-KV（又称 Flash-Decoding）的做法是把每条请求长长的历史 KV 序列切分成多个切片，分配给全卡所有计算单元并行扫描，每个切片用在线 Softmax 算出局部累加输出 $\tilde{O}_s$ 与对数和指数统计量 $\text{LSE}_s = m_s + \ln \ell_s$ 写入临时缓冲，随后由一个轻量的归并 Kernel（如 `FlashMLA` 的 `combine.cu`）按全局权重 $\exp(\text{LSE}_s - \text{LSE}_{\text{global}})$ 无损合并[^flashmla-repo]，并常利用 CUDA 的程序依赖启动（PDL）将末尾归并与主扫描重叠。动态 Split-KV 会随切片数改变浮点加法结合顺序，导致输出出现末位微小差异；因此要求逐位可复现的线上环境会在 `vLLM` 与 `FlashMLA` 中打开 `enable_batch_invariant`（`batch_invariant` 确定性模式），将计算锁回单分片路径[^vllm-code][^flashmla-repo]。

当面对带有宽潜向量的注意力解码架构时（例如《DeepSeek 架构演进》第 01 篇详述的 MLA 架构），约束变得更加具体：权重吸收把 128 个查询头折叠后共同面对唯一的 1 个压缩 KV 潜在头（$h_{kv} = 1$），且向量宽度为 576 维（512 维内容加 64 维位置编码）。此时单请求查询矩阵高度跃升至 $M = h_q s_q = 128$，恰好跨过 H800 SXM5（降频实用峰值约 865 TFLOPS、带宽 3.35 TB/s）在 $h_q s_q \ge 128$ 处的算力拐点，把原本访存受限的解码推进算力受限区[^flashmla-v3]。但单份 $64 \times 512$ 的 FP32 输出累加器就要占用 32,768 个寄存器，H800 每 SM 的 65,536 个寄存器装不下两份完整累加器。为此，FlashMLA 把输出矩阵竖劈成左右两半 $O_L$ 与 $O_R$（各 $64 \times 256$），交给两个 Warpgroup 如跷跷板般交替占用 Tensor Core 与 CUDA Core，并用 9 路 $64 \times 64$ 的 `EVICT_FIRST` TMA 异步传输切分 576 维宽行，技术报告在 H800 上取得 660 TFLOPS 与 3 TB/s 带宽[^flashmla-v3]（而在最新的 `FlashMLA@395cb3af` 主干中，Hopper 576 维稠密 Kernel 已归档，活跃分支转向了 SM100 的 512 维稀疏解码 Kernel[^flashmla-repo]）。

在华为昇腾平台上，硬件约束催生了另一套截然不同的在线归并方案[^flashmla-ascend]。以 Ascend 950 的 `1C2V` 核心为例，1 个 Cube 单元（4096 FMA/clk、256 KB `L0C`）配 2 个 Vector 单元：由于 `L0C` 累加缓冲只支持 `FixPipe` 迁出或做矩阵乘累加，无法就地执行任意标量重缩放乘法 $\alpha \cdot \tilde{O}$，昇腾 Kernel 干脆把在线 Softmax 的输出累加器 $\tilde{O}$ 放在 Vector `UB` 中维护。为了避免每扫一个分块都把 `L0C` 数据经 `FixPipe` 搬到 `UB` 做一次缩放，算子引入了 `RESCALE_THRES = 6` 的阈值跳过缩放策略（skip-scale），并用每次突发搬运 2 个 token 的 `gather2` 技巧防止超出单个 Vector 仅 16 槽位的 `MTE2` 发射队列，再把上一块的值乘法 $S_{i-1} V_{i-1}$ 延迟一拍执行以把 Softmax 掩蔽在 Cube 计算空窗期内，从而在稀疏 Prefill 与 Decode 上分别取得 410 TFLOPS（95% 峰值）与 360 TFLOPS（83% 峰值）的算力表现[^flashmla-ascend]。与此同时，在开源稀疏解码入口 `sparse_decode.cpp` 中，昇腾分支显式关闭了多段 Split-KV（`enable_split_kv = false`）[^flashmla-repo]，而 `vllm-ascend` 的常规 GQA 与 MLA 解码则统一依托 `npu_fused_infer_attention_score_v2` 完成硬件融合执行[^ascend-code]。

## NumPy 验证与双硬件源码对照

下面这段自包含的 NumPy 脚本复现图 1 中的 $B_r=2, B_c=2$ 两块在线 Softmax 在位更新，并与标准全量 Softmax 核对精度：

```python
import numpy as np

S = np.array([[1.0, 3.0, 5.0, 2.0], [4.0, 2.0, 1.0, 2.0]])
V = np.array([[1.0, 0.0], [0.0, 2.0], [2.0, 1.0], [0.0, 4.0]])
m, l = np.full(2, -np.inf), np.zeros(2)
o_tilde = np.zeros((2, 2))
for j in range(0, 4, 2):
    sj, vj = S[:, j : j + 2], V[j : j + 2]
    m_new = np.maximum(m, np.max(sj, axis=-1))
    alpha = np.exp(m - m_new)
    pj = np.exp(sj - m_new[:, None])
    l = alpha * l + np.sum(pj, axis=-1)
    o_tilde = alpha[:, None] * o_tilde + pj @ vj
    m = m_new
o_fa = o_tilde / l[:, None]
p_ref = np.exp(S - np.max(S, axis=-1, keepdims=True))
o_ref = (p_ref / np.sum(p_ref, axis=-1, keepdims=True)) @ V
assert o_fa.shape == (2, 2) and np.max(np.abs(o_fa - o_ref)) < 1e-15
print("FA O:", np.round(o_fa, 6).tolist(), "max_diff:", f"{np.max(np.abs(o_fa - o_ref)):.2e}")
```

脚本运行输出与图 1 每一步计算完全吻合：

```text
FA O: [[1.677125, 1.22135], [0.832722, 0.652652]] max_diff: 2.22e-16
```

贴近硬件边界优化的 Kernel 都带着严格的形状契约——无论是页块大小还是头维度限制，只要上层张量错位就会退回通用慢路径[^vllm-code]；而动态 Split-KV 对浮点归约顺序的改写，也要求注重逐位一致性的服务显式切回 `batch_invariant` 确定性单分片模式。

算子融合已经把当前 16-bit 精度下的显存搬运与片内计算压到了接近物理天花板；要想把每个权重和 KV 元素占用的字节数再压低一半甚至四倍，下一章 [05 模型与 KV 量化：从 INT8、FP8 细粒度缩放到 MXFP4 与昇腾量化差异](../05-quantization/) 将展开低比特表示与量化硬件适配。
