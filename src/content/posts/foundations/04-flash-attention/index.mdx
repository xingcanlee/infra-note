标准注意力最耗时的地方，往往不是矩阵乘法本身，而是把中间矩阵一次次写回显存再读出来。以序列长度 $N = 32{,}768$、$128$ 个查询头、BF16 精度（`2` 字节）为例，仅仅把注意力打分矩阵 $S = QK^\top / \sqrt{d}$ 完整落盘到显存 HBM，就需要 $128 \times 32{,}768^2 \times 2\text{ B} = 256\text{ GiB}$（约 `275 GB`），随后算完概率矩阵 $P = \operatorname{softmax}(S)$ 再读写一轮，吞吐瞬间被显存带宽墙锁死[^fa1-paper]。

更棘手的是以 DeepSeek MLA 为代表的潜在注意力解码场景（多头潜在注意力，详见[系列三 DeepSeek 01：MLA](../../deepseek/01-mla/)）：解码阶段通过权重吸收把所有查询头并到一起面对唯一 **`1` 个压缩后的 KV 潜在头（`h_kv = 1`）**，且 V3/V3.2 上向量宽度是不凑整的 `576 = 512 + 64`，每次只生成 `1` 个新 token。内核必须同时打赢「$O(N^2)$ HBM 读写墙」和「单头窄批饥饿」两仗。

读完这一篇，你可以带走四件事：

1. **为什么不用存 $S$ 矩阵也能算准 Softmax**：用一个 $B_r=2, B_c=2, N=4$ 的分块例手算两轮，看清片上单一累加器如何靠 $\alpha = \exp(m_{\text{old}} - m_{\text{new}})$ 就地重缩放。
2. **从 FA-2 到 FA-4 的主线不是新公式，而是追逐硬件偏科**：A100 的矩阵/非矩阵算力差 `16` 倍、H100 出现异步 TMA/WGMMA、B200 矩阵算力翻倍而 MUFU 与 SMEM 带宽原地踏步——每代内核都在给当下最挤的那根管子减负[^fa2-paper][^fa3-paper][^fa4-paper]。
3. **Decode 如何把饥饿的向量乘变回满载矩阵乘**：MLA 权重吸收合并多头使有效高度跃升至 $M = 128$，Split-KV 切分长上下文喂饱全部 SM，再借 `9` 路 TMA 与双 Warpgroup 跷跷板吃下 `576` 维宽行[^flashmla-v3]。
4. **上游主干与昇腾 NPU 的演进切面**：为什么 `FlashMLA@395cb3af` 主干撤下 Hopper `576` 维稠密内核转向 SM100 稀疏 `512` 维[^flashmla-repo]，而昇腾 `1C2V` 选择把累加器搬进 Vector `UB` 并关闭 Split-KV[^ascend-code][^flashmla-ascend]。

## 先看一个例子：片上单一累加器如何绕开 S 矩阵落地

按教科书定义计算注意力，需要先算出完整分数矩阵 $S$ 扫第一遍找最大值与分母，再扫第二遍乘 $V$。一旦 $S$ 太大装不进算力核心旁只有几百 KB 的片上 SRAM / UB，就不得不写回慢速 HBM 再读入，白跑两趟长途货运。

解决思路可以浓缩成一句话：**片上只维护唯一一份在位累加状态 $(m, l, \tilde{O})$，新块出现更大最大值时就地给旧账乘一次缩放系数，全块扫完后才除一次分母**。我们用 $B_r = 2, B_c = 2, N = 4$ 的最小块演示整个片上就地覆盖过程（见图 1 交互步骤），其中第 0 行取分数 $s_0 = [1.0, 3.0 \mid 5.0, 2.0]$，第 1 行取 $s_1 = [4.0, 2.0 \mid 1.0, 2.0]$：

跟着图 1 的 5 个步骤拆开核对第 0 行的数字（第 1 行同步并行推进）：

- **载入 Tile 1 并写入唯一 $\tilde{O}$**：第 1 块 $K_{0:2}, V_{0:2}$ 进 SRAM，算出局部得分 $S^{(1)} = [[1,3],[4,2]]$。第 0 行最大值 $m_1 = 3.0$、指数和 $\ell_1 = \exp(-2) + \exp(0) = 1.135335$，直接乘 $V_{0:2}$ 写入唯一累加器得 $\tilde{o}_0^{(1)} = [0.135335, 2.000000]$（第 1 行为 $[1.000000, 0.270671]$）。
- **Tile 2 原地覆盖并触发行级重缩放**：旧的 $S^{(1)}$ 直接丢弃，同一块 SRAM 槽位覆写为 $S^{(2)} = [[5,2],[1,2]]$。第 0 行最大值从 `3.0` 跳升到 `5.0`，只需把旧账统一乘缩放因子 $\alpha_0 = \exp(3 - 5) = 0.135335$；第 1 行最大值仍为 `4.0`，因此 $\alpha_1 = \exp(4 - 4) = 1.0$ 无需缩水。
- **就地加总并一次性收尾**：把旧累加器按 $\alpha$ 就地缩水并加上新块贡献 $\tilde{P}^{(2)} V_{2:4}$，得到 $\tilde{O}^{(2)} = [[2.018316, 1.469819], [1.099574, 0.861799]]$，分母更新为 $\ell^{(2)} = [1.203438, 1.320458]$。直到全部分块结束，才在片上做唯一一次除法 $O = \tilde{O}^{(2)} / \ell^{(2)}$ 并单次写回 HBM。

与全量一次性 $\operatorname{softmax}(S_4) \cdot V_4$ 对照，双精度下最大绝对误差仅为 **`2.22e-16`**！将这套无除法内循环写回一般公式（行块 $B_r$、列块 $B_c$）：

$$
\begin{aligned}
m^{(j)} &= \max\bigl(m^{(j-1)},\; \operatorname{rowmax}(S^{(j)})\bigr), \qquad \alpha^{(j)} = \exp\bigl(m^{(j-1)} - m^{(j)}\bigr) \\
\ell^{(j)} &= \alpha^{(j)} \odot \ell^{(j-1)} + \operatorname{rowsum}\bigl(\exp(S^{(j)} - m^{(j)})\bigr) \\
\tilde{O}^{(j)} &= \operatorname{diag}(\alpha^{(j)})\,\tilde{O}^{(j-1)} + \exp(S^{(j)} - m^{(j)})\,V^{(j)}
\end{aligned}
$$

图 2 从硬件存储视角把这条数据流落回 HBM 与片上 SRAM/UB 之间：只要外循环固定 $Q_i$、内循环流式滑过 $K_j, V_j$，规模为 $O(N^2)$ 的打分矩阵 $S$ 与概率矩阵 $P$ 从诞生到销毁从未离开过片上缓冲，从而把 HBM 读写复杂度从 $\Theta(Nd + N^2)$ 压降到 $\Theta(N^2 d^2 M^{-1})$（$M$ 为片上 SRAM 容量）[^fa1-paper]。

## 从 FA-2 到 FA-4：追逐不对称的硬件算力演化

在线 Softmax 解决了 HBM 带宽墙之后，工程师很快撞上了第二堵墙：**GPU 内部不同计算单元的算力膨胀速度严重失衡**。

### FA-2（Ampere）：砍掉内循环除法，改写外循环并行度

在 A100 GPU 上，Tensor Core 矩阵乘峰值高达 `312 TFLOPs/s`，但标量/超越函数执行非矩阵 FP32 运算仅有 `19.5 TFLOPs/s`，相差整整 **`16` 倍**[^fa2-paper]。FA-2 做出三项关键改写，在 A100 上把前向推到 `230 TFLOPs/s`（约 `73%` 利用率）：

1. **延迟归一化（保留 $\tilde{O}$）**：内循环只乘标量因子 $\alpha$，省掉中间 $\operatorname{diag}(\ell)^{-1}$ 除法，反向传播仅缓存合并对数和指数 $L = m + \log(\ell)$。
2. **外循环切 $Q$、内循环扫 $K, V$**：一个 CTA 死攥一块 $\tilde{O}_i$ 不放手，仅在循环结束时写回 HBM 一次。
3. **Warp 间采用 Split-Q**：CTA 内 4 个 warp 各自负责不同的 $Q$ 行切片，彻底消除每步 SMEM 跨 warp 归约。

### FA-3（Hopper）：TMA 与 WGMMA 异步化 + Ping-Pong 双片交错

到了 Hopper H100，异步引擎 **TMA** 与 **WGMMA** 登场，让同一组线程干等 `exp` 会把 Tensor Core 利用率拽回 `35%`[^fa3-paper]。FA-3 把 Warpgroup 拆成搬运 `Producer` 与两个交替执行 GEMM 和 Softmax 的 `Consumer`（WG-A / WG-B），配合 FP8 块量化与 Hadamard 旋转在 H100 跑到 `740 TFLOPs/s`（FP16 75% 利用率）[^fa3-paper]。但此时累加器仍驻留稀缺的片上寄存器（每 SM 总计 `65,536` 个 32-bit 寄存器）。

### FA-4（Blackwell）：当指数单元 MUFU 与共享内存原地踏步

到 Blackwell B200，BF16 矩阵算力翻倍到 **`8192 ops/clk/SM`**，但 MUFU 指数单元仍停在 `16 ops/clk/SM`、SMEM 读带宽也依然停在 `128 B/clk/SM`[^fa4-paper]。面对 `M=256, N=d=128` 分块，MUFU 算指数竟要 `2048` 周期，正面卡死矩阵引擎。FA-4 为此重构四层协同（见图 3 第 3 步）：

1. **256 KB TMEM 解放寄存器**：专用 **Tensor Memory（TMEM）** 接管 `128x128` UMMA 累加器，将 Warpgroup 拆成 `2 个 Softmax + 1 个独立 Correction + 1 个 MMA/TMA`。
2. **FMA 3 次多项式分流 `exp2`**：把 $2^x = 2^{\lfloor x\rfloor}\cdot 2^{x-\lfloor x\rfloor}$ 的小数部分用 Horner 法交由空闲 FMA 算 `10%–25%` 元素（相对误差远低于 BF16 `7-bit` 尾数本底噪声）。
3. **条件跳过重缩放**：若新块最大值增幅未超阈值（$\log_2$ 空间 $\tau = 8.0$，对应 $\le 256\times$），直接跳过对 TMEM 内 $\tilde{O}$ 的乘法缩放。
4. **2-CTA DSMEM 反向与 CuTe-DSL**：相邻两个 CTA 配对减半 `dQ` 读写，前向 B200 达到 **`1613 TFLOPs/s`**（`71%` 峰值）[^fa4-paper]。

## Split-KV、FlashMLA 与昇腾 1C2V 硬件对齐演进

将镜头转回自回归解码（`s_q = 1`）：在 DeepSeek MLA 中，所有查询头共享仅有的 **`1` 个 KV 潜在头（$h_{kv} = 1$）**。为了把单个 SM 从访存受限救活到满载矩阵乘，DeepSeek FlashMLA 采用「权重吸收并头 + Split-KV + 核内跷跷板」组合拳[^flashmla-v3]：

- **并头拉高 $M$ 与 Split-KV 喂饱全部 SM**：查询侧先吸收 $W_{UK}^\top$ 使 `128` 个查询头共同面对 `576` 维潜向量，H800 SXM5（实用峰值 ~`865 TFLOPS`、带宽 `3.35 TB/s`）拐点落在 $h_q s_q \ge 128$，单请求瞬间踩进算力受限区[^flashmla-v3]。同时调度器把长历史切为多段分发给全卡 SM 并行扫描，末段由 `combine.cu` 借助 PDL 与全局 LogSumExp 权重无损归并[^flashmla-repo]。
- **H800 双 Warpgroup 跷跷板（见图 3 第 2 步）**：单份 `64x512` FP32 累加器就要吃掉 `32,768` 个寄存器，H800 根本装不下双缓冲；FlashMLA 把输出劈成左右两半 $O_L, O_R$（各 `64x256`）交由 `WG0` 与 `WG1` 交替占用 Tensor Core 与 Softmax，并用 `9` 路 `64x64` `EVICT_FIRST` TMA 切分 `576` 维宽行，实测冲到 **`660 TFLOPS`** 与 **`3 TB/s`**[^flashmla-v3]。
- **昇腾 Ascend 950 `1C2V` 三线 Ping-Pong（见图 3 第 4 步）**：在最新 `FlashMLA@395cb3af` 中，CUDA 主干已转向 SM100 `512` 维稀疏内核（FP8 `528 B/token`、FP4 `288 B/token`），而昇腾分支面对的是 `1` 个 Cube（`4096 FMA/clk`, `256 KB L0C`）配 `2` 个 Vector 的 `1C2V` 架构[^flashmla-repo][^flashmla-ascend]。因为 `L0C` 累加器无法做就地标量乘法，昇腾核把 $\tilde{O}$ 搬到 Vector `UB` 中累加，用 `RESCALE_THRES = 6` 的 `skip-scale` 省掉频繁重缩放、用 `gather2` 双突发规避 `16` 槽位 `MTE2` 队列拥堵，并通过延迟一拍的 $S_{i-1} V_{i-1}$ 流水线把稀疏 Prefill 跑到 **`410 TFLOPS`（95% 峰值）**、Decode 跑到 **`360 TFLOPS`（83% 峰值）**。

## NumPy 核心实现与双硬件源码对照

下面用 20 行独立 NumPy 代码完整复现图 1 的 `B_r=2, B_c=2` 两块在线 Softmax 在位更新，并与标准全量 Softmax 核对精度：

```python
import numpy as np

S = np.array([[1.0, 3.0, 5.0, 2.0], [4.0, 2.0, 1.0, 2.0]])
V = np.array([[1.0, 0.0], [0.0, 2.0], [2.0, 1.0], [0.0, 4.0]])
m, l = np.full(2, -np.inf), np.zeros(2)
o_tilde = np.zeros((2, 2))
for j in range(0, 4, 2):
    sj, vj = S[:, j : j + 2], V[j : j + 2]
    m_new = np.maximum(m, np.max(sj, axis=-1))
    alpha = np.exp(m - m_new)
    pj = np.exp(sj - m_new[:, None])
    l = alpha * l + np.sum(pj, axis=-1)
    o_tilde = alpha[:, None] * o_tilde + pj @ vj
    m = m_new
o_fa = o_tilde / l[:, None]
p_ref = np.exp(S - np.max(S, axis=-1, keepdims=True))
o_ref = (p_ref / np.sum(p_ref, axis=-1, keepdims=True)) @ V
assert o_fa.shape == (2, 2) and np.max(np.abs(o_fa - o_ref)) < 1e-15
print("FA O:", np.round(o_fa, 6).tolist(), "max_diff:", f"{np.max(np.abs(o_fa - o_ref)):.2e}")
```

实测输出与图 1 每一步完全一致：

```text
FA O: [[1.677125, 1.22135], [0.832722, 0.652652]] max_diff: 2.22e-16
```

## 代价与边界

- **极窄的形状契约（错一位都触发回退）**：无论是 Hopper 核的 `block_size = 64`、`d_qk = 576`，还是 `FlashMLA@395cb3af` 硬断言的 `h_kv == 1 && d_qk == 512 && d_v == 512`、`vllm-ascend` 的 `block_size = 128`，只要形状或对齐条件（如 `VLLM_BATCH_INVARIANT` 下 `topk % 64 == 0`[^vllm-code]）不满足，上层就只能切换通用回退路径，吞吐立刻掉档。
- **动态分片换速度，代价是浮点非结合性**：Split-KV 改变分片数量时，由于浮点加法不满足结合律，FP32/BF16 下会产生轻微归约序漂移；线上若要求严格逐位可复现，必须在 `vLLM` / `FlashMLA` 里开启 `enable_batch_invariant` 强制固定单分片[^vllm-code][^flashmla-repo]。
- **片上缓存形态决定软件架构上限**：在 Hopper 上是寄存器不足逼出跷跷板调度；在 B200 上是 SMEM 带宽和 `16 ops/clk` MUFU 逼出 TMEM 解耦与多项式逼近；在 Ascend 950 上则是 Cube `L0C` 不支持就地标量乘法，逼出「UB 接管累加 + skip-scale」。

算子内核已经把当前精度下的算力与带宽压到物理极限，要想继续压缩**每份权重与 KV Cache 占用的字节体积**、把 Roofline 上限再推宽一倍甚至四倍，请继续阅读收官章节 [05 · 模型与 KV 量化：W8A8、FP8 与 MXFP4 如何守住精度并突破带宽墙](../05-quantization/)。
